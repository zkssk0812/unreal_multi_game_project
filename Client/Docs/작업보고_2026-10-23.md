## 2. 테스트 결과

### 자동화 테스트 (창 → 테스트 자동화 → VaultHeist) — 5개 모두 통과
- `VaultHeist.Interaction.HoldProgress`: 30초 중 10초 → 취소(유지) → 다시 20초, 초기화 취소, 시간 설정이 바뀌어도 비율 유지, 서버 정보로 복원
- `VaultHeist.Interaction.CarryRules`: 3개 한도·무게 한도, **소리 예시 (12 + 2×2) × 1.1 = 17.6m**, 걷기 + 보물 3개 = 6.6m, 무게 최대 → 속도 50%·스테미나 2배, 대상 점수
- `VaultHeist.Interaction.AuthorityFlow`(가상 월드): 금고 동시 1명(Busy) → 취소 후 다른 의적이 이어서 열기 → 잡히면 즉시 취소 → 열림 → 보물 줍기 → 빈 금고 제외 → 3개면 줍기 거절 → 다른 의적이 주우면 사라짐 → 손전등 연타 방지·잡힘·손전등 없음 → 숨기(Occupied, 숨은 동안 다른 대상 없음) → 창고(못 나감, 취소 시 초기화, 구출) → 탈출구(잠김, 도중 3개 미만이면 중단·진행도 유지, 열림, 탈출, 보물 없는 의적도 탈출 가능)
- 기존 `VaultHeist.Net.*` 2개도 그대로 통과(메뉴·Mock 영향 없음)

### PIE (L_InteractionTest) — 화면 캡처와 로그로 확인
- **대상 찾기·외곽선·안내**: 금고 앞에서 노란 외곽선 + `[우클릭/G] 길게 눌러 금고 열기 (30초)`, 할 수 없으면 회색 외곽선 + 회색 문구(`더 들 수 없습니다 (3/3)`, `탈출구가 잠겨 있습니다 (보물 0/3)`, `창고에 갇힌 의적이 없습니다`)
- **금고**: 길게 누르기 → `금고 열기 중... 29.7초` + 진행 바 → 떼면 취소, `남은 11초`로 진행도 유지 → 다시 눌러 완료 → 문 열림·알림 → 안내가 `보물 줍기`로 바뀜 → 줍기(0.5초)
- **떨어진 보물**: 내 주변 바닥에 흩어져 생성(약하게 빛남), 3개·무게 30/30이면 HUD 빨간 "무거움", **최대 속도 1.5m/s**, 소리 반경 6.6m 원 표시

- **잡힘(VHCapture)**: 진행 중 금고 열기 즉시 취소
- **손전등**: 켜면 앞쪽 원뿔 빛, HUD `손전등: 켜짐 [R]`
- **숨는 곳**: 1초 뒤 숨음(캐릭터 사라짐, 상태: 숨음, 안내 `나오기`) → 0.5초 뒤 나옴
- **창고**: 더미를 가둠 → 5초 길게 누르기 → 문이 올라가며 더미가 문 밖으로 풀려남. 나를 가두면 `… 창고에 갇혔습니다`

## 3. 남은 문제
- **외곽선이 "가장자리 발광" 방식**이다(메시 위에 반투명 머티리얼을 덧씌움). 평평한 기본 도형에서는 면 전체가 노랗게 보인다. 아트가 정해지면 포스트 프로세스(커스텀 뎁스) 외곽선으로 바꾸는 것을 권장. 탈출 지점 바닥판에도 같이 씌워진다.
- 진행 바가 설계 문서의 원형이 아니라 가로 막대다(UMG 기본 위젯). UI 디자인 확정 때 교체.
- 안내 문구의 키 이름 `[우클릭/G]`가 코드에 고정. 키를 바꿀 수 있게 하려면 매핑에서 읽어 오도록 수정 필요.
- ~~숨으면 카메라가 옷장 안에 갇혀 화면이 까맣게 됨~~ → **추가 수정에서 해결**(8장).
- 열린 금고의 보물은 별도 액터가 아니라 금고 상태(Opened → Empty)로 처리했다.
- 금고 "후보 10곳 중 매 판 5곳 랜덤"은 미구현(배치한 금고가 모두 활성). 서버 `SC_GAME_LOAD.safe_slots`가 오면 연결할 부분.
- 소리 신호 간격(걷기 0.5초·달리기 0.2초)과 서버 소리 이벤트, 스테미나, 구르기, 공격은 범위 밖이라 없음. 무게에 따른 스테미나 2배는 값만 보관.
- 에디터 창이 뒤에 있으면 PIE 프레임이 크게 낮아진다(에디터 기본 "백그라운드에서 CPU 적게 사용"). 동작에는 영향 없음.
- 자동화 테스트 실행 후 "메시지 로그" 창이 자동으로 떠서 뷰포트를 가린다(닫으면 됨).
- 지난번 남은 문제(엔진 PDB 없음, InputMode 경고 로그 등)는 그대로.

## 4. 확인 필요 (가정 목록)
1. 대상 찾기: "반경 1.5m"를 **캐릭터 중심 ~ 대상 가장자리** 거리로 계산, 바라보는 방향 좌우 **75°** 안, 거리와 각도를 합친 점수로 1개 선택. 대상을 밟고 서 있으면(거리 0) 각도 무시.
2. 보물 소리: 서 있거나 상호작용 중에도 `(0 + 2m × 개수) × 1.1`로 난다(설계 문서 "보물 소지 소리는 계속 발생"). `bTreasureNoiseWhileStill`로 끌 수 있음.
3. 무게: 보물 10, 최대 운반량 30(임시). 줍기는 "합계 + 새 보물 > 30"이면 거절, "합계 ≥ 30"이면 속도 50% 감소. 지금 값으로는 개수 한도(3개)와 같은 시점에 걸린다.
4. 테스트 캐릭터 걷기 속도를 템플릿 5m/s → 기획 3m/s로 적용(테스트 캐릭터에만).
5. 짧게 누르기(0.5초) 동작 중에는 움직일 수 없고 키를 떼도 계속 진행. 길게 누르기는 키를 떼거나 이동·점프 입력이 오면 취소.
6. 진행도 유지 금고는 다른 의적이 이어서 열 수 있음 [제안 그대로]. 빈 금고는 대상에서 제외.
7. 숨는 곳: 들어가는 1초 동안은 아직 자유 상태(공격받을 수 있음), 숨은 동안 손전등 켜기 불가.
8. 창고: 갇히면 들고 있던 보물을 잃는다(경비원이 가져간 것으로 처리). 구출 5초, 취소 시 초기화 [제안 그대로].
9. 탈출구·탈출 조건 = 남은 의적 소지 + 이미 탈출한 보물 ≥ 3. 탈출은 **열린 탈출구에 짧게 누르기**(별도 탈출 지점 오브젝트 없음).
10. 손전등: 시작 시 꺼짐, 연타 방지 0.3초(연타 거절은 안내 없이 무시).
11. Shift 달리기는 테스트용(스테미나 없음) — 사용자 결정(2026-10-23).
12. 에디터 재시작은 알리고 직접 진행 — 사용자 결정(2026-10-23).

3. `SC_INTERACT.duration_ms`는 **남은 시간**인가 전체 시간인가? (클라이언트는 남은 시간으로 가정 — 진행도 유지 금고에서 중요)
4. 짧게 누르기(줍기 0.5초 등)도 `SC_INTERACT Begin → Complete`가 오는가, 바로 결과(`SC_TREASURE` 등)만 오는가? 동작 중 이동 입력은 서버가 무시하는가 취소하는가?

6. 보물 소리: 서 있을 때도 나는가? 소리 신호 간격(걷기 0.5초·달리기 0.2초)은 서버가 계산해 `SC_NOISE`로 주는가?
7. 손전등 연타 제한(`Cooldown`) 서버 값은? 숨은 상태에서 `FlashlightOn`을 보내면 거절하는가?
8. 탈출: 열린 `ExitGate`에 `InteractBegin` = 탈출인가, 별도 탈출 지점 엔티티가 있는가? 회의 메모의 "환풍구로 보물 전달" 방식이 정해지면 프로토콜도 바뀌는가?
9. 잡힐 때 `SC_CAPTURED.treasure_moved`는 경비원이 가져가는 보물 수인가? 그 보물은 경비원이 경직될 때 떨어진 보물로 다시 나오는가?
10. 엔티티 ID: 테스트 레벨은 클라이언트가 1부터 붙인다. 실제로는 `SC_GAME_START`의 엔티티 목록과 레벨에 배치된 오브젝트를 어떻게 짝짓는가(배치 인덱스? 위치?)

## 7. 발표 대비 메모
- **사용자 결정 요구사항**: 상호작용 키 = 우클릭 + G(둘 다), 손전등 = R, 캐릭터 미확정이라 마네킹으로 "기능만", 기능은 캐릭터 클래스가 아니라 **컴포넌트**로, 메뉴·Mock과 분리된 **별도 테스트 레벨**, 숫자는 전부 **데이터 에셋**, 판정은 한곳에 모아 **나중에 서버 판정으로 교체**, 순수 로직은 **자동화 테스트**, 테스트용 Shift 달리기 추가.
- **판정과 반영의 분리**: "할 수 있는가·끝나면 무엇이 되는가"는 판정 담당 하나(`Authority`)만 정하고, 화면 반영은 `Apply*` 입구 하나로만 한다. 지금은 클라이언트가 판정하지만, 서버가 판정하게 되면 요청을 패킷으로 보내고 받은 패킷으로 같은 `Apply*`를 부르면 된다. 오브젝트·컴포넌트·HUD는 고칠 필요가 없다. (지난번 Mock 서버로 UI를 먼저 완성한 것과 같은 아이디어)
- **진행도를 "비율"로 저장**: 30초 중 10초가 아니라 "1/3 열림"으로 저장한다. 그래서 기획이 30초를 40초로 바꿔도 진행도가 자연스럽고, 서버가 주는 "시작 시각 + 남은 시간"으로도 똑같이 다시 계산할 수 있다. 진행 바는 서버 응답을 기다리지 않고 클라이언트가 시간으로 직접 그린다.
- **대상 고르기**: 탑뷰라서 시선 레이캐스트 대신 "가까울수록 + 정면일수록" 점수를 매겨 하나를 고른다. 할 수 없는 대상도 고르되 회색 외곽선과 이유를 보여준다.
- **소리 반경 공식**: (동작 기본 반경 + 2m × 보물 수) × 1.1. 예) 보물 2개 들고 달리기 = (12 + 4) × 1.1 = 17.6m. 자동화 테스트와 PIE 바닥 원으로 확인.
- **무게**: 보물마다 무게를 두고 합계가 최대 운반량에 닿으면 최대 속도 50% 감소(PIE에서 3.0 → 1.5m/s 확인).
- **컴포넌트 설계**: 상호작용 / 보물 소지 / 이동·소리 / 의적 상태 / 손전등 5개. 입력은 컨트롤러가 받아 컴포넌트로 전달만 한다 → 진짜 캐릭터에 컴포넌트만 붙이면 끝.
- **경비원이 없어도 테스트하는 방법**: 개발용 콘솔 명령(보물 뿌리기·개수 바꾸기·잡힘·가두기·더미 의적)과, 가상 월드를 만들어 규칙 전체 흐름을 자동으로 검사하는 테스트. 시간도 테스트에서 직접 정해서(30초를 기다리지 않고) 확인한다.
- **실제 입력 확인**: MCP로는 "누르고 있기"를 보낼 수 없어 OS 입력으로 키를 누른 채 유지해 G·우클릭 길게, W 취소, R, Shift 달리기를 확인했다.

### 숨는 곳 카메라 문제
- **증상**: 옷장에 숨으면 캐릭터 카메라가 옷장 안에 갇혀 화면이 까맣게 됨 (앞선 임시 조치는 캐릭터를 옷장 앞에 두는 방식이라 근본 해결이 아니었음)
- **수정**
  - `AVHHideSpot`에 전용 카메라 `HideCamera` 추가: 옷장 앞 3.8m·높이 2.6m에서 옷장을 약간 내려다봄 (블루프린트에서 위치·각도, `CameraBlendTime` 조정 가능)
  - 숨으면(`ApplyHide`) 내 캐릭터일 때만 화면을 옷장 카메라로 0.35초 동안 부드럽게 전환, 의적은 **옷장 안**에 둔다(안 보임·충돌 없음)
  - 나오면 캐릭터 카메라로 복귀. 이때 시점 방향을 "바깥에서 옷장 쪽"으로 맞춰 카메라가 방 쪽에 놓이게 함(나온 방향을 보게 하면 카메라가 등 뒤 옷장에 막혀 캐릭터에 바짝 붙었음)
  - 숨어 있다 창고로 끌려가는 경우(`ApplyJail`)도 캐릭터 카메라로 복귀
  - HUD 안내 상자가 왼쪽 위 상태 패널과 겹치면 패널 아래로 내림
- **테스트**: 자동화 테스트 5개 통과(“숨은 동안 의적은 옷장 안에 있음” 확인 추가). PIE에서 HideSpot_1·HideSpot_2에 숨기 → 옷장 바깥 카메라로 옷장과 `[우클릭/G] 나오기` 안내가 보임 → 나오기 → 캐릭터 카메라가 정상 거리로 복귀하는 것을 화면 캡처로 확인
- **참고**: 다른 의적(더미·다른 플레이어)이 숨을 때는 내 화면을 바꾸지 않는다.
