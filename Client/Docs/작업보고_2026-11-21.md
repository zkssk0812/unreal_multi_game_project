## 확인 필요 (가정)
- 도적3 키를 도적1·2와 같은 약 180cm 로 맞춤(지시대로). 모델 원래 비율이 다르면 `import_characters.py` 의 `scale`.

- 얼굴 그림 구도는 도적1·2와 같은 카메라·같은 자르기(도적3은 머리가 조금 위에 옴 — 키·목 비율 차이).

## 발표 대비 메모
- **뼈대가 조금 달라도 같이 쓰기**: 도적3 뼈대는 도적1보다 끝 뼈가 13개 많았다. 이 뼈들은 "가중치" — 정점을 얼마나 움직이는지 — 가 0 이라 메시를 전혀 움직이지 않는 표시용 끝점이다. 그래서 지우고 나머지 65개를 도적1 스켈레톤에 맞췄다. 지우지 않으면 엔진이 도적1 스켈레톤에 뼈를 추가해 다른 캐릭터의 에셋까지 바뀐다.
- **가중치를 어떻게 확인했나**: FBX 는 뼈마다 "클러스터(이 뼈가 움직이는 정점 목록)"를 따로 저장한다. 파일을 직접 읽어 13개 뼈에 클러스터가 하나도 연결되지 않은 것을 확인했다.
- **손 위치를 숫자로 비교**: 무기 손잡이는 각 캐릭터 "주먹 가운데" 소켓에 붙는다. 이 소켓을 각 메시 손가락 관절로 계산하므로 손이 작아도 손잡이는 주먹 안에 들어간다(소켓 ↔ 손잡이 거리 세 캐릭터 모두 같음, 손목 ↔ 손잡이 거리만 손 크기만큼 다름).
- **같은 사람이 모든 화면에서 같은 모습**: 고른 번호가 서버를 거쳐 모든 클라이언트에 같은 값으로 간다(`SC_ROOM_STATE` → `EntitySpawn.type_id`). 세 클라이언트 로그와 화면으로 확인.
- **사용자 결정**: 플레이어 캐릭터 3명(도적1~3), 키 약 180cm 통일, 옛 파일은 지우지 않고 보관.

# 작업보고 2026-11-21 (2) — 카메라 효과: 천장 가림(방 단위 시야)

## 사용자 지시
- 내가 있는 구역(방 하나 또는 복도)만 보이고 나머지 구역은 위에서 회색 천장으로 덮기. 복도에 있으면 복도만, 방에 들어가면 그 방만. 문을 지나면 천장이 바뀜.
- 구역 데이터가 클라 어디에 있는지 찾아 보고(이어진 복도는 한 구역), 천장 덮개(차분한 회색, 조명 영향 없음, 구역 경계 벽 선 보이게), 내 구역 판정(문가 여유, 0.2초 페이드, 쓰러짐·관전 = 카메라 대상), 덮인 구역의 플레이어·경비 로봇·아이템·금고는 몸·이름표·HP 글자·발밑 원·이펙트까지 숨김(판정은 서버 그대로), 퍽 위치 표시는 계속 보이게(미니맵 그대로), `vh.Ceiling 0/1`(기본 켬).
- 확인: 탑뷰 화면(복도·방·문 지나는 연속 프레임), 다른 방 이름표·HP 숨김, 퍽 표시, 실서버 V3b 봇과 한 판, 95fps, 작업보고.

## 2. 천장 — 어떻게 만들었나 (보고 요청)
- 새 `UVHCeilingSubsystem`(월드 서브시스템)이 게임 시작 때 방 볼륨에서 구역을 만들고, 구역마다 **인스턴스 메시 1개**(엔진 `Plane` 100×100 을 조각 크기로 늘린 것, 모두 189조각)를 깐다. 재질은 새 **`M_VHCeiling`**(언릿 = 조명 영향 없음, 마스크). 색은 `DA_VHGameplayConfig` → `CeilingColor`(0.30, 0.31, 0.33).
- **벽 선**: 천장을 벽 윗면보다 2cm 낮게(`CeilingHeightOffset -2`) 두어 구역 사이 벽 윗면(흰 선)이 천장 위로 보인다. 서버 조각은 벽에서 25~30cm 떨어져 있어 천장을 30cm 넓혔다(`CeilingExpand`).
- **높이**: 게임 시작 때 구역 둘레 벽 속을 위에서 아래로 쏴서(숨긴 액터 = 원래 천장·조명 기구는 건너뜀) 벽 윗면 높이 중앙값을 쓴다. 결과 **중앙 홀만 800cm(2층 높이 벽), 나머지 400cm**. 처음엔 모두 400 으로 했더니 홀의 높은 나무 벽이 천장 위로 튀어나와 바꿨다. 측정 추적 36,256번, 약 0.06초(시작 때 한 번).
- **기둥 자리 구멍**: 서버 조각은 기둥 자리(100×100)를 비워 둬서 홀 천장에 구멍 8개가 보였다 → 구역 안에 갇힌 2m 이하 빈칸은 메운다(복도 고리 안쪽의 방·홀 같은 큰 빈칸은 그대로).
- **맵 밝기 영향 없음**: 그림자·간접광·거리장·반사 캡처·레이트레이싱에서 모두 뺐다(천장 끄고 켜도 방 밝기 같음 — 화면 비교).
- **내 캐릭터가 가려지지 않게**: 카메라가 비스듬해(-65°) 카메라 쪽 벽에 붙으면 옆 구역 천장이 내 캐릭터를 가린다 → 벽 투명과 같은 `MPC_VHOcclusion` 으로 "카메라 → 내 캐릭터" 선 둘레(반경 150cm)를 천장에서도 비운다(그 안의 다른 구역 물체는 아래 4번 규칙으로 이미 숨김).

## 3. 내 구역 판정
- 기준 = 플레이어 카메라 매니저의 **뷰 타깃 위치**(보통 내 캐릭터. 쓰러져 숨겨져도 내 폰이 뷰 타깃. 관전이 생기면 그 대상).
- **문가 깜빡임 방지**: 지금 구역 조각에서 40cm(`CeilingSwitchMargin`) 넘게 벗어나고 **다른 구역 조각 안에 들어가야** 바뀐다. 문틀 양쪽 조각 사이가 50cm 라 문턱을 넘어 새 방 조각에 들어선 순간 바뀌고, 되돌아가도 같은 폭만큼 여유가 있다. 어느 조각에도 없는 곳(벽 옆·문 한가운데)에서는 이전 구역 유지.
- **0.2초 페이드**(`CeilingFadeSeconds`): 재질의 `Opacity` 를 0↔1 로 바꾸고 4×4 디더(화면 픽셀 격자)로 그 비율만큼 픽셀을 남긴다(TSR 이 부드럽게 섞음). 완전히 걷힌 구역은 그리지 않는다.

## 4. 덮인 구역 안의 것 숨기기
- 매 틱 `AVHNetProxy`(다른 플레이어·경비원), `AVHInteractableBase`(금고·상자·떨어진 아이템·반납지점), `AVHFxActor`(폭발·끈끈이·지뢰·연막·빔)를 본다. 위치가 **천장이 반 넘게 덮인 구역** 안이고 내 구역 경계 30cm(`CeilingVisibleMargin`, 문가에 선 사람) 밖이면 숨긴다.
- 숨기는 방법: 액터와 붙은 액터의 **모든 컴포넌트 `SetHiddenInGame`** → 몸·든 무기·이름표(이름·HP·상태 글자, TextRender)·발밑 색 원·붙은 이펙트·상호작용 노란 테두리(커스텀 뎁스)까지 함께 안 그려진다. 다른 코드가 쓰는 `SetVisibility`(은신·쓰러짐)·`SetActorHiddenInGame`(쓰지 않는 금고 후보)과 **다른 스위치**라 서로 덮어쓰지 않고, 내가 숨긴 컴포넌트만 되돌린다.
- 연출은 범위(경계 상자) 전체가 덮인 구역일 때만 숨긴다 → 다른 방에서 문을 넘어 내 방으로 오는 빔은 보인다. 바닥 자국(데칼)·위치에 생기는 나이아가라는 불투명 천장에 가려진다.
- 덮인 물품은 **상호작용 후보·커서 정보창에서도 뺐다**(`VHInteractionComponent`: 벽 너머 3m 안 물품에 테두리·F 대상이 생기지 않게. 서버 판정은 그대로).
- 판정은 서버 그대로(보내는 패킷·받는 처리 변경 없음).

## 5. 퍽 예외
- 보물탐색·로봇탐지·생체감지는 지금 **미니맵(HUD 위젯)에만** 그려진다(월드에 놓는 표시 없음, `VHMinimapWidget.cpp`·`GetTreasureSense`). HUD 는 3D 천장 위에 그려지므로 **그대로 보인다**. 미니맵 코드는 손대지 않음. 리스폰 뒤 "내가 떨어뜨린 보물 방향" HUD 표시도 HUD 라 그대로.

## 6. 끄고 켜기·개발 명령
- `vh.Ceiling 0/1`(콘솔 변수, 기본 1). 설정 `DA_VHGameplayConfig` → Camera|Ceiling → `bCeiling` 로도 끌 수 있다.
- 개발용: `vh.CeilingInfo`(내 구역, 다른 플레이어·경비원·물체마다 구역·숨김·이름표 여부를 로그로), `vh.CeilingGo X Y` / `vh.CeilingGo guard [거리]`(순간이동), `vh.CeilingShots 장수 간격 [이름]`(게임 시간 간격 연속 화면 저장, slomo 와 함께).

## 남은 문제
- 중앙 홀 벽이 800cm 라 옆 구역(사무실·복도)에 있으면 홀의 높은 나무 벽 바깥면이 원근으로 크게 보인다(벽 높이 그대로라 정상. 답답하면 홀 천장을 400에 두는 방법도 있지만 그러면 홀 벽 윗부분이 천장 위로 튀어나온다).
- 카메라 쪽 벽에 붙으면 옆 구역 천장에 반경 150cm 원 구멍이 생겨 그 바닥이 조금 보인다(내 캐릭터가 가려지지 않게 하려는 것. 그 안의 다른 구역 사람·물체는 숨겨져 있다).
- 넓게 찍은 화면(카메라 75m)에서는 자동 노출 때문에 회색이 밝게 보인다. 게임 카메라에서는 중간 회색.
- 클라 3개를 한 PC 에 띄우면 그래픽 메모리 경고로 화면 저장이 1~2초 늦다(첫 시도 화면 2장은 버리고 클라 2개로 다시 찍음).
- 사람이 직접 한 판(키보드로 문 드나들기)은 못 함. 걷기는 `vh.Walk`(실제 이동 입력)로 확인.

## 확인 필요 (가정)
- 천장 색 (0.30, 0.31, 0.33) — 그림의 "차분한 회색"에 맞춰 정함. 바꾸려면 `DA_VHGameplayConfig` → Camera|Ceiling → Ceiling Color.
- 반납지점도 다른 구역에 있으면 숨긴다(물품과 같은 규칙). 반납지점은 미니맵에 따로 표시되지 않으므로, 다른 방 반납지점을 늘 보여 줘야 하면 알려 주세요(예외 한 줄).
- 다른 구역의 상대가 천장 아래에서 공격해도 총알 빔이 내 구역으로 넘어오는 부분만 보인다(보이는 것만 바꿈, 맞는 판정은 서버).
- 덮인 물품은 F·커서 정보창 대상에서 뺐다(벽 너머 물품에 노란 테두리가 생기지 않게).
- 관전 기능은 아직 없어서 "카메라가 따라가는 대상" = 내 캐릭터(쓰러져도). 관전이 생기면 뷰 타깃을 바꾸기만 하면 자동으로 따라간다.

## 발표 대비 메모
- **방 단위 시야**: 맵의 방 영역(서버가 보내는 맵과 같은 35개 방, 직사각형 조각들)을 그대로 써서, 내 위치가 어느 방 조각 안인지 계산한다. 서버와 같은 데이터라 "서버가 생각하는 방"과 "화면의 방"이 어긋나지 않는다.
- **문가 깜빡임 방지(히스테리시스)**: "지금 방에서 40cm 넘게 벗어나고, 새 방 안에 들어섰을 때만" 바꾼다. 경계에서 왔다 갔다 해도 바로 바뀌지 않는다.
- **판정은 서버, 화면은 클라**: 서버는 모든 사람 위치를 계속 보내 준다. 클라이언트가 "내 방이 아닌 곳"에 있는 사람·물체를 그리지 않을 뿐이라 게임 규칙은 그대로다(PvP 정보 가리기). 퍽(로봇탐지·생체감지)은 미니맵에만 그려서 천장과 상관없이 보인다.
- **조명은 그대로**: 천장은 빛을 받지도 막지도 않는 "언릿" 재질이고 그림자·간접광 계산에서 뺐다. 그래서 천장을 깔아도 방 밝기가 같다.
- **0.2초 디더 페이드**: 반투명 대신 픽셀을 격자 모양으로 듬성듬성 지우는 방식이라 뒤의 물체와 그리는 순서가 꼬이지 않고 가볍다.
- **오히려 빨라짐**: 덮인 방의 가구·사람이 천장에 가려 그릴 것이 줄어 100fps → 116fps.
- **사용자 결정**: 내 구역만 보이기, 복도는 한 구역, 회색 천장(조명 영향 없음)·벽 선 보이기, 0.2초 전환, 퍽 표시는 계속, `vh.Ceiling` 으로 켜고 끄기(기본 켬).

## 사용자 지시
1. 카메라가 비스듬해서 카메라 쪽 벽 가까이 서면 옆 구역 천장이 내 구역 바닥 위로 겹쳐 그 띠 안의 적·아이템·바닥이 가려지는 문제 해결. 화면 픽셀이 내 구역을 보고 있으면 가리는 다른 구역 천장을 지우기(카메라 → 픽셀 선을 바닥 또는 허리 높이까지 늘려 구역 지도 텍스처로 판정, 둘 중 나은 쪽 고르기). 내 구역은 가림 없이, 다른 구역 안은 지금처럼. 부족하면 카메라 각도도 비교 제안(바꾸기 전 보고).
2. 방 입구마다 문(현대식 저택, 입구 폭에 맞춰 한 짝·양문). 먼저 서버 맵 데이터의 문·잠긴 문 정보 확인. 보이는 연출만(충돌 없음, 판정·이동 예측 영향 없음), 누가 오면 열리고 다 지나가면 닫힘, Kenney 문 소리. 서버가 잠긴 문을 주면 닫힌 채 표시, 없으면 모두 자동 문. 열린 문으로 다른 구역 안이 비치지 않게.
- 확인: 1번 전후 비교(띠 안 다른 플레이어·아이템, 다른 구역 안 안 비침, 문 지나는 연속 프레임), 2번 문 모습(탑뷰·가까이)·열고 닫는 연속 프레임·문 개수, 실서버 V3b 봇과 드나들기, 95fps, 작업보고.
- 규칙: client/menu-ui 에만 커밋·push, PR 없음, `Config/DefaultEditor.ini` 커밋 안 함, .uasset 텍스트 수정 금지, 서버 코드 수정 금지, 패키징 안 함.

## 1번: 어떻게 지웠나
- 구역 지도 텍스처: 게임 시작 때 방 볼륨 35개로 **996×896 칸(10cm) 텍스처**를 한 번 만든다(`UVHCeilingSubsystem::BuildZoneTexture`). R 채널 = 넓은 구역(서버 조각을 벽 면까지 30cm 넓힌 것), G 채널 = 좁은 구역(서버 조각 + 메운 기둥 자리).
- 재질 계산(`ZoneCut`, 천장 `M_VHCeiling` 과 벽 `M_VHWallFadeTex` 에 같은 코드): 카메라 → 이 픽셀 선을 `CutPlaneZ`(기본 0 = 바닥) 높이까지 늘린 점의 구역(R)을 읽어 **내 구역이면 그 픽셀을 지운다**.
  - 천장: 자기 구역 천장은 지우지 않음(자기 0.2초 페이드). 벽·기둥·창틀: 픽셀 자리(G)가 내 구역이면 그대로(방 안 기둥은 남음). 문: 자리 상관없이.
  - 천장만 지우면 그 뒤의 벽 면이 보여서 **카메라 쪽 벽(과 문)도 같은 규칙으로 지운다** → 내 구역은 바닥까지 다 보이고, 화면에서 회색 천장 끝이 바닥 경계선과 딱 맞는다.
  - 문 전환: 내 구역(A)과 직전 구역(B)의 지우기 정도를 천장 페이드와 같이 0.2초 디더로 바꾼다(문 지날 때 툭 바뀌지 않음).
- **다른 구역 안이 비치지 않게**: 지운 자리로 옆 구역의 키 큰 가구(선반·옷장)가 보이거나 내 바닥을 가릴 수 있어서, **다 덮인 구역의 소품(가구 341개)은 숨긴다**. 숨겨도 그림자·간접광은 남게 했다(`bCastHiddenShadow`, `bAffectIndirectLightingWhileHidden`) → 방 밝기 그대로. 덮인 구역의 사람·물품은 예전처럼 숨김.
- 처음 시도에서 카메라 쪽 벽 **윗면 20cm 가 남았다**: 넓은 구역(R)이 문가에서 벽 속까지 들어가 "자기 구역 벽"으로 오판 → 벽 자리 판단은 좁은 구역(G)으로 바꿔 해결.

| 기준 | 결과 |
|---|---|
| **바닥 0cm (채택)** | 내 구역 바닥이 벽 밑까지 다 보임. 띠 안 캐릭터 발까지 보임 |
| 허리 90cm | 카메라 쪽 벽에서 42cm(=90/tan65°) 띠가 남아 그 안의 발·바닥 아이템이 실루엣/가려짐. 옆 구역 가구가 덜 비치는 장점은 "덮인 구역 소품 숨기기"로 이미 해결 |

### 카메라 각도 (제안만, 바꾸지 않음)
- 가려지는 띠 폭 = 벽 높이 / tan(각도): -65°(지금) 1.87m, -75° 1.07m, -80° 0.71m (홀 8m 벽은 각각 3.7m·2.1m·1.4m). 각도를 세워도 띠가 줄 뿐 없어지지는 않고 화면이 평면적이 된다 → **지우기로 해결되어 각도 변경은 필요 없다고 판단**.

## 남은 문제
- **카메라 쪽 벽의 문은 그 벽과 함께 지워져** 내가 그쪽으로 나갈 때 문이 열리는 모습은 안 보인다(지나간 뒤 뒤쪽에서 닫히는 것은 보임). 벽과 같은 규칙이라 그대로 둠. → **사용자 결정(2026-11-21): 지금처럼 둔다**(카메라 쪽 문도 벽과 함께 지움).
- 홀처럼 반들한 바닥에는 지운 벽이 반사로 옅게 비친다(벽은 실제로 있어 반사 계산에 남음).
- 2명 클라를 한 PC 에 띄운 시험에서는 클라당 44~91fps(그래픽 메모리 나눠 씀, 측정용 아님).
- 사람이 직접 키보드로 한 판은 못 함(`vh.Walk` = 실제 이동 입력으로 확인).

## 확인 필요 (가정)
- 양문/한 짝: 입구가 모두 200cm 라 방 종류로 나눔(공용 공간 양문, 개인실 한 짝). 문 모양은 미닫이(벽 속으로).
- 열림 범위 220cm·0.35초 열림·0.4초 대기·0.5초 닫힘.
- 덮인 구역끼리의 문은 소리 없음(정보 숨김). 문소리도 들려야 하면 한 줄 수정.
- 덮인 구역의 가구는 숨김(그림자·간접광은 남음).
- 닫힌 방 1~3 은 입구가 없어 문을 달지 않음. 벽에 "장식용 잠긴 문"을 그려 넣길 원하면 알려 주세요(판정과 무관한 그림만 가능).

- **선 늘리기**: 카메라 → 천장 픽셀 선을 바닥까지 늘린 점이 내 방이면, 그 천장 픽셀은 내 방을 가리고 있는 것 → 지운다. 같은 규칙을 벽에도 적용해 카메라 쪽 벽까지 잘라 낸다(인형의 집 단면처럼).
- **다른 방은 그대로**: 지운 자리로 옆 방 가구가 비치지 않게 덮인 방 가구는 숨기되, 그림자·간접광은 남겨 방 밝기가 안 바뀐다.
- **문은 보이는 연출만**: 서버 맵에는 "문 위 벽"만 있고 문 열림 판정은 없다. 그래서 문은 충돌이 전혀 없는 장식이고, 서버가 보내는 위치로 누가 가까이 오면 클라가 스스로 연다. 서버가 막는 바깥 문 2곳만 잠긴 문으로 그렸다.
- **문간 가림막**: 열린 문 너머 덮인 방이 비치지 않도록 문 자리에 세로로 선 회색 천장 조각을 둔다(그 방 천장과 함께 덮이고 걷힘).
- **사용자 결정**: 내 구역은 가림 없이 다 보이게, 다른 구역 안은 안 보이게, 문은 연출만(판정 영향 없음), Kenney 문 소리, 잠긴 문 정보가 없으면 모두 자동 문.

## 어떻게 만들었나
- 데이터: 레벨의 `AVHDoor` 39개(= 서버 `above_door` 39곳, (4)절 `door_plan.py` 로 놓은 것) 그대로. 표시는 문 액터가 스스로 그린다(새 레벨 작업 없음).
- 새 재질 `M_VHDoorMark`(반투명 언릿, `make_ceiling_material.py doormark`): 엔진 Plane 위에 모양을 그린다. 모양 0 = 문턱 띠(가장자리 부드럽게), 1 = 화살표(>> 두 겹), 2 = X, 3 = 천장 위 밝은 틈.
- ① **바닥 문턱 띠 + 화살표** (`AVHDoor::UpdateMarks`, 매 틱 내 구역 확인): 문의 양쪽 구역 중 내 구역 쪽에만. 띠 = 벽 가운데에서 내 구역 쪽으로 (벽 두께/2 + 45cm), 문 폭만큼. 화살표 = 벽 면에서 80cm, 크기 90cm, 다른 구역 쪽을 가리킴. 바닥 높이라 (4)절의 "앞 가림 지우기"에서 내 구역 바닥으로 보이므로 **벽·문이 지워진 카메라 쪽 문에도 보인다**. 문이 열리는 만큼 밝기·불투명도 ×1.5.
- ② **천장 위 밝은 틈**: 문 자리 벽 윗면(두 구역 천장 중 높은 쪽 + 5cm)에 문 폭 × (벽 두께 + 40cm) 띠. 내 구역과 상관없는 문(덮인 구역끼리) + 내 구역 문 중 카메라 쪽 벽이 아닌 문(복도에서 방 입구가 벽 위로도 보이게)에 켠다. 카메라 쪽 벽의 문은 바닥 표시만(벽 위 틈이 내 바닥 위에 떠 보이지 않게). 벽 위에 얹은 표시라 덮인 구역 안은 비치지 않는다. 천장 위에 그려지도록 정렬 우선순위 10.
- ③ **미니맵**: 방 사이 벽 틈 위에 문 폭 방향 선분(검은 테두리 + 하늘색, 굵기 3px). 미니맵 축척에서 문 2m 가 2px 남짓이라 점처럼 보여서 선분을 굵기의 2.5배 이상으로 늘렸다.
- ④ **잠긴 바깥 문(현관·냉동실)**: 바닥 = 빨간 띠 + 화살표 대신 **X**, 천장 틈 = 빨강, 미니맵 = 빨강.

## 발표 대비 메모
- **문 위치 표시**: 탑뷰라 카메라 쪽 벽은 지워 보여 주는데, 그러면 그 벽의 문도 사라진다. 그래서 문 자리를 바닥(문턱 띠 + 나가는 방향 화살표)·천장 가장자리(밝은 틈)·미니맵 세 군데에 서버 맵 입구 데이터 그대로 그린다.
- **내 구역에 따라 바뀜**: 문은 두 구역 사이에 있으므로 "지금 내가 있는 쪽"에만 바닥 표시를 그리고 화살표는 늘 바깥(다른 구역)을 가리킨다. 내가 문을 지나면 표시가 반대편으로 옮겨 간다.
- **잠긴 문은 빨강 X**: 서버가 막는 바깥 문 2곳은 세 표시 모두 빨강, 바닥은 X 로 "못 나감"을 알린다.
- **숫자로 조절**: 색·밝기·크기는 데이터 에셋 한곳(DA_VHGameplayConfig)에서 바꾼다.
- **사용자 결정**: 문 위치는 서버 맵 입구 그대로, 바닥 띠 + 바깥쪽 화살표, 천장 위 문 표시, 미니맵 표시, 잠긴 문은 빨강.
