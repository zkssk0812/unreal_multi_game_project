- 처음 상태도 출처에게 묻는다(지금 = 모두 닫힘). 시야·통과 막기·소리·표시·미니맵은 모두 이 상태만 본다.

### F 우선순위
- `UVHInteractionComponent::InteractPressed`: **F 대상 물품(상자·아이템·금고·반납)이 있고 지금 할 수 있으면 그것**, 없거나 할 수 없을 때만(예: 반납할 게 없는데 반납 구역 옆) 앞의 문. 작업 중·다가가는 중의 F(= 취소)와 구르기·공격 중은 예전 그대로.
- 문 고르기: 벽 면에서 앞뒤 150cm·문 폭 바깥 40cm 안의 가장 가까운 문(`DoorInteractDepth`·`DoorInteractSideMargin`). HUD 안내 "[F] 문 열기 / [F] 문 닫기", 잠긴 문은 회색 "잠긴 문".
- 거절 안내(토스트): 잠긴 문 "잠긴 문입니다 — 열 수 없습니다", 문간(문짝 자리)에 서서 닫기 "문간에 서 있어서 닫을 수 없습니다 — 한 걸음 비키세요"(닫히는 문짝·막기 상자가 캐릭터와 겹치지 않게).

### 닫힌 문 통과 막기
- 문마다 `Blocker` 상자(문 구멍 크기). **WorldDynamic, 모든 채널 무시 + Pawn 채널만 막음** → 내 캐릭터 이동(걷기·달리기·구르기·밀려남)만 막히고 총알·시야·마우스 조준·카메라·배치 점검(WorldStatic 만 셈)에는 안 걸린다. 다른 플레이어·경비원 표시는 서버 위치 그대로라 막지 않는다.
- 열림 0.75(`DoorPassAlpha`) 이상이면 통과. `vh.Doors 0`(문 숨김)이면 막지 않음. 이동은 클라 권위라 결과적으로 서버의 내 위치도 막힌다(서버 코드는 그대로).

### 열린 문 너머 부채꼴 시야 (`UVHCeilingSubsystem::UpdatePeek`)
1. 내 구역에 닿은 열린 문마다 문 로컬 좌표(x = 벽을 뚫는 방향, y = 문 폭)에서 **지금 뚫린 문틈**(문짝이 비켜난 만큼, `AVHDoor::GetAperture`)의 양 끝을 지나는 각도 범위를 구한다. 벽이 두꺼우니 **가까운 벽 면과 먼 벽 면 둘 다에서 문틈 안을 지나는 각도만** 남긴다 → 비스듬할수록 좁아진다(측정: 정면 1.3m 58°, 정면 3.2m 31°, 옆 4m 8°).
2. 그 사이 광선 64개를 구역 지도(10cm 칸) 위로 쏜다. 먼 벽 면에서 시작해 **너머 구역 안에서만** 늘리고 벗어나는 곳(= 벽)에서 멈춘다 → 방 모양(ㄱ자 복도, 기둥 자리)대로 잘린다. 내 쪽도 확인: 내 위치 → 문까지가 내 구역 밖(복도 모퉁이 벽)을 지나면 그 광선은 0.
3. 광선 끝을 이어 만든 다각형을 **엿보기 마스크**(렌더 타깃, 구역 지도와 같은 범위 × 3배 해상도 ≈ 3cm 칸)에 그린다. 천장·벽 재질의 ZoneCut 노드가 "카메라 → 픽셀 선을 바닥까지 늘린 점이 마스크 안이면 지운다" — 11-21 (4) 의 "내 구역 앞 가림 지우기"와 같은 원리를 문 너머 부채꼴에도 적용(너머 구역 천장·카메라 쪽 벽·문간 가림막에 부채꼴 구멍). 너머 방 안 기둥은 자기 자리가 마스크 안이면 남긴다.
4. 같은 다각형으로 **사람·경비원·물품(`IsPointPeeked`, 몸 반경 20cm 여유)과 가구(경계 상자 다섯 점)**를 보이게 한다 → 이름표·HP 글자까지 보이고, 부채꼴 밖은 예전처럼 숨김. 미니맵·퍽은 손대지 않음.
- 문틈이 문짝 움직임을 따라가므로 **닫으면 부채꼴이 좁아지다가 덮인다**(별도 페이드 없음). 내가 움직이면 다시 계산(입력이 그대로면 건너뜀 — 내 위치 2cm·문틈·설정이 같으면 계산·그리기 안 함).
- 바라보는 방향과 무관. 설정 `DoorPeekMode` = "문틈 + 바라보는 방향"(반각 `DoorPeekFacingHalfAngle` 60°)으로 바꾸면 조준 방향 부채꼴과 겹치는 부분만 보이게 이미 구현해 둠(시험은 기본값만).
- 처음엔 10cm 마스크라 가장자리가 계단 모양이었다 → 3배(`DoorPeekMaskScale`)로 올려 매끈해짐(`02_…png`).

## 남은 문제
- **문 상태가 클라마다 다르다**(서버에 없음): 내가 연 문이 다른 사람 화면에서는 닫혀 있고, 다른 플레이어·경비원은 내 화면의 닫힌 문을 그냥 지나가는 것처럼 보인다(서버는 문을 모름). 서버 상태가 생기면 출처만 바꿔 끼우면 된다.
- 경비원(서버 AI)은 문과 상관없이 다닌다. 닫힌 문 너머 경비원이 문을 뚫고 나오는 것처럼 보일 수 있다.
- 부채꼴은 "바닥 점" 기준이라 부채꼴 가장자리에 선 사람은 머리 쪽이 천장에 살짝 걸릴 수 있다(판정은 발 위치 + 20cm 여유).
- 비스듬히 볼 때 문간 가림막(세로 회색)이 문 옆에 네모로 보인다 — 부채꼴 밖 = 덮인 부분이라 의도대로지만 어색하면 조정 필요.
- 문 하나 너머(한 단계)까지만 보인다. 너머 구역의 다른 열린 문 너머는 덮임.
- 부채꼴 끝은 최대 30m. 긴 복도 끝 문은 내 위치→문 직선이 복도 안이면 멀리서도 가는 부채꼴이 생긴다(부하 시험 로그 객실 4 2°).
- 사람이 직접 키보드로 한 판은 못 함(`vh.PressF`·`vh.Walk` 는 키 입력과 같은 함수).
- 재질을 다시 만들었으므로 다음 패키징 때 쿡 확인 필요(렌더 타깃은 게임 중 생성이라 에셋 없음).

## 확인 필요 (가정)
- F 우선순위: 물품이 "있고 지금 할 수 있을 때"만 물품, 아니면 문. (물품이 있어도 할 수 없으면 문이 열린다)
- F 문 범위 150cm/옆 40cm, 통과 가능 열림 0.75, 문간 닫기 거절.
- 다른 플레이어·경비원이 문 근처에 와도 내 화면의 문은 바뀌지 않음(서버 상태 전까지 각자).
- 닫힌 문 색 = 흰 회색 0.45배 밝기, 열린 문 = 하늘색.
- 문 너머 한 구역까지만, 최대 30m, 바라보는 방향 무관(설정으로 전환 가능).
- `vh.Doors 0`(문 숨김)이면 모든 문을 열린 것으로 친다(막지 않고 문틈 전체로 엿보기).

## 발표 대비 메모
- **상태는 한 곳에서만 바뀐다**: 문 열림을 바꾸는 함수는 하나(`ApplyDoorState`). 지금은 F 를 누른 내 클라가 부르고, 나중에는 서버 메시지를 받은 코드가 부르면 된다. 화면·소리·시야·막기는 그 상태만 보므로 바꿀 곳이 한 군데다(전략 패턴: "상태 출처" 인터페이스 교체).
- **부채꼴 계산**: 내 눈에서 문틈 양 끝을 잇는 두 선 사이가 보이는 범위. 벽이 두꺼우니 벽 앞면·뒷면 둘 다 문틈 안을 지나는 각도만 남긴다(비스듬히 보면 좁아짐). 그 사이로 광선 64개를 방 지도 위에 쏴서 방을 벗어나면(벽) 멈춘다 → 벽에 가린 곳은 안 보인다.
- **마스크 텍스처**: 광선 끝을 이은 다각형을 위에서 본 흑백 그림(렌더 타깃)에 그려 두면, 천장·벽 재질이 픽셀마다 "이 픽셀이 보는 바닥이 흰 곳인가"만 읽어 지운다. 그림은 문이 움직이거나 내가 움직일 때만 다시 그린다 → 부하 시험(문 39개 모두 열기)에서도 105fps.
- **문짝 = 시야**: 보이는 틈을 문짝이 실제로 비켜난 만큼으로 계산해서, 문을 닫으면 부채꼴이 저절로 좁아지다가 사라진다(따로 페이드 없음).
- **판정은 서버, 화면·내 이동은 클라**: 닫힌 문은 "Pawn 채널만 막는 상자"라 내 캐릭터만 막고 총알·조준·카메라에는 영향이 없다. 이동은 클라가 보낸 위치를 서버가 쓰므로 결과적으로 서버의 내 위치도 막힌다.
- **사용자 결정**: F 로 열고 닫기(자동 열림 없음), 처음엔 모두 닫힘, 잠긴 바깥 문 2곳, 닫힌 문 통과 불가, 내 구역 + 문틈 부채꼴만 보이기(벽에 가린 곳 제외, 마우스 방향 무관), 부채꼴 안은 이름표까지, 미니맵·퍽 그대로, 반납 문구 "반납".

## 어떻게 만들었나
### 문 상태 = 서버 (`IVHDoorStateSource` 서버용 추가)
- `FVHServerDoorStateSource`: F → `UVHServerGameSubsystem::SendDoorInteract` = 지금 위치 CS_MOVE 한 번 + `CS_ACTION InteractBegin(문 엔티티 id)`. **상태는 바꾸지 않는다.** 스냅샷에서 Door 엔티티의 `ES_OPENED` 가 바뀌면 `ApplyServerDoorState` → `ApplyDoorState`(유일한 길) → 문짝·소리·부채꼴 시야·통과 막기·문 표시·미니맵이 모두 따라간다. 그래서 다른 플레이어·경비원이 연 문도 그대로 열리고 부채꼴이 생긴다.
- 출처 선택: 설정 `DoorStateSource` 기본값을 **Server** 로(서버가 Door 엔티티를 보내면 서버, 가짜 서버처럼 문이 없으면 로컬). DA 에 저장된 값이 없어 C++ 기본값이 적용된다.
- **짝짓기** `UVHDoorSubsystem::BindServerDoor`: 클라 문 중 잠기지 않은 37개를 `ServerId` 문자열 순(wall_014 … wall_252)으로 세운 번호 = 서버 type_id. 위치(문 가운데 30cm)·방향(yaw 차 10°, 180° 뒤집힘은 같은 문)으로 확인하고, 어긋나면 위치로 다시 찾아 목록을 로그에 남긴다(`vh.DoorBind`). 결과 **37/37, 어긋남 0, 서버에 없는 문 = wall_134·wall_260(잠김)**.
  - 처음엔 FName 비교(`LexicalLess`)로 정렬했더니 `wall_105` 를 "wall"+숫자로 쪼개 비교해 순서가 23칸 밀렸다 → 위치 확인이 37개 모두 바로잡았고(그래서 동작은 맞았음), 정렬을 문자열 비교로 고쳐 어긋남 0.
- F 고르기: 서버 문은 **문 가운데 140cm(2D) 안**만 고른다(`DoorServerRange`, 서버 150 − 위치 차 여유). 문간에 내가 서서 닫기는 예전처럼 요청 없이 안내.
- 거절(`SC_ACTION_REJECT`, 같은 seq): TargetBusy → **"문간에 누가 있어 닫을 수 없습니다"**, OutOfRange → "문에서 너무 멉니다 — 문 앞 1.5m 안에서 F를 누르세요", 그 밖(경직·쓰러짐 등) → 공통 문구.
- 닫힌 문의 내 캐릭터 막기(`Blocker`, Pawn 채널)는 그대로. 서버도 이동은 막지 않는다.

### 닫힌 문 연출 (서버: 총알·근접·폭발을 막음, 레일건은 뚫음)
- `AVHDoor::BlocksShots`(상태가 닫힘 또는 잠김) + `IntersectPanel`(문짝 자리 상자와 선분 교차) → `UVHDoorSubsystem::TraceClosedDoor`.
- 직선 연출 두 곳에 적용: `UVHWeaponFxSubsystem::OnFire` 의 `LineEnd`(권총 탄 궤적·테이저건 전기 줄기)와 `UVHServerGameSubsystem::SpawnFireFx`(사제 테이저·경비원 기관총·예비 연출). 벽 다음에 닫힌 문을 검사해 **문에서 끊고**, 문에 맞은 불꽃(무기 색 + 나무색) + 짧은 빛 + 소리 `DoorHit`(Kenney `impactPlank_medium_000` + 작은 금속음, `setup_sounds.py nocheck fillone DOOR_HIT` 로 그 칸만 채움).
- 레일건 빔은 원래대로 벽·문을 무시하고 끝까지. 근접 궤적·폭발 이펙트는 그대로(피해 표시는 서버 SC_DAMAGE 가 올 때만 나오므로 문 너머 피해 표시는 생기지 않는다).

### 상자 두 종류
- `AVHBox::SetBoxType(type_id)`: **무기 상자** = 낮고 긴 상자 + **하늘색 띠 + 뚜껑 위 막대**, **환금 상자** = 정육면체 상자 + **금색 띠 + 금화**. 띠·표시는 조명과 관계없는 단색(`M_VHUnlitColor`).
- 안내 "[F] 무기 상자 열기 (3초)" / "[F] 환금 상자 열기 (3초)", 정보창 "무기 상자 · 무기 또는 소비 아이템" / "환금 상자 · 환금 아이템"(띠 색 강조). 미니맵에는 원래 상자 표시가 없어 그대로.
- 가짜 서버 상자 6개에 종류를 넣었다(무기 4·환금 2).
- 상자가 부서지면 같은 자리 1.5초 안에 생긴 아이템을 `[상자 드롭] 무기 상자 → 권총` 으로 로그(시험용).

## 남은 문제
- 무효였던 시도: 첫 문 판(wall_109)은 7초쯤 경비원이 와서 둘 다 쓰러져 뒤쪽이 무효 → 경비원 스폰에서 먼 wall_119 로 다시. 첫 사격 판은 봇 창 위 실제 마우스가 조준을 덮어 yaw 165 로 쏴 무효 → 쏘기 직전 `vh.Aim 0` 으로 고쳐 다시.
- 문에 맞은 불꽃은 화면으로 또렷이 찍지 못했다(문 앞 가까이에서 쏴 F 안내·캐릭터에 가림). 로그로는 문에서 멈춤을 확인, 소리는 귀로 확인 못 함.
- **엔진 기본 도형 재질에 색 파라미터가 먹지 않는다**(`TintMesh`). 상자 몸통·금고 등 `BodyColor` 는 예전부터 실제로는 적용되지 않았던 것 같다. 상자 띠·표시는 단색 재질로 해결, 몸통 색은 그대로(모양·띠로 구분).
- 문 F 는 작업(금고·상자·반납) 중에는 "작업 취소"가 먼저라 문 요청이 가지 않는다(예전과 같음).
- 문이 닫힐 때 서버 위치 지연(최대 50ms)으로 내 캐릭터가 문간에 걸치면 막기 상자와 겹칠 수 있다(서버가 문간 점유로 닫기를 막아서 거의 없음, 시험 중 못 봄).
- 사람이 직접 키보드로 한 판은 못 함.

## 발표 대비 메모
- **상태 출처 바꿔 끼우기**: (2)절에서 문 상태를 바꾸는 길을 하나(`ApplyDoorState`)로 모아 두었기 때문에, 서버 문이 생기자 "출처" 클래스 하나(`FVHServerDoorStateSource`)만 추가했다. F 는 요청만 보내고, 화면은 서버 스냅샷이 올 때만 바뀐다 → 모든 클라와 경비원이 같은 문 상태를 본다(서버 권위).
- **두 기준으로 짝짓기**: 서버는 문을 번호로만 알려 준다. 번호 순서(맵의 문 위 벽 순서 = 이름 순)로 맞추고, 위치·방향으로 한 번 더 확인해서 어긋나면 위치로 바로잡고 목록을 남긴다. 실제로 정렬 실수(FName 이 "wall_105"를 숫자로 쪼갬)를 이 이중 확인이 잡아냈다.
- **판정은 서버, 연출은 같은 규칙으로**: 닫힌 문을 총알이 못 지나가는 것은 서버가 판정한다. 클라는 같은 규칙(닫힌 문 = 벽, 레일건만 통과)으로 선을 문에서 끊고 문에 맞은 불꽃·소리를 낸다 → 화면과 결과가 어긋나지 않는다.
- **같은 틱 맞추기**: 서버는 한 틱의 이벤트를 다 보낸 뒤 스냅샷을 보낸다. 그래서 "반납이 끊김(Cancel)"과 "구역이 사라짐(Despawn)"이 같은 틱인지 스냅샷 전까지 모아 두고 id 를 맞춰 본다. 3곳이 한꺼번에 바뀌어도 내 구역 id 가 아니면 "닫혀서 실패"로 보지 않는다.
- **시험 봇**: 서버 코드는 건드리지 않고, 클라 봇이 무기 상자를 열어 권총·레일건을 직접 구한 뒤 닫힌 문 너머 상대를 쏴서 "막힘/뚫음"을 피해 횟수로 확인했다.
- **사용자 결정**: 서버 기준으로 문 상태·상자 종류를 따름, 바깥 잠긴 문 2곳은 클라에서 계속 잠김, 닫힌 문 이동 막기는 클라, 반납 실패는 같은 틱 id 일치만.
