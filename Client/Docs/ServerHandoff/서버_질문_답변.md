# 서버 질문 답변 (RULES_CHANGE_PLAN.md 10장) — 클라 실제 값

> **좌표 기준을 서버에 맞췄습니다 (2026-10-27).** 클라 `L_Mansion_1F`의 맵을 **원점·회전 없음**(블록아웃 FBX를 언리얼 원점에 회전·크기 변경 없이 놓은 것)으로 바꾸고, 배치한 오브젝트도 모두 같이 옮겼습니다. 화면 방향은 **탑뷰 카메라만 90° 돌려서** 예전과 같습니다(게임 화면 위 = +Y, 화면 왼쪽 = +X = 서쪽).
> → 이 문서와 `mansion_1f_layout.json`의 좌표는 **언리얼 월드 cm 그대로 = 서버 좌표**입니다. 변환할 것 없음.
> 검증: 서버 `mansion_1f_server.json`의 벽 93개를 클라 레벨에서 선 쏘기(trace)로 558번 재서 **모두 0.1cm 안에서 일치**(최대 차이 0.06cm). 문 틈 끝·맵 범위도 일치.

기준: 클라 `client/menu-ui` 브랜치, 레벨 `/Game/VaultHeist/Maps/Mansion/L_Mansion_1F`, 데이터 에셋 `DA_VHGameplayConfig`·`DA_VHInteractionConfig`.
**확인 필요**라고 쓴 것은 클라 팀도 아직 정하지 않은 것입니다(정해지면 다시 알려 드림).

## 2. "서쪽 옆문"의 정확한 위치 → **서버 문서의 ②(화면 위쪽 끝 틈)가 맞습니다**
- 클라는 벽을 뚫지 않았습니다. 클라 평면도에서 "서쪽" = 서버 좌표 **+X 쪽**이라, 서버 탑뷰(위 = +X)에서는 위쪽 끝이 됩니다.
- 틈: x ≈ 9778(바깥 벽 x 9767.9~9787.9), **y −4634.7 ~ −4354.7 (폭 280cm)** — 클라 레벨에서 선 쏘기로 잰 값, 서버 `wall_081`/`wall_082` 사이와 같음.
- 탈출구(`exit`): 위치 **(9778, −4495)**, yaw **180**(앞면 = 건물 안쪽, −X), 문 폭 300cm(틈 280cm보다 양쪽 10cm씩 넓게 덮음), 높이 280cm. 양옆 기둥 40×40cm.
- **탈출 구역(`escape_zone`)은 문 너머 건물 밖**: x **9828 ~ 10048**, y **−4635 ~ −4355** (클라 `EscapeTrigger` 상자 그대로). 열린 뒤 여기에 들어오면 자동 탈출.
- 문 밖 바닥: FBX에 바닥이 없어서 클라가 바닥판 `Floor_Exit`를 놓았습니다 → x **9778 ~ 10180**, y **−4685 ~ −4305**, 윗면 z = 0. `floors`에 `floor_exit`로 넣었습니다.
- 그래서 옛 배치의 `blocker_113`(② 막음)은 없앴고, 대신 정문을 막았습니다(3번).
- `exit.interact_pos` (9658, −4495)는 클라에서 쓰지 않습니다(탈출구와는 상호작용 없음). 서버 `ValidateMap`이 읽는 항목이라 문 안쪽 120cm 지점을 넣었습니다.

> ⚠ **서버 쪽 한 가지 필요**: 지금 `tools/fbx_to_map.py`는 `floors`를 FBX 바닥 5개로 **덮어써서** `floor_exit`가 빠집니다. 그러면 탈출 구역 24칸이 모두 '걸을 수 없는 칸'이 됩니다(클라 쪽 검사 도구로 확인: 우리 파일을 그대로 읽으면 24칸 모두 걸을 수 있음 → 변환 후 0칸).
> 예: `out["floors"] = FBX 바닥 + [f for f in layout.get("floors", []) if "fbx" not in f]` 처럼 FBX에 없는 바닥은 남겨 주세요.
> 또 탈출 구역(x 최대 10048)이 기존 격자(`origin_x` 9790) 밖이라, 우리 파일의 `nav_grid.origin_x`를 **10190**(칸 경계 유지, 8칸 늘림)으로 했습니다. `fbx_to_map.py`는 layout의 `origin_x`를 그대로 쓰므로 그대로 두면 됩니다.

## 5. 반납 지점 상호작용 범위 → **클라가 서버 값(가운데에서 100cm 원)에 맞춥니다**
- 클라 팀 결정(10/27): 서버 10/26 메모의 **"반납 지점 중심에서 100cm 원 안"** 을 기준으로 하고, 클라를 그에 맞게 고칩니다(다음 클라 작업, v2.1 반영과 함께). 서버는 지금 값 그대로 두시면 됩니다.
- 사각형 안에 설 필요는 없음(중심에서 100cm 원 안이면 됨) — 이렇게 이해했는데 판정 여유(+cm)가 있으면 알려 주세요.

참고 — 지금(고치기 전) 클라 구현(`UVHInteractionComponent`, `DA_VHInteractionConfig`):
- 반납 지점 = 바닥의 **1m × 1m 사각형**(중심에서 ±50cm).
- 대상 후보 조건: 캐릭터 중심에서 **사각형 가장자리(가장 가까운 점)까지 수평 거리 ≤ 150cm** (`SearchRadius`), 그리고 바라보는 방향(커서) 좌우 **75°** 안, 그리고 **내 손전등 빛 안**에 보일 것.
- 거리 판정 여유: 상호작용 시작 때 **150 + 50 = 200cm**까지 허용, 넘으면 `OutOfRange`.
- 금고·숨는 곳·떨어진 보물·창고 문도 모두 같은 규칙입니다(각 물체의 상자 가장자리 기준. 창고 문은 문 판만 기준).
- 서버 값보다 넓어서(축 방향으로 중심에서 200cm, 여유 포함 250cm) 그대로 두면 클라에서 대상이 잡혔는데 서버가 거절하는 일이 생깁니다 → 위 결정대로 **반납 지점만** 중심 100cm로 줄입니다(금고·숨는 곳 등 다른 대상은 그대로).
