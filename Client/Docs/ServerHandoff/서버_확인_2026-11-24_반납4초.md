# 서버 확인 2026-11-24 — 반납 4초·테이저·레일건·캐릭터 3명 반영

정호님, 11-22~23에 올려 주신 커밋(`3109190` 반납 구역, `9f88c99` 사제 테이저건, `3d224f6` 레일건, `3e79979` 상자 확률, `416bf22` 캐릭터 3명)에 클라이언트를 맞췄습니다. 서버 코드는 손대지 않았고 팀 저장소 `Server/`를 그대로 빌드(Release x64, 경고 0)해서 시험했습니다. `ContentTests` 178개 모두 통과했습니다. `Common/Protocol/protocol.h`도 그대로 복사했습니다(이번에는 주석 두 곳만 바뀜).

## 클라에서 바꾼 것
- **반납**: F로 시작하는 시간 작업으로 바꿨습니다. `SC_INTERACT` Begin·Cancel·Complete와 `duration_ms`(4000)를 그대로 써서 금고·상자처럼 진행 게이지를 보여 주고, 작업 속도 퍽은 곱하지 않습니다. 구역의 남은 시간은 `SC_ENTITY_SPAWN`의 `timer_ms`로 셉니다(30초를 클라에 고정하지 않음). 자동 반납은 껐습니다.
- **반납이 끊긴 이유 안내**: `SC_INTERACT` Cancel에는 이유가 없어서, 같은 틱에 온 것으로 고릅니다 — 그 구역의 `SC_ENTITY_DESPAWN`(또는 남은 수명 0) = "구역이 닫혀 실패", 내 상태 Stunned = 경직, Cancel 뒤 `SC_DAMAGE` = 맞음, 방금 제가 보낸 공격·구르기·취소 = 그 행동, 제 위치가 범위(100cm) 밖 = 구역 밖.
- **반납 시작 거절**: TargetBusy = "다른 사람이 이 구역에서 반납 중", NotAvailable = "곧 사라지는 구역이라 반납할 수 없음", InvalidState = "반납할 환금 아이템이 없음".
- **사제 테이저건**: 든 동안 휠·E는 서버로 보내지 않고 "Q로 먼저 집어넣으세요" 안내만 띄웁니다(서버 Locked와 같은 결과). 쿨타임 표시는 `SC_PLAYER_STATUS`의 `skill_cooldown_ms` 그대로입니다.
- **레일건**: 클라는 원래 클릭 한 번 = 한 발(내 `SC_FIRE`를 받으면 `AttackStop`)이라 바뀐 서버 동작과 같습니다.
- **캐릭터**: 대기실은 이미 도적1~3만 보여 주고 있었습니다.

## 시험 결과 (팀 서버, 봇)
- 반납: 구역 밖으로 나가면 끊김, 다른 사람이 반납 중인 구역에서 F → TargetBusy, 반납 중 맞으면 끊김(테이저건에 맞으면 "경직"으로 따로 구분), 1.6초 남은 구역에서 F → NotAvailable, 3.2초 남은 구역에서 시작 → 3.2초 뒤 Cancel + 구역 교체, 완료는 F 뒤 3.96초에 Complete와 `SC_MONEY`.
- 테이저·레일건 결과는 작업보고 2026-11-24에 적었습니다.

## 여쭙고 싶은 것
1. 반납 도중 구역이 닫힐 때 Cancel과 구역 교체(Despawn/Spawn)가 같은 틱에 와서 클라가 "닫혀서 실패"로 알아봅니다. 나중에 Cancel 이유를 알려 주는 값이 생기면 더 확실해질 것 같은데, 지금 방식으로 충분하면 그대로 두겠습니다.
2. 11-22에 여쭌 "무기 하나일 때 테이저 든 채 휠"과 "레일건 꾹 누르기"는 이번 커밋으로 해결된 것으로 보았습니다(든 동안 교체 Locked, 쏘면 손 뗀 것으로 처리). 감사합니다.
