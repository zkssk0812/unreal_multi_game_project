## 남은 문제
1. **한 PC에서 클라 3개 이상**을 띄우면 그래픽 메모리가 모자라 일부가 매우 느려진다(혼자 하면 100fps). 봇을 붙여 놓고 직접 해 볼 때는 봇 창을 작게(바탕화면 봇 붙이기는 640×360) 쓰거나 봇에 `-VHFill=0`을 붙인다.
2. **펜던트 조명 기구 14개**(높이 220~255cm)가 탑뷰에서 바로 아래 바닥을 조금 가린다. 숨길지는 사용자 결정.
3. 에디터에서 위에서 내려다본 캡처는 노출이 과하게 밝다(게임 화면은 정상).
4. 서버가 준 금고 방향을 클라가 바꿔 그린다(문 앞이 막힐 때). 보물도 문 앞에 옮겨 그린다. 서버 답에 따라 뺄 수 있다.
5. `DA_VHGameplayConfig`에는 `SafeClass`가 저장돼 있지 않아 C++ 기본값(`BP_VHSafe`)이 쓰인다.
6. 옛 레벨용 문서(`Docs/맵_교체_가이드.md`, `Docs/ServerHandoff/mansion_1f_*.json`)는 옛 맵 기준 그대로다.

## 발표 대비 메모 (2단계)
- **레벨을 손으로 놓지 않고 스크립트로 만든 이유**: 가구 365개·조명 293개·방 영역 35개를 사람이 놓으면 서버 맵과 1cm라도 어긋날 수 있다. 서버가 쓰는 것과 같은 숫자(패키지의 배치 목록, 서버 맵 JSON의 방 범위)를 스크립트가 그대로 읽어 놓으므로 두 쪽이 정확히 같다. 다시 만들 때도 명령 두 줄이면 된다.
- **금고를 서버 위치에 만드는 방식**: 예전에는 레벨에 금고 자리 10곳을 놓고 서버가 고른 자리의 금고를 켰다. 서버가 "방 안 아무 칸"으로 바뀌어, 상자·반납지점처럼 서버가 보낸 좌표에 금고 액터를 만든다. 문이 벽을 보지 않게 빈 방향으로 돌리는 것은 화면만의 일이고, 작업 거리 판정은 서버가 금고 중심에서 잰다.
- **서버와 클라의 충돌이 같은지 확인하는 법**: 서버가 물건을 놓은 좌표마다 클라 레벨에서 "그 자리에 벽·가구가 있는지"(겹침 검사)와 "어느 방 안인지"를 로그로 남긴다. 사람이 일일이 보지 않아도 판마다 자동으로 점검된다(이번 57곳 중 0곳 어긋남).
- **방 모양이 직사각형 하나가 아닐 때**: 복도처럼 꺾인 방은 직사각형 조각 여러 개(복도는 66조각)로 표현한다. 미니맵은 조각을 그대로 그리고, "지금 어느 방인가"는 조각 중 하나에 들어 있는지로 판단한다.
- **조명이 많아도 프레임이 버티는 이유와 측정**: 채움광 277개는 그림자를 만들지 않는 조명이라 비용이 작다. 다 켰을 때 101fps, 다 껐을 때 115fps로 차이가 12% 정도여서 그대로 두었다. 탑뷰에서는 광원이 바닥에 흰 점으로 비쳐 보여 반사만 껐다.
- **사용자 결정·가정**: 원본은 LFS로 보관·낮 조명 유지(사용자), 카메라 방향·방 이름·펜던트는 화면을 보고 결정 예정(임시 값).

| 실서버 다시 한 판 | ❌ 안 함(레벨의 보이기 설정만 바꿨고 코드는 그대로) |

- 백그라운드에 남아 있던 시험 서버 대기 작업(서버는 이미 꺼졌고 대기용 `ping`만 남아 있었음)을 멈췄다. 지금 켜져 있는 `GameServer`·봇은 없다.

## 발표 대비 메모
- **펜던트를 지우지 않고 숨긴 이유**: 조명 기구의 "모양"(메시 액터)과 "빛"(점 조명 액터)은 서로 다른 액터다. 탑뷰에서는 머리 위에 매달린 모양이 캐릭터를 가리므로 모양만 "게임에서 숨김"으로 바꿨다. 빛은 그대로라 방 분위기는 같고, 에디터에서는 기구가 계속 보여 배치를 고칠 수 있다.
- **화면 방향을 +X 위로 둔 이유**: WASD가 화면(월드) 축 고정 이동이고 조작키 문서에서 W = +X이므로, 화면 위가 +X여야 "W를 누르면 화면 위로 간다"가 성립한다. 미니맵도 같은 방향으로 그린다.
