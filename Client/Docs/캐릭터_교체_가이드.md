## 0-1. 지금 들어간 캐릭터와 다시 만드는 순서 (Tripo FBX, Mixamo 뼈대)
| 무엇 | 위치 |
|---|---|
| 원본 | `SourceArt/Characters/Thief/Thief.fbx`, `Guard/Guard.fbx` + `Textures/`(2048 jpg). 4096 원본·zip은 로컬에만 |
| 메시·재질 | `/Game/VaultHeist/Characters/Thief/SK_VHThief`(+`MI_VHThief`), `Guard/SK_VHGuard`(+`MI_VHGuard`), 공용 `Materials/M_VHCharacter` |
| 애니메이션 | `Thief/Anims`(ABP `ABP_VHThief_VHThief` 포함), `Guard/Anims`, 리타게팅 자산 `Retarget/` |
| 경비원 총·링 | `Guard/SM_VHGuardGun`, `Materials/M_VHPlayerRing` |
| 비교 이미지 | `Docs/Design/Characters_v1/` |

다시 만들기 (에디터 아래쪽 Cmd 칸, 플레이는 멈춘 상태. 스크립트는 `Tools/CharacterBuild/`):
1. `py ".../import_characters.py" all` — 임포트(배율 180) → **뼈 크기 굽기(fixscale)** → 텍스처 → 재질. ⚠️ Tripo FBX는 배율이 Hips 뼈 크기로 들어가 애니메이션에서 몸이 뭉치므로 fixscale을 빼면 안 된다.
2. (스켈레톤을 새로 만들었다면) 에디터를 닫고 `Content/VaultHeist/Characters/*/Anims` 폴더를 지운 뒤 다시 연다 — 열린 에셋은 스크립트로 강제 삭제하지 않는다.
3. `py ".../retarget.py" all` — IK Rig·리타게터·애니메이션(걷기·달리기는 제자리로).
4. 소켓이 없으면 MCP `editor_toolset.toolsets.skeletal_mesh.SkeletalMeshTools.add_socket`(SK_VHThief, `WeaponSocket_R`, 본 `RightHand`).
5. `py ".../setup_character_data.py" ring gun socket grip data gunfit sword` — 링 재질·기관총·소켓 값·근접 손잡이 보정·DA·총 위치·근접 자세/베기.

손으로 고칠 때 (`DA_VHCharacterVisuals`):
- **쥔 손가락**: `Weapon|Grip`의 `Grip Fingers`(주먹)·`Ranged Grip Fingers`(총)·`Left Grip Fingers`. 값은 뼈 자기 축 회전이라 직접 고치기보다 스크립트의 `FIST`·`GUN_GRIP`·`LEFT` 각도(뿌리·가운데·끝 마디)를 고치고 `data`를 다시 돌린다.
- **근접 든 자세·베기**: `Weapon Poses`·`Attack Motions`의 삼단봉·도검·빔 소드. 스크립트 `SWORD_HOLD`(수평에서 50° 세움 = 조준 쪽 40° 기울임)·`SWORD_KEYS`·`SWORD_EFFECT`(연출 순간·궤적 시간). 키 시간은 서버 간격(삼단봉·도검 0.5초, 빔 소드 0.333초)보다 짧게.
- **궤적**: 동작의 `Effect Time` = 칼날이 부채꼴 오른쪽 끝(+60°)에 올 때, `Effect Duration` = 왼쪽 끝(−60°)까지 걸리는 시간.
- **쓰러짐**: `Downed`의 `Down Anim`·`Down Show Seconds`(1.4)·`Down Play Rate`(1.3).
- **경비원**: `Guard` 칸(메시·서기/걷기/달리기/사격 자세·총 메시·붙일 뼈·보정·속도).
- **플레이어 색**: `Players` 칸(링 보이기·색 목록·지름·이름표 색).

확인 명령(게임 레벨 ▶): `vh.Cam 330 -14 -125 20`(가까이) / `vh.Cam off`, `vh.Ring 0`, `vh.Weapon N`, `vh.WeaponAnim N 초`, `vh.Down`, `vh.ProxyTest N -200 0`(서버 없이 다른 플레이어 표시를 옆에 세움 — `vh.WeaponAnim`이 같이 재생). ⚠️ 콘솔 명령을 새로 추가했으면 Live Coding 말고 정식 빌드.

## 0-2. 여러 캐릭터 (2026-11-20: 도적1~3)

플레이어 캐릭터는 **도적1·도적2·도적3 세 명으로 확정**이다. 대기실에서 고른 번호가 서버를 거쳐 모든 클라이언트에 같은 값으로 간다(아래 "번호가 전달되는 길"). C++ 코드는 고치지 않는다.

| 번호 | 모델 | 어디에 | 지금 |
|---|---|---|---|
| 도적1 | 캐릭터1 (`SourceArt/Characters/Thief`) | `DA_VHCharacterVisuals` → **Default** 칸 | 완성 |
| 도적2 | 캐릭터2 (`SourceArt/Characters/Thief2`) | `DA_VHCharacterVisuals` → **Characters[2]** | 완성 (`/Game/VaultHeist/Characters/Thief2/SK_VHThief2`) |
| 도적3 | 캐릭터3 (`SourceArt/Characters/Thief3`, 2026-11-21 리깅본) | `DA_VHCharacterVisuals` → **Characters[3]** | 완성 (`/Game/VaultHeist/Characters/Thief3/SK_VHThief3`). 옛 뼈대 없는 파일은 `Thief3/_old_norig/` |

- **빈 칸 규칙**: 번호 칸이 없거나, 칸이 있어도 `Mesh`가 비어 있으면 그 번호는 **Default(도적1) 모습 전체**를 쓴다(`UVHCharacterVisuals::Find`). → 도적3은 메시만 넣으면 바로 그 칸이 살아난다.
- **캐릭터 선택 창**: `DA_VHGameData` → Characters 목록(1·2·3)이 그대로 버튼이 된다. 버튼 위 얼굴 그림 = 각 칸의 `Portrait` (`/Game/VaultHeist/UI/Portraits/T_VHPortrait_Thief1·2·3`). 그림이 없으면 "모델 준비 중 (지금은 도적1 모습)" 글자. 게임 HUD 왼쪽 아래 얼굴 칸도 같은 그림을 쓴다.
- 서버(v3.0)는 캐릭터 1~5 를 받지만 클라이언트는 1~3 만 보여 주고, 개발용 봇·가짜 서버도 1~3 만 고른다.

### 스켈레톤을 함께 쓰는 방법 (도적2가 이렇게 들어갔다)
모든 도적이 **캐릭터1 스켈레톤(`SK_VHThief_Skeleton`) 하나**를 쓴다 → 애니메이션(Mixamo·권총/라이플·블렌드스페이스·몽타주 약 100개)을 캐릭터마다 다시 만들 필요가 없다.
1. 같은 Tripo(Mixamo 이름) 뼈대라도 **뼈 자기 축 방향이 캐릭터마다 다르다**(캐릭터2: 평균 10°, 오른 아래팔 52°). 그대로 쓰면 팔이 비틀린다. → `import_characters.py share` 단계가 뼈마다 "관절 위치는 그 캐릭터 그대로, 축 방향은 캐릭터1과 같게" 바인드 자세를 다시 잡는다(메시 모양은 그대로). 끝 뼈 이름(`Head_end`·`*3_end`·`*ToeBase_end`)도 캐릭터1 이름(`HeadTop_End`·`*4`·`*Toe_End`)으로 바꾼다.
2. 팔·다리 길이는 캐릭터마다 다르므로 스켈레톤의 **뼈 이동 리타게팅 모드**를 `Hips = AnimationScaled`, 나머지 = `Skeleton`으로 둔다(`setup_character_data.py retargetmode`). 각 메시가 자기 뼈 길이로 같은 애니메이션을 쓴다. 캐릭터1 애니메이션의 뼈 이동값은 캐릭터1 기본 자세와 0cm 차이라(`_probe_trans.py`) 도적1 모습은 바뀌지 않는다.
3. 손 소켓 `WeaponSocket_R`은 메시마다 따로 있다(MCP `SkeletalMeshTools.add_socket` 으로 만들고 `socket2` 단계가 그 메시 손가락 관절로 위치를 계산). 도적2 결과 (−0.1, −8.6, 2.9) = 도적1 (−0.4, −8.5, 2.9)과 거의 같음.
4. 무기 손 위치: 무기 10종의 "손 뼈 ↔ 무기 손잡이 소켓" 거리가 도적1과 0.1cm(왼손 0.8cm) 안으로 같아 **캐릭터별 보정 없음**. 어긋나는 캐릭터가 오면 `setup_character_data.py` 의 `CHAR_FIT`(손 소켓 추가 보정·무기 배율) 을 고치고 `chars` 를 다시 돌린다.
   - 숫자 비교(2026-11-21): 미리보기 레벨 ▶ 에서 `vh.Char N` 뒤 `bash Tools/WeaponBuild/dump_all_points.sh hN` (캐릭터마다) → `엔진파이썬 -I Tools/WeaponBuild/compare_points.py h1 h2 h3`. 보는 값은 **R소켓**(손 소켓 = 쥔 주먹 가운데 ↔ 무기 Grip 소켓, 캐릭터끼리 같아야 함)과 **L손**(왼손 뼈 ↔ SupportHand 소켓). **R손목**(손목 뼈 ↔ Grip)은 손 크기가 다르면 달라지는 게 정상이다(손 소켓을 그 메시 손가락 관절로 계산하므로).
5. 뼈대 비교 도구: `엔진파이썬 -I Tools/CharacterBuild/compare_rigs.py A.fbx B.fbx` (뼈 수·이름 차이·축 차이), 한 파일만 주면 뼈·스킨(Deformer) 유무 → 리깅 여부 확인.

### 번호가 전달되는 길 (서버 프로토콜 v3.0, 서버 코드 수정 없음)
대기실 `CS_SELECT_CHARACTER(character_id)` → 서버가 방 전원에게 `SC_ROOM_STATE`(멤버별 `character_id`, 중복이면 `CharacterTaken`) → 게임 시작 `SC_GAME_START`/`SC_ENTITY_SPAWN` 의 플레이어 엔티티 `type_id` = 캐릭터 번호 → 내 캐릭터 `UVHWeaponVisualComponent::SetCharacterId`, 다른 플레이어 `AVHNetProxy::InitProxy` 가 같은 표(`DA_VHCharacterVisuals`)를 본다. 로그 `[캐릭터] 내 캐릭터 2 → 메시 SK_VHThief2` / `[캐릭터] 다른 플레이어 엔티티 2 'Bob' 캐릭터 2 → 메시 SK_VHThief2`.

### 새 도적을 하나 더 넣을 때 (예: 도적2를 다시 만들 때도 같음)
1. zip 을 `SourceArt/Characters/ThiefN/`에 풀고 `ThiefN.fbx`, 4K 원본은 `Original4k/T_ThiefN_Color·Metallic·Roughness(·Normal).jpg` → `powershell -File Tools/CharacterBuild/resize_textures.ps1 ThiefN` (2048 로 `Textures/`).

   - 끝 뼈 이름이 다르면(캐릭터2: `Head_end`·`*3_end`) `share` 단계가 캐릭터1 이름으로 바꾼다. 캐릭터1 끝 뼈 아래에 `*_end` 가 하나 더 붙어 있으면(캐릭터3: 78개) `share` 단계가 지운다 — **스킨 가중치가 없는 뼈만**(FBX 클러스터 없음. 확인: 0-3절 1번).

4. 에디터 Cmd 칸(플레이 멈춘 상태): `py "C:/UnrealProjects/MCPTest/Tools/CharacterBuild/import_characters.py" all ThiefN` (임포트 → 뼈 크기 굽기 → 뼈 축 맞춤·캐릭터1 스켈레톤으로 다시 임포트 → 텍스처 → 재질 → 확인). 로그에 `다시 임포트: 스켈레톤 = …SK_VHThief_Skeleton` 이 나와야 한다.

## 0. 먼저 알아 둘 구조 (한 장 요약)

| 무엇 | 어디에 있나 | 누가 읽나 |
|---|---|---|
| 캐릭터 메시·애니메이션·무기 드는 방법 | `/Game/VaultHeist/Weapons/Data/DA_VHCharacterVisuals` | 내 캐릭터, 다른 플레이어 표시 둘 다 |
| 무기 메시·아이콘·재질·무기 쪽 손 보정 | `/Game/VaultHeist/Weapons/Data/DA_VHWeaponCatalog` | 바닥 무기, 손에 든 무기, HUD |
| 무기를 캐릭터에 붙이는 기능 | 컴포넌트 `VH Weapon Visual` (`UVHWeaponVisualComponent`) | 내 캐릭터 블루프린트, `AVHNetProxy` |
| 팔을 무기 자세로 뻗고 무기 동작을 재생하는 기능 | 애니메이션 인스턴스 `UVHThiefAnimInstance` (내 캐릭터는 이를 부모로 한 `/Game/VaultHeist/Animation/ABP_VHThief`) | 내 캐릭터, 다른 플레이어 둘 다 |

- 무기의 최종 위치 = **캐릭터 보정 × 무기 보정**. 캐릭터가 바뀌면 캐릭터 쪽 값만, 무기 모델이 바뀌면 무기 쪽 값만 고친다.
- 누가 무슨 무기를 들었는지는 서버가 알려 준다. 여기서 정하는 것은 "어떻게 보이는가"뿐이다.

## 1. 캐릭터 메시를 임포트한다
1. 콘텐츠 브라우저에서 새 폴더(예: `/Game/VaultHeist/Characters/Thief01`)를 만들고 FBX를 끌어다 놓는다.
2. 임포트 창에서 **스켈레탈 메시**로, 스켈레톤은 새로 만들게 둔다.
3. 캐릭터는 **발이 원점**(Z = 0)에 있고 **+Y 쪽(언리얼 마네킹과 같은 방향)을 바라보게** 되어 있어야 한다. 다르면 모델러에게 맞춰 달라고 하거나, 임포트 창의 "임포트 회전"으로 맞춘다.

## 2. 손 소켓을 만든다 (이름: `WeaponSocket_R`)
1. 콘텐츠 브라우저에서 캐릭터의 **스켈레탈 메시**를 더블클릭해 연다.
2. 왼쪽 **스켈레톤 트리**에서 오른손 본(보통 `hand_r`)을 찾아 **우클릭 → 소켓 추가**.
3. 소켓 이름을 `WeaponSocket_R`로 바꾼다. (다른 이름을 쓰려면 3번의 `Weapon Socket Name`을 그 이름으로 바꾼다.)
4. 소켓을 선택하고 오른쪽 디테일에서 위치·회전을 맞춘다. 약속은 이렇다.
   - 소켓의 **빨간 축(+X) = 무기 앞쪽**(총구·칼끝이 향하는 쪽)
   - 소켓의 **파란 축(+Z) = 무기 위쪽**(권총이면 슬라이드 쪽)
   - 위치 = 손바닥 가운데(손잡이를 쥐는 자리)
5. 소켓을 **우클릭 → 프리뷰 에셋 추가**에서 `SM_VHW_04_Pistol`을 고르면 권총이 손에 붙은 모습을 바로 볼 수 있다. 보면서 4번 값을 맞추고 저장한다.
   - 참고(마네킹 값, 2026-11-17 손가락 뼈로 계산): 본 `hand_r`, 위치 (−5.3, −1.2, 0.3), 회전 Pitch 3 · Yaw −167 · Roll 0.6.
   - 계산을 도와주는 명령: 게임 레벨 ▶ 뒤 Cmd 칸에 `vh.SocketGuess` (뼈 이름이 다르면 `vh.SocketGuess 손뼈 가운데손가락뼈 집게손가락뼈 새끼손가락뼈`) → 출력 로그에 추천 위치·회전. 또는 에디터(플레이 아님)에서 `py "C:/UnrealProjects/MCPTest/Tools/WeaponBuild/setup_anim.py" guess`.
- 소켓이 없어도 게임은 멈추지 않는다. 출력 로그에 `[무기 표시] … 소켓 'WeaponSocket_R'이 없습니다 → 몸 앞 기본 위치에 붙입니다` 경고가 한 번 나오고 무기는 몸 앞에 붙는다.
- 던지기·설치 연출용 소켓이 따로 필요해지면(예: `ThrowSocket_R`) 같은 방법으로 만들고, 그때 `DA_VHCharacterVisuals`에 칸을 하나 더 만든다(지금은 필요 없다).

## 3. 캐릭터 표에 넣는다 (`DA_VHCharacterVisuals`)
콘텐츠 브라우저 → `/Game/VaultHeist/Weapons/Data/DA_VHCharacterVisuals`를 연다.

- **모든 캐릭터를 한 번에 바꾸려면** `Default` 칸을 고친다.
- **캐릭터 번호(대기실의 도적1~3)마다 다르게 하려면** `Characters`에 `+`로 칸을 추가하고 키에 번호를 넣는다. 번호 칸이 없거나 그 칸의 Mesh 가 비어 있으면 `Default`(도적1)를 쓴다. (지금: 2 = 도적2, 3 = 비어 있음 → 0-2절)

| 칸 | 넣을 것 |
|---|---|
| Mesh | 1번에서 임포트한 스켈레탈 메시 |
| Anim Class | 내 캐릭터가 쓸 애니메이션 블루프린트 (비우면 캐릭터 블루프린트에 들어 있는 것 그대로) |
| Idle / Walk / Run Anim | 다른 플레이어를 보여 줄 때 쓰는 서기·걷기·달리기 애니메이션 |
| Hold Mode | **`손 소켓`(기본)**: 무기를 손 소켓에 붙이고 팔을 자세 위치로 뻗는다. `몸 앞 기본 위치`는 소켓이 없는 캐릭터용 예비 방식 |
| Weapon Socket Name | 2번에서 만든 소켓 이름 (`WeaponSocket_R`) |
| Socket Offset | 이 캐릭터만의 손 보정. 소켓을 잘 맞췄다면 0 그대로 |
| Melee / Ranged / Thrown / Placed Pose | **무기 분류별 든 자세**. `Weapon` = 무기 손잡이가 놓일 자리·각도(발 기준 앞 X·오른쪽 Y·높이 Z cm, 회전 0 = 총구·날 끝이 조준 방향, Roll 90 = 옆으로 눕혀 탑뷰에서 옆모습). `Elbow Direction` = 팔꿈치가 향하는 쪽, `Left Hand Support` + `Left Hand On Weapon` = 왼손 받치기. **키·팔 길이가 다르면 X·Z를 같이 고친다** (마네킹: 근접 40·26·108 / 원거리 54·17·128 / 투척 34·27·118 / 설치 44·0·102) |
| Weapon Poses | 무기별 든 자세(분류 자세 대신). 지금: 화염방사기·레일건 = 두 손으로 허리~가슴 높이 |
| Procedural Arms | 켜면 코드가 팔 뼈를 돌려 손을 자세 위치로 보낸다. **팀 캐릭터 애니메이션이 무기 든 자세를 이미 갖고 있으면 끈다** (무기는 손 소켓을 그대로 따라간다) |
| Right/Left Upper·Lower Arm Bone, Hand Bone, Spine Bone | 코드가 돌리는 뼈 이름 (마네킹: `upperarm_r`·`lowerarm_r`·`hand_r`·…·`spine_03`). 뼈 이름이 다른 캐릭터는 여기만 고친다. 이름이 틀리면 팔을 건드리지 않는다(멈추지 않음) |
| Attack Motions / Hold Motions / Railgun Lock Motion | 무기 사용 동작(7절) |
| Weapon Scale | 이 캐릭터가 든 무기 크기 배율 (몸집이 작으면 0.8처럼) |

## 4. 컴포넌트를 연결한다
- **지금 캐릭터 블루프린트(`BP_VHTestThief`)를 그대로 쓰면 할 일이 없다.** 이미 `VH Weapon Visual` 컴포넌트가 붙어 있고, 3번의 Mesh·Anim Class(`ABP_VHThief`)를 게임 시작 때 스스로 입힌다.
- **팀 캐릭터의 애니메이션 블루프린트를 쓸 때**: 그 블루프린트를 열고 툴바 **클래스 세팅 → 디테일 → 부모 클래스**를 `VHThiefAnimInstance`로 바꾸고 컴파일·저장 → 3번의 `Anim Class`에 넣는다. 그러면 팔 자세·무기 동작이 그 캐릭터의 걷기·뛰기 위에 그대로 덮인다. 몽타주를 쓰려면 애님 그래프에 `DefaultSlot` 슬롯 노드가 있어야 한다(템플릿 ABP에는 있다).
- **새 캐릭터 블루프린트를 만들었다면**: 블루프린트를 열고 왼쪽 위 **+ 추가 → `VH Weapon Visual`** 을 넣고 컴파일·저장한다. 그 밖의 연결은 필요 없다(서버 값이 오면 서브시스템이 이 컴포넌트를 찾아 알려 준다).
  - 스켈레탈 메시 컴포넌트가 여러 개면 컴포넌트의 `Target Mesh Component Name`에 무기를 붙일 컴포넌트 이름을 적는다.
- 다른 플레이어 표시(`AVHNetProxy`)는 코드가 같은 컴포넌트를 달고 같은 표를 읽으므로 따로 할 일이 없다.

## 6. 무기별로 손에 안 맞을 때 (`DA_VHWeaponCatalog`)
- 특정 무기만 손에서 어긋나면 그 무기 칸의 `Grip Offset`(위치·회전)을 고친다. 캐릭터 쪽 값은 건드리지 않는다.
- 무기 전체가 너무 작거나 크면 맨 아래 `Held Scale`(손), `Floor Scale`(바닥) — 지금 둘 다 2배. 무기 칸의 `Held Scale`·`Floor Scale`은 그 무기만 곱하는 값이다(긴 무기는 0.5~0.6).
- 바닥 방식(`Floor Mode`): `3D 모델` 또는 `구상안 탑뷰 그림`(납작한 판). 지금은 테이저건만 그림 판, 나머지는 3D 모델.
- 표의 값(배율·바닥 방식·메시 연결)은 `Tools/WeaponBuild/setup_weapon_assets.py data`를 다시 돌리면 스크립트의 표(`WEAPON_SCALE`·`FLOOR_MODE`)로 덮어쓰인다. 에디터에서 손으로 고쳤다면 스크립트 표도 같이 고친다.
- 모델러가 무기 모델을 새로 주면 그 무기 칸의 `Mesh`만 바꾼다(바닥에서도 그 모델을 보이게 하려면 `Floor Mode`를 `3D 모델`로). 모델 약속: 실제 크기(cm), +X = 총구·칼끝, +Z = 위, 피벗 = 손잡이(지뢰는 바닥 중앙).

## 7. 무기 사용 동작 (키 프레임 · 몽타주)

지금은 새 애니메이션 파일 없이 **키 프레임(시간 곡선)** 으로 팔·허리 뼈를 돌린다. 값은 `DA_VHCharacterVisuals` 캐릭터 칸에 있다.

| 칸 | 언제 재생되나 (서버 이벤트) | 지금 들어 있는 것 |
|---|---|---|
| Attack Motions (무기별) | `SC_FIRE` 한 번 (쏜 사람이 나든 다른 플레이어든) | 삼단봉 내려치기, 도검 가로 베기, 빔 소드 사선 베기, 권총·테이저 반동, 레일건 큰 반동, 수류탄 던지기, 지뢰 내려놓기 |
| Hold Motions (무기별) | 공격 키를 누르는 동안 (`ES_ATTACKING`, 내 캐릭터는 보낸 공격 시작/끝) | 화염방사기 겨누기(떨림), 레일건 충전 |
| Railgun Lock Motion | 레일건 발사 1초 (`ES_RAILGUN_LOCK`) | 버팀 자세(떨림) |
| Category Attack Montages (분류별) / 각 동작의 Montage | 위와 같음 | 비어 있음 → **팀 캐릭터의 몽타주를 넣으면 키 프레임 대신 재생** |

- 키 하나 = `Time`(초) · `Hand Offset`(손 위치 이동 cm, 조준 방향 기준) · `Weapon Rotation`(Yaw + = 오른쪽, Pitch + = 위) · `Spine Yaw`(허리 비틀기) · `Spine Pitch`(+ = 앞으로 숙임).
- `Effect Time` = 연출 순간(총구 불꽃, 칼 궤적의 가장 빠른 때, 수류탄이 손을 떠나는 때, 지뢰가 바닥에 닿는 때). 던지기·설치는 이 순간에 손의 무기가 사라진다.
- **동작 길이는 서버 공격 간격보다 길면 자동으로 빨리 재생한다** (`UVHWeaponCatalog::ServerIntervalSeconds` = 서버 `GameData.h` 값: 삼단봉·도검 0.5초, 빔 소드 0.333초, 권총 0.25초, 레일건·테이저·수류탄·지뢰 1초). 몽타주도 같다.
- 몽타주로 바꿀 때: 몽타주 길이가 위 간격보다 짧게, 연출 순간(`Effect Time`)은 몽타주의 그 순간 시간으로 맞춘다.
- 확인 명령(게임 레벨 ▶ 뒤 Cmd 칸): `vh.Aim -90`(조준 방향 고정) → `vh.WeaponAnim 2`(도검 공격 재생) / `vh.WeaponAnim 2 0.14`(0.14초에 멈춤) / `vh.WeaponAnim off` / `vh.WeaponHold 1`(꾹 누르기) / `vh.RailLock 1` / `vh.Walk 0 1 3 1`(오른쪽으로 3초 달리기).
- 다른 플레이어 표시(`AVHNetProxy`)는 그래프 없이 `UVHThiefAnimInstance`를 쓰므로 **몽타주는 재생되지 않고 키 프레임만** 나온다. 팀 캐릭터 몽타주를 다른 플레이어에도 쓰려면 `AVHNetProxy::InitProxy`에서 캐릭터의 Anim Class를 입히고, 그 그래프가 `VHGroundSpeed`(이 클래스가 채우는 속도)를 읽게 만든다.

## 8. 무기 이펙트 위치 옮기기 (캐릭터·무기 모델이 바뀌었을 때)

이펙트는 `UVHWeaponFxSubsystem`(코드)이 그리고, 위치는 아래에서 읽는다. 캐릭터가 바뀌어도 코드는 고치지 않는다.

| 이펙트 | 위치를 정하는 것 | 팀 캐릭터·모델로 바꿀 때 |
|---|---|---|
| 총구 불꽃·탄 궤적·전기 줄기 시작점·레일건 충전 빛 | 무기 메시의 **`Muzzle` 소켓** (없으면 메시의 앞(+X) 끝) | 정식 무기 모델이 오면 스태틱 메시 에디터에서 총구에 `Muzzle` 소켓을 만든다 |
| 근접 궤적 | 캐릭터 발 위치 + 60cm, 조준 방향 (판정 부채꼴 그대로) | 할 일 없음 (판정 범위라 캐릭터와 무관) |
| 빔 소드 날 잔상 | 손에 든 무기 메시 자체를 복사 | 할 일 없음 |
| 연출 순간(총구 불꽃·궤적·수류탄 출발·지뢰 놓임) | 7절 동작의 `Effect Time` | 몽타주로 바꾸면 그 몽타주에서 같은 순간의 시간(초)을 `Effect Time`에 넣는다 |
| 날아가는 수류탄 출발점 | 손에 든 수류탄 메시 위치 | 할 일 없음 |
| 설치된 지뢰·날아가는 수류탄 모델 | `DA_VHWeaponCatalog`의 그 무기 `Mesh`·`Floor Scale`·`Held Scale` | 모델만 바꾸면 따라간다 |
| 감전·불붙음 | 맞은 캐릭터 발 위치 기준 몸 높이 20~175cm, 반지름 40cm | 키가 크게 다르면 `VHWeaponFx.cpp`의 높이 값을 고친다(지금은 서버 몸 크기 180cm 기준) |

- 판정 범위(부채꼴·빔 폭·폭발 반지름)는 서버 `GameData.h` 값이 `VHWeaponFx.cpp`의 `VHFx` 상수에 있다. 서버 값이 바뀌면 거기를 고친다.
- 색: `DA_VHWeaponCatalog`의 분류 색(`Melee/Ranged/Thrown/Placed Glow`)·`Flame Color`.
- 나이아가라: `DA_VHWeaponCatalog`의 `Explosion/Smoke/Hit Spark Niagara`(화염은 비어 있음 = 도형 방식). `Use Niagara`를 끄면 전부 도형 방식. 다시 만들기: `엔진파이썬 -I Tools/WeaponBuild/setup_niagara.py hitspark explosion smoke` → 에디터 Cmd 칸 `py ".../setup_fx.py" data`.
- 확인 명령(게임 레벨 ▶): `vh.Aim -90` → `slomo 0.05` → `vh.Fx N`(1~10), `vh.Fx hit N`, `vh.Fx smoke`, 끝나면 `slomo 1`.

## 8-2. 구르기 동작 (키 프레임 · 몽타주) — `DA_VHCharacterVisuals` 캐릭터 칸의 **Roll Motion**

지금은 새 애니메이션 파일 없이 **키 프레임 + 뼈 회전**으로 앞구르기 한 바퀴를 만든다: 숙이며 웅크림(허리·목·허벅지·무릎·팔 뼈) → 몸 전체를 구르는 방향으로 한 바퀴 → 펴며 일어섬.

| 칸 | 뜻 | 지금 값 |
|---|---|---|
| `Keys` | 시간은 **비율(0~1)**. `Tuck`(웅크림 0~1)·`Flip`(앞구르기 각도, 360 = 한 바퀴)·`Drop`(몸 낮춤 cm)·`Face`(몸을 구르는 방향으로 돌린 정도) | 0 → 0.12 숙임 → 0.22~0.62 공처럼 돎 → 0.8~1 일어섬 |
| `Pivot Height` | 한 바퀴 돌 때 중심 높이(발바닥 기준 cm) | 55 |
| `Spine Curl`·`Head Tuck`·`Hip Flex`·`Knee Bend`·`Arm Forward`·`Elbow Bend` | 다 웅크렸을 때 뼈 각도(도) | 80·35·105·125·105·55 |
| `Leg Gather` | 다리 모으기(0~1). 걷기·달리기 보폭을 웅크린 만큼 기본 자세(나란히 선 다리) 쪽으로 되돌린 뒤 굽힌다 → 거꾸로 도는 순간(60%) 발이 벌어지지 않는다 | 1 |
| `Knees In` | 무릎을 몸 가운데로 모으는 각도(도) | 6 |
| `Spine Bones`·`Head Bones`·`Thigh`·`Calf`·`Foot` | 웅크릴 때 돌리는 뼈 이름 (팔은 `Weapon|Arm Bones` 칸을 같이 씀). 없는 이름은 건너뜀 | 마네킹 이름 |
| `Release At`·`Regrip At` | 무기 든 팔 자세(IK)를 푸는 때·다시 쥐는 때(비율) | 0 · 0.74 |
| **`Hide Weapon`** | **구르는 동안 손에 든 무기를 숨긴다**(시작 → `Regrip At`에 다시 보임). 다른 플레이어 화면도 같다. **팀 몽타주가 무기를 쥔 채 구르는 동작이면 끈다** | 켬 |
| **`Montage`** | **팀 캐릭터의 진짜 구르기 애니메이션.** 넣으면 키 프레임 대신 재생한다 | 비어 있음 |

- **길이는 자동으로 게임의 구르기 시간에 맞춘다**: `DA_VHGameplayConfig`의 `Thief Stats → Roll Seconds`(0.5초 = 서버 무적 `DodgeInvulnMs` 500ms, 이동 9m/s × 0.5초 = 4.5m). 키 시간이 비율이라 이 값이 바뀌어도 그대로 맞는다. 몽타주는 `몽타주 길이 ÷ 구르기 시간` 빠르기로 재생된다(어떤 길이의 몽타주든 0.5초 안에 끝남).
- **방향 = 실제로 굴러가는 방향**: 내 캐릭터는 구르기 시작 때 누르고 있던 이동 키 방향(없으면 커서 방향). 몸은 평소 커서를 보므로 처음 0.12 동안 구르는 쪽으로 돌았다가 끝에서 다시 커서 쪽으로 돌아온다.
- **다른 플레이어(`AVHNetProxy`)**: 스냅샷의 `ES_DODGING`이 켜지는 순간(화면 보간 시점에 맞춰)부터 같은 동작. 방향은 그 사람의 화면 위 실제 이동으로 정한다. 그래프가 없어 **몽타주는 재생되지 않고 키 프레임**이 나온다(7절과 같은 제한).
- **몽타주로 바꾸는 순서**: ① 팀 캐릭터의 구르기 애니메이션에서 몽타주 만들기(콘텐츠 브라우저 → 애니메이션 우클릭 → 생성 → 애님 몽타주 생성, 슬롯 `DefaultSlot`) ② 캐릭터 애니메이션 블루프린트 그래프에 `Slot 'DefaultSlot'` 노드가 있는지 확인 ③ `DA_VHCharacterVisuals` → 그 캐릭터 칸 → `Roll` → `Roll Motion` → `Montage`에 넣고 저장. 애니메이션이 몸을 앞으로 옮기는 "루트 모션"이면 끈다(이동은 코드가 한다).
- 몽타주가 팔에 무기 든 자세까지 갖고 있지 않으면 `Release At`·`Regrip At`은 그대로 둔다(구르는 동안 코드의 팔 IK가 풀림).
- 몽타주가 무기를 손에 쥔 채 구르는 동작(무기가 몸에 붙어 같이 도는 동작)이면 `Hide Weapon`을 끈다. 끄면 무기는 손 소켓에 붙은 채 몽타주를 따라 돈다.
- 확인 명령(게임 레벨 ▶ 뒤 Cmd 칸): `vh.Aim 0` → `vh.RollFreeze 0.4`(구르기 40% 자세에 멈춤) → `vh.RollFreeze off`. 실제 구르기 + 슬로모션 6장: `vh.RollTest 0 1 0 1`(오른쪽으로 걷다 구르기), `vh.RollTest 0 -1 1 1`(왼쪽으로 달리다 구르기) → `Saved/Screenshots`.

## 9. 나중에 애니메이션을 붙일 자리
| 하고 싶은 것 | 붙일 자리 |
|---|---|
| 무기 종류에 따라 든 자세 바꾸기 | 3번의 분류별·무기별 자세(코드가 팔을 돌림). 캐릭터 애니메이션으로 하려면 애니메이션 블루프린트에서 `VHWeaponId`(이 클래스가 채움)로 자세를 고르고 `Procedural Arms`를 끈다 |
| 쏘기·휘두르기·던지기·설치 | 7절의 동작 칸. 코드 연결: `UVHServerGameSubsystem::OnFire` → `UVHWeaponVisualComponent::PlayAttack` |
| 연출(이펙트)을 동작 순간에 맞추기 | `UVHWeaponVisualComponent::OnAnyActionEffect`(어느 캐릭터든 연출 순간에 불린다) → `UVHWeaponFxSubsystem` (8절) |
| 구르기 | 8-2절 `Roll Motion` (몽타주 칸 있음). 코드: 내 캐릭터 `UVHActionComponent::RequestRoll` → `UVHWeaponVisualComponent::PlayRoll`, 다른 플레이어 `AVHNetProxy::PushSnapshot`(`ES_DODGING`) → `StartRollFromSamples` |
| 쓰러짐·경직 | 스냅샷의 상태 비트(`ES_DOWNED`, `ES_STUNNED`) — 내 캐릭터는 `ApplySelfState`, 다른 플레이어는 `AVHNetProxy::UpdateAnimation` |
| 총구 불빛·탄피 | 무기 메시에 `Muzzle` 소켓을 만들고 `OnFire`에서 그 위치를 쓴다(지금은 가슴 높이에서 선을 긋는다) |

다른 플레이어는 지금 서기·걷기·달리기 한 가지씩만 되풀이 재생한다(`AVHNetProxy::UpdateAnimation`). 애니메이션 블루프린트를 쓰게 바꾸려면 그 함수를 고치면 된다.
