## 1. 게임 소개 (3줄)

1. 악당 카피바라 사업가 '바바라'의 어두운 저택에 **의적(도둑) 최대 3명**이 들어가, **5분 안에** 금고를 털어 보물을 반납지점에 반납하고 탈출하는 **PvE 협동 탈출 게임**이다(경비는 서버 AI 예정).
2. **탑뷰 카메라**에서 마우스 커서 쪽을 바라보며 손전등으로 어둠을 비추고, 금고 열기·보물 줍기·반납·숨기·구출·공격을 한다. 팀 반납 가치 **10,000$**를 채우면 탈출구가 열리고, **탈출한 사람은 승리**, 못 하면 패배(개인별 승패).
3. 나는 **클라이언트(Unreal Engine 5.8, C++)** 를 맡았고, 서버(C++ IOCP)는 팀원이 만든다. 서버가 아직 게임 판정을 못 하므로 **같은 프로토콜로 말하는 가짜 서버(Mock)** 를 클라이언트 안에 만들어 메뉴부터 결과창까지 한 흐름을 완성했다.

## 4. 기술적으로 가장 자신 있게 말할 포인트 3개

### ① 서버 없이도 "진짜처럼" 개발한 구조 — 전송 계층 교체 + Mock 서버
- `UVHNetSubsystem`은 `IVHTransport` 인터페이스(바이트 보내기/받기)만 안다. 실제 TCP(`FVHTcpTransport`)와 가짜 서버(`FVHMockTransport` → `FVHMockServer`)가 **같은 바이트 패킷**을 주고받으므로, 위쪽 코드(패킷 해석·UI)는 하나도 바꾸지 않고 설정 `bUseMockServer`만 바꾸면 된다.
- Mock은 일부러 패킷을 1~97바이트 조각으로 잘라서 보낸다(`FVHMockTransport::Tick`, `bMockSplitPackets`) → TCP 스트림 재조립 코드가 실제와 같은 조건에서 늘 시험된다.

### ② TCP 스트림 재조립과 단계별 패킷 제한
- TCP는 "경계 없는 바이트 흐름"이라 패킷이 잘리거나 붙어서 온다. `FVHPacketAssembler::Append`로 쌓고 `Pop`이 맨 앞 2바이트(size)를 보고 **다 모였을 때만** 한 패킷을 꺼낸다(`NeedMore / Packet / Error`).
- 서버는 지금 단계(로그인 전·로비·방·게임)에서 허용되지 않은 패킷이 오면 연결을 끊는다. 클라이언트도 `UVHNetSubsystem::CanSend`에 같은 표를 두고 **보내기 전에 막는다**.

### ③ "판정"과 "반영"의 분리 — 나중에 서버 판정으로 바꾸기 쉬운 상호작용 구조
- 할 수 있는지·끝나면 무슨 일이 생기는지는 `UVHInteractionAuthority`(지금은 클라이언트 판정 `UVHLocalInteractionAuthority`)만 정하고, 화면·상태 반영은 `UVHInteractionSubsystem::Apply*` 함수로만 한다.
- 서버 판정이 생기면 Authority를 "요청 = 패킷 전송, 응답 패킷 = Apply* 호출"로 바꾸기만 하면 되고, 오브젝트·컴포넌트·HUD는 그대로다. 순수 규칙은 `VHRules`(`VHInteractionRules.*`)에 모아 **자동화 테스트**로 검사한다.

## 5. "1분 설명" 대본

> 저는 졸업작품 「털어라! 금고!」의 클라이언트를 언리얼 엔진 5와 C++로 만들었습니다. 의적 최대 3명이 5분 안에 저택 금고를 털어 보물을 반납하고 탈출하는 협동 게임입니다.
>
> 크게 두 부분입니다. 첫째, **메뉴부터 결과창까지의 네트워크 흐름**입니다. 서버는 팀원이 C++ IOCP로 만들고 있는데, 아직 게임 판정이 없어서 같은 프로토콜로 응답하는 **가짜 서버를 클라이언트 안에** 만들었습니다. 전송 계층을 인터페이스로 나눠서 설정 한 줄로 진짜 TCP 서버와 바꿀 수 있고, TCP에서 잘려 오는 패킷을 다시 맞추는 재조립과, 단계별로 허용된 패킷만 보내는 규칙을 넣었습니다.
>
> 둘째, **게임 플레이**입니다. 탑뷰에서 커서 방향을 바라보며 움직이고, 손전등 빛 안의 물건만 테두리가 생겨 상호작용할 수 있습니다. 금고·반납지점·탈출구·숨는 곳·창고·공격과 경직을 컴포넌트로 나눠 구현했고, 판정 코드와 반영 코드를 분리해 나중에 서버 판정으로 바꾸기 쉽게 했습니다. 수치는 모두 데이터 에셋에 있고, 규칙은 자동화 테스트 6개로 검증합니다.

## 6. "5분 설명" 대본

**(0:00) 게임 소개**
> 「털어라! 금고!」는 악당 카피바라 '바바라'의 저택에서 의적 최대 3명이 5분 안에 금고를 털어 탈출하는 PvE 협동 게임입니다. 경비는 서버 AI가 맡을 예정이고, 저는 클라이언트를, 팀원은 C++ IOCP 서버를 맡았습니다. 승패는 개인별로, 탈출한 사람이 승리입니다.

**(0:40) 전체 구조**
> 레벨이 두 개로 나뉩니다. 메뉴 레벨 `L_MainMenu`에서는 메뉴 전용 플레이어 컨트롤러 `AVHMenuPlayerController`가 메인화면·로그인·로비·대기실·결과창 위젯을 바꿔 끼웁니다. 서버 연결은 레벨이 바뀌어도 살아 있어야 해서 **게임 인스턴스 서브시스템** `UVHNetSubsystem`이 맡습니다. 서버가 게임 로드 패킷 `SC_GAME_LOAD`를 보내면 게임 레벨 `L_Mansion_1F`로 이동하고, 게임이 끝나면 다시 메뉴 레벨로 돌아와 결과창을 띄웁니다.

**(1:30) 네트워크**
> 패킷은 `[크기 2바이트][종류 2바이트][본문]` 형태의 고정 크기 구조체이고, 서버 팀원의 `protocol.h`를 그대로 복사해 이름 충돌을 피하려고 `RobProto` 네임스페이스로 감쌌습니다. TCP는 바이트 흐름이라 패킷이 잘려 올 수 있어서, 받은 바이트를 버퍼에 쌓고 크기만큼 모였을 때만 꺼내는 **재조립기**를 만들었습니다. 서버는 정해진 단계에서 허용되지 않은 패킷을 받으면 연결을 끊기 때문에 클라이언트도 같은 표로 보내기 전에 막고, 2초마다 PING을 보내 연결을 유지합니다. 서버가 아직 게임 판정을 못 해서 **같은 바이트 패킷으로 답하는 Mock 서버**를 만들었고, 전송 계층을 인터페이스로 분리해 설정 한 줄로 바꿀 수 있습니다. Mock은 일부러 패킷을 잘라 보내서 재조립 코드도 늘 시험됩니다.

**(2:40) 게임 플레이**
> 게임 레벨에서는 `AVHGamePlayerController`가 키 입력을 받아 캐릭터의 컴포넌트로 전달만 합니다. 캐릭터 클래스는 템플릿 그대로 두고 **기능을 컴포넌트 8개로 나눴습니다** — 시선, 행동(달리기·구르기·공격·스테미나), 상태이상, 상호작용, 보물 소지, 이동 소리, 의적 상태, 손전등. 진짜 캐릭터가 정해지면 컴포넌트만 붙이면 됩니다.
> 카메라는 탑뷰 고정이고, 캐릭터는 몸 전체가 마우스 커서를 바라보며 WASD는 그 방향 기준으로 움직입니다. 탑뷰에서 벽 뒤에 캐릭터가 가려지는 문제는, 카메라와 캐릭터 사이의 벽 픽셀만 지우는 재질로 해결했습니다.
> 상호작용은 손전등 빛 안에 있는 물건만 테두리가 생기고 대상이 됩니다. 금고는 30초 길게 누르기이고 떼도 진행도가 남습니다. 판정은 `Authority`, 반영은 서브시스템의 `Apply*` 함수로 나눠서 나중에 서버 판정으로 쉽게 바꿀 수 있게 했습니다. 한 판의 규칙 — 반납지점 5곳 유지와 60초 교체, 10,000$ 달성 시 탈출구 자동 열림, 5분 제한 — 은 월드 서브시스템 `UVHMatchSubsystem`이 관리합니다.

**(4:00) 데이터·검증·맵**
> 속도·시간·보물 가치 같은 숫자는 전부 데이터 에셋에 있어서 기획이 바뀌어도 코드를 고치지 않습니다. 순수 규칙은 자동화 테스트 6개로 검사하고, 기능마다 에디터에서 실제로 플레이해 로그와 화면으로 확인한 뒤 커밋했습니다. 맵은 모델러의 FBX를 가져와 방 33곳을 지역으로 나누고 금고 후보 10곳 등을 배치했으며, 새 맵이 오면 리임포트만으로 교체되게 구조를 잡았습니다.

**(4:35) 한계와 다음 단계**
> 아직 경비원 AI와 실서버 게임 판정 연동은 없습니다. 서버 팀원 저장소가 프로토콜 v2로 바뀌어서 다음 단계는 v2 반영과 판정을 서버 쪽으로 옮기는 것입니다. 개발은 Claude Code를 활용했고, 요구사항·설계 선택·검증 기준은 제가 정하고 단계마다 실행으로 확인했습니다.
