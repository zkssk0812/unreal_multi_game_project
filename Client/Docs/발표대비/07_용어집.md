# 07. 용어집 — 발표·답변에 나오는 말을 내 말로

> 읽는 법: 각 용어는 **쉬운 설명 → 정확한 정의 → 우리 프로젝트에서 어디에 → (수업 연결)** 순서.
> 파일 경로는 `Source/MCPTest/` 기준. 확실하지 않은 부분은 "확인 필요"로 표시했다.
> 수업 연결: [OS] = 운영체제, [AI] = 게임인공지능.

---

## A. 언리얼 엔진 기본

### 1. 액터 (Actor)
- 쉬운 설명: 레벨에 "놓을 수 있는 물건" 하나. 위치·회전이 있다.
- 정의: `AActor`를 상속한 클래스. 월드에 스폰되고, 컴포넌트를 담는 그릇.
- 우리 코드: 금고 `AVHSafe`, 숨는 곳 `AVHHideSpot`, 반납지점 `AVHReturnPoint`, 방 지역 `AVHRoomVolume`, 더미 경비원 `AVHDummyGuard` (모두 `Gameplay/`).

### 2. 컴포넌트 (Actor Component)
- 쉬운 설명: 액터에 붙이는 "기능 부품". 같은 부품을 여러 액터에 재사용한다.
- 정의: `UActorComponent`(위치가 없는 부품) / `USceneComponent`(위치가 있는 부품) 상속 클래스.
- 우리 코드: 의적 캐릭터 `BP_VHTestThief`에 붙은 `UVHInteractionComponent`(상호작용), `UVHActionComponent`(달리기·구르기·공격·스테미나), `UVHAimComponent`(커서 시선·이동 기준), `UVHStatusEffectComponent`(경직·면역), `UVHTreasureCarrierComponent`(보물 소지), `UVHMovementNoiseComponent`(소리), `UVHThiefStateComponent`(자유·숨음·잡힘·갇힘·탈출), `UVHFlashlightComponent`(손전등, `USpotLightComponent` 상속).
- 왜: 진짜 캐릭터가 정해지면 부품만 옮겨 붙이면 된다(캐릭터 클래스에 기능을 넣지 않음).

### 3. 폰 (Pawn) / 캐릭터 (Character)
- 쉬운 설명: 플레이어나 AI가 "조종하는" 액터. 캐릭터는 걷기·충돌 캡슐이 이미 들어 있는 폰.
- 정의: `APawn`, `ACharacter`(캡슐 + `UCharacterMovementComponent` + 스켈레탈 메시).
- 우리 코드: `AMCPTestCharacter`(템플릿 캐릭터, `MCPTestCharacter.cpp`의 `DoMove`에서 커서 기준 이동 계산을 부름), 더미 경비원 `AVHDummyGuard : ACharacter`.

### 4. 플레이어 컨트롤러 (Player Controller)
- 쉬운 설명: "사람의 손". 키·마우스 입력을 받아 폰에게 전달한다.
- 정의: `APlayerController`. 입력 처리, 화면(UI) 관리, 컨트롤 회전을 가진다.
- 우리 코드: 게임 레벨 `AVHGamePlayerController`(`Game/`) — 입력을 컴포넌트로 전달, 개발용 콘솔 명령(`UFUNCTION(Exec)` 25개), `UpdateRotation`에서 컨트롤 회전 = 커서 방향. 메뉴 레벨 `AVHMenuPlayerController` — 화면 전환.

### 5. 게임 모드 (Game Mode)
- 쉬운 설명: 그 레벨의 "규칙 설정표". 어떤 캐릭터·컨트롤러를 쓸지 정한다.
- 정의: `AGameModeBase`. 레벨의 월드 세팅에서 "게임 모드 오버라이드"로 지정.
- 우리 코드: `AVHMenuGameMode`(`Game/VHMenuGameMode.h`) + 블루프린트 `BP_VHMenuGameMode`(메뉴), 게임 레벨은 `BP_VHInteractionTestGameMode`(블루프린트). `BP_VHInteractionTestGameMode`의 C++ 부모는 템플릿 `AMCPTestGameMode`(에디터에서 MCP로 확인, `L_Mansion_1F`·`L_InteractionTest` 둘 다 이 게임 모드).

### 6. 레벨 (Level, Map)
- 쉬운 설명: 하나의 "장면" 파일(.umap).
- 우리 코드: `Content/VaultHeist/Maps/L_MainMenu`(메뉴), `Maps/Mansion/L_Mansion_1F`(저택, 기본 게임 레벨), `Maps/L_InteractionTest`(기능 테스트용).

### 7. 블루프린트 (Blueprint)
- 쉬운 설명: C++ 클래스를 "상속해서" 에디터에서 값·외형만 바꾼 자식 클래스.
- 정의: 비주얼 스크립트 클래스 에셋(.uasset). C++ 부모의 `UPROPERTY`를 디테일 패널에서 바꿀 수 있다.
- 우리 코드: `Content/VaultHeist/Blueprints/BP_VHSafe`, `BP_VHHideSpot`, `BP_VHTestThief` 등. 원칙(CLAUDE.md 6번): 로직은 C++, 조립·수치는 블루프린트.

### 8. UCLASS / UPROPERTY / UFUNCTION (리플렉션 매크로)
- 쉬운 설명: "엔진에게 이 클래스·변수·함수를 알려 주는 표시".
- 정의: 언리얼 헤더 툴(UHT)이 읽어 리플렉션 정보를 만든다. `UPROPERTY`는 에디터 노출·저장·가비지 컬렉션 추적, `UFUNCTION(Exec)`는 콘솔 명령, `UFUNCTION(BlueprintImplementableEvent)`는 블루프린트에서 구현.
- 우리 코드: `AVHInteractableBase::OnVisualStateChanged`(BlueprintImplementableEvent), `AVHGamePlayerController::VHGoto`(Exec).
- 주의: `UPROPERTY`를 추가·삭제하면 헤더가 바뀌어 **Live Coding으로 안 되고 에디터를 닫고 빌드**해야 한다.

### 9. 가비지 컬렉션 (GC) 과 `UPROPERTY` 포인터
- 쉬운 설명: 언리얼이 "아무도 안 쓰는 UObject"를 자동으로 지운다. 그런데 `UPROPERTY`가 없는 맨 포인터는 엔진이 "쓰는 중"인지 모른다.
- 정의: 마크-스윕 방식 GC. `UPROPERTY() TObjectPtr<T>`로 잡아 둔 객체는 살아 있다고 표시된다.
- 우리 코드: `AVHInteractableBase`의 `UPROPERTY TObjectPtr<UStaticMeshComponent> Body`, `UVHGameHUDWidget`의 위젯 포인터들 (`UPROPERTY() TObjectPtr<UTextBlock> ...`).
- [OS] 메모리 관리 — 참조 추적(reachability)으로 해제 시점을 정하는 자동 메모리 관리. C++의 `new/delete` 수동 관리와 비교해서 설명할 수 있다.

### 10. 약한 포인터 `TWeakObjectPtr`
- 쉬운 설명: "가리키긴 하지만 살려 두지는 않는" 포인터. 대상이 지워지면 자동으로 null이 된다.
- 우리 코드: `AVHInteractableBase::ActiveUser`(지금 쓰는 의적), `UVHLocalInteractionAuthority::FSession`의 `By`·`Target`.
- [OS] 매달린 포인터(dangling pointer) 방지 — 이미 해제된 메모리를 가리키는 문제를 막는다.

### 11. 서브시스템 (Subsystem)
- 쉬운 설명: 엔진이 알아서 만들고 지워 주는 "관리자 객체". 수명 범위가 정해져 있다.
- 정의: `UGameInstanceSubsystem`(게임 실행 동안 1개, 레벨이 바뀌어도 유지), `UWorldSubsystem`(레벨마다 새로 생김).
- 우리 코드:
  - `UVHNetSubsystem : UGameInstanceSubsystem` (`Network/VHNetSubsystem.h`) — 연결·단계·방 상태. 메뉴 ↔ 게임 레벨을 오가도 연결이 유지되어야 하므로 GameInstance 범위.
  - `UVHInteractionSubsystem : UTickableWorldSubsystem`, `UVHMatchSubsystem : UTickableWorldSubsystem` (`Gameplay/`) — 그 레벨의 오브젝트 등록부·게임 규칙. 레벨이 바뀌면 새로 시작.
- [OS] 객체 수명(lifetime)과 범위(scope) — "프로세스 동안 사는 것 vs 한 장면 동안 사는 것".

### 12. 데이터 에셋 (Data Asset)
- 쉬운 설명: 숫자·문구만 모아 둔 "설정 파일" 에셋. 코드를 다시 빌드하지 않고 값을 바꾼다.
- 정의: `UPrimaryDataAsset` 상속 클래스의 인스턴스(.uasset).
- 우리 코드: `UVHGameplayConfig` → `Content/VaultHeist/Data/DA_VHGameplayConfig`(속도·스테미나·공격·보물 표·반납지점·제한 시간·카메라·커서), `UVHInteractionConfig` → `DA_VHInteractionConfig`(상호작용 시간·소리·손전등), `UVHUIStyle` → `DA_VHUIStyle`(UI 색·글자), `UVHGameData` → `DA_VHGameData`(캐릭터·퍽 임시 목록).

### 13. 개발자 설정 (Developer Settings)
- 쉬운 설명: 프로젝트 세팅 창에 나오는 우리 프로젝트 전용 설정.
- 정의: `UDeveloperSettings` + `Config = Game` → `Config/DefaultGame.ini`에 저장.
- 우리 코드: `UVHSettings`(`Network/VHSettings.h`) — 에디터 **편집 → 프로젝트 세팅 → 게임 → "털어라 금고"**. `bUseMockServer`, `ServerHost`, `ServerPort`, `bMockSplitPackets`, `GameLevel`(지금 `L_Mansion_1F`), 데이터 에셋 경로.

### 14. Enhanced Input (입력 액션 / 입력 매핑 컨텍스트)
- 쉬운 설명: "키"와 "동작"을 분리하는 입력 시스템. 키를 바꿔도 코드는 그대로.
- 정의: `UInputAction`(IA, 동작 하나) + `UInputMappingContext`(IMC, 키 ↔ 동작 표). 코드에서 `BindAction(액션, ETriggerEvent::Started/Triggered/Completed, ...)`.
- 우리 코드: `Content/VaultHeist/Input/IMC_VHGameplay` + `IA_VHInteract`(우클릭·G), `IA_VHSprint`(Shift), `IA_VHFlashlight`(R), `IA_VHRoll`(Space), `IA_VHAttack`(좌클릭). 바인딩은 `AVHGamePlayerController::SetupInputComponent`. 이동(`IA_Move`)은 템플릿 `IMC_Default`.

### 15. UMG 위젯 / 위젯 블루프린트 (WBP)
- 쉬운 설명: 언리얼의 UI 화면 제작 도구.
- 정의: `UUserWidget` 상속 클래스 + 디자이너에서 배치한 위젯 블루프린트.
- 우리 코드: `Content/VaultHeist/UI/WBP_MainMenu`, `WBP_Login`, `WBP_Lobby`, `WBP_Room`, `WBP_Result` — 부모는 C++ `UVHMainMenuWidget` 등(`UI/`, 공통 부모 `UVHScreenWidget`).

### 16. BindWidget
- 쉬운 설명: "블루프린트에 같은 이름의 위젯이 있으면 C++ 변수에 자동 연결"하는 표시.
- 정의: `UPROPERTY(meta = (BindWidget))` — 이름이 다르면 컴파일 오류, `BindWidgetOptional`이면 없어도 됨.
- 우리 코드: `UI/VHLobbyWidget.h`의 `UserNameText`, `StatsText`, `SearchTextBox`, `RoomCountText`(Optional).

### 17. 코드로 만드는 위젯 (Code Widget)
- 쉬운 설명: 블루프린트 없이 C++에서 위젯 트리를 직접 짜는 방식.
- 우리 코드: `UVHCodeWidget`(`UI/VHCodeWidgets.h`)과 자식들(토스트, 방 목록 한 줄, 결과 카드), 게임 HUD `UVHGameHUDWidget`(`BuildTree()`에서 생성). 디자인이 정해지면 블루프린트로 바꿀 수 있게 정보만 쓴다.

### 18. 머티리얼 / 포스트 프로세스 / 커스텀 스텐실
- 쉬운 설명: 머티리얼 = 표면 색 계산식, 포스트 프로세스 = 다 그린 화면 위에 한 번 더 칠하는 효과, 스텐실 = 물체마다 붙이는 번호표.
- 우리 코드: 테두리 `M_VHOutline`(스텐실 1 빛 안 / 2 대상 / 3 불가 경계에만 색), `AVHInteractableBase::SetOutline`. 설정 `r.CustomDepth=3`(`Config/DefaultEngine.ini`).

### 19. 재질 파라미터 모음 (MPC, Material Parameter Collection)
- 쉬운 설명: 모든 머티리얼이 같이 읽는 "공용 칠판". C++이 매 프레임 값을 쓴다.
- 우리 코드: `MPC_VHOcclusion`(PlayerPos·Radius·Enabled) ← `UVHAimComponent::UpdateOcclusion`. 벽 재질 `M_VHWallFade`가 읽어 카메라와 캐릭터 사이 벽을 원 모양으로 지운다.

### 20. 스태틱 메시 / 충돌(콜리전) / 복합 충돌을 단순으로
- 쉬운 설명: 스태틱 메시 = 움직이지 않는 3D 모델. 충돌 = 부딪힘 판정 모양.
- 정의: 단순 충돌(박스·볼록 껍질) vs 복합 충돌(삼각형 그대로). "Use Complex Collision As Simple"은 보이는 모양 그대로를 충돌로 쓴다.
- 우리 코드: `Content/VaultHeist/Maps/Mansion/SM_Mansion_1F` — 사용자 결정 (가)로 복합 충돌 사용.

### 21. 내비게이션 메시 (NavMesh)
- 쉬운 설명: AI가 "걸어갈 수 있는 바닥"을 미리 계산해 둔 지도.
- 정의: Recast로 만드는 다각형 그래프. `NavMeshBoundsVolume` 범위 안에 생성, `RecastNavMesh` 액터에 저장. 에디터 뷰포트에서 `P` 키로 표시.
- 우리 코드: `L_Mansion_1F`의 `NavMeshBounds_Mansion`(아웃라이너 Map 폴더). 아직 경비원 AI가 없어 길찾기에는 안 쓰는 중.
- [AI] 경로 탐색(A*) — 내비 메시의 다각형을 노드로 A* 탐색을 한다. 격자(grid) 대신 다각형 그래프를 쓰는 이유(노드 수 감소)를 연결해 설명할 수 있다.

### 22. 행동 트리 (Behavior Tree)
- 쉬운 설명: AI가 "무엇을 할지" 고르는 나무 모양 규칙표.
- 우리 코드: **아직 없음**(더미 경비원은 움직이지 않음). 다음 단계에서 순찰·소리 듣고 이동·추격을 만들 때 후보.
- [AI] 기획 PDF 8-1장 "소리가 난 위치로 걸어가고, 이동 중 다른 소리를 들으면 마지막 소리 위치로" = 상태 머신(순찰 → 조사 → 추격)이나 행동 트리로 구현할 수 있다. 소리 정보는 이미 `UVHInteractionSubsystem::ReportNoise` / `OnNoise` 델리게이트로 나온다.

### 23. PIE (Play In Editor)
- 쉬운 설명: 에디터 안에서 바로 실행해 보는 것(툴바 ▶).
- 주의: PIE 월드는 에디터 월드의 복사본이다(이름 앞에 `UEDPIE_0_`). PIE 중 바꾼 값은 끄면 사라진다.

### 24. 핫 리로드 / Live Coding
- 쉬운 설명: 에디터를 켠 채로 `.cpp`만 고쳐 다시 컴파일해 넣는 것.
- 우리 경험: `.cpp`만 바뀌면 Live Coding(`Ctrl+Alt+F11` 또는 콘솔 `LiveCoding.Compile`), 헤더·`UPROPERTY` 구조가 바뀌면 에디터를 닫고 `Build.bat`로 빌드.

### 25. 자동화 테스트 (Automation Test)
- 쉬운 설명: 사람이 안 눌러 봐도 코드가 규칙대로 계산하는지 자동으로 검사하는 코드.
- 정의: `IMPLEMENT_SIMPLE_AUTOMATION_TEST` + `RunTest`. 에디터 **창 → 테스트 자동화**(Session Frontend)에서 실행.
- 우리 코드: `Gameplay/Tests/VHInteractionTests.cpp`(`VaultHeist.Interaction.HoldProgress`, `CarryRules`, `AuthorityFlow`, `AimMove`), `Network/Tests/VHNetTests.cpp`(`VaultHeist.Net.PacketAssembler`, `MockServerFlow`). 총 6개.

### 26. 로그 카테고리 / 출력 로그 / Verbose
- 쉬운 설명: 로그를 종류별로 나눈 이름표. Verbose는 평소에 숨겨진 자세한 로그.
- 우리 코드: `LogMCPTest`(게임플레이, `MCPTest.h`), `LogVHNet`(네트워크, `VHNetSubsystem.cpp`), `LogVHMock`(가짜 서버), `LogVHTcp`, `LogVHMenu`. 이동 확인 로그 `[Move]`는 Verbose → 콘솔에 `Log LogMCPTest Verbose`를 입력해야 보인다. 에디터 **창 → 출력 로그**.

### 27. 콘솔 명령 (Exec)
- 우리 코드: `AVHGamePlayerController`의 `VHHelp`, `VHGoto`, `VHFastInteract`, `VHSetTime` 등 25개. 플레이 중 `~` 키 또는 에디터 아래 `Cmd` 칸.

### 28. SaveGame
- 쉬운 설명: 디스크에 작은 값을 저장하는 기능.
- 우리 코드: `UVHLocalSaveGame`(`Game/VHLocalSaveGame.h`) — 마지막 로그인 이름 기억(`UVHNetSubsystem::SaveLastLoginName`).

### 29. 델리게이트 (Delegate) / 이벤트
- 쉬운 설명: "일이 생기면 알려 줄게" 구독 목록. 보내는 쪽은 누가 듣는지 몰라도 된다.
- 정의: `DECLARE_MULTICAST_DELEGATE...` → `Broadcast()`로 알림, `AddUObject/AddLambda`로 구독.
- 우리 코드: `UVHInteractionSubsystem`의 `FVHOnNoise`, `FVHOnWorldMessage`, `FVHOnTeamTreasureChanged`; `UVHInteractionComponent::OnMessage`; `UVHNetSubsystem::OnStatusMessage` 등 → UI가 구독해서 화면을 갱신.
- [OS] 관찰자 패턴 / 콜백 — 인터럽트 핸들러 등록처럼 "이벤트 발생 시 등록된 함수 호출".

### 30. 틱 (Tick) / 틱 그룹
- 쉬운 설명: 매 프레임 한 번씩 불리는 함수.
- 우리 코드: `UVHAimComponent`는 `TG_PostPhysics`(이동이 끝난 뒤 시선 갱신), `UVHNetSubsystem::Tick`(전송 계층 Tick → 핑·타임아웃 검사), 월드 서브시스템은 `UTickableWorldSubsystem::Tick`.
- [OS] 게임 루프 = 고정된 순서로 반복되는 스케줄러 한 바퀴.

### 31. 컨트롤 회전 (Control Rotation)
- 쉬운 설명: 컨트롤러가 "바라보라고 하는 방향".
- 우리 코드: `AVHGamePlayerController::UpdateRotation`에서 커서 방향(`UVHAimComponent::GetAimYaw`)으로 설정 → `UCharacterMovementComponent`의 `bUseControllerDesiredRotation`이 몸을 그 방향으로 `RotationRate`(=Body Turn Speed 1800°/s) 속도로 돌린다.

### 32. 스프링 암 / 카메라 랙
- 쉬운 설명: 카메라를 캐릭터에서 일정 거리 떨어뜨려 잡는 "막대". 랙은 카메라가 부드럽게 늦게 따라오는 것.
- 우리 코드: `UVHAimComponent::ApplyTopDownCamera` — 절대 회전(피치 -65°), 거리 1500, 충돌 검사 끔, `CameraLagSpeed` 10.

### 33. 디프로젝션 (Deproject)
- 쉬운 설명: 화면의 점(마우스)을 3D 세상으로 쏘는 선으로 바꾸는 것.
- 우리 코드: `UVHAimComponent::TraceMouseToFloor` — `DeprojectMousePositionToWorld` 후 캐릭터 발 높이 평면과 만나는 점.

## B. 네트워크

### 34. 소켓 (Socket)
- 쉬운 설명: 프로그램끼리 데이터를 주고받는 "전화기".
- 정의: OS가 제공하는 통신 끝점. 우리는 언리얼의 `FSocket`(TCP)을 쓴다.
- 우리 코드: `FVHTcpTransport`(`Network/VHTcpTransport.h/.cpp`) — **논블로킹 소켓을 게임 스레드 Tick에서 폴링**(별도 수신 스레드 없음).
- [OS] 소켓 API(socket/connect/send/recv), 블로킹 vs 논블로킹 I/O.

### 35. TCP
- 쉬운 설명: 순서가 보장되고 빠짐없이 도착하는 연결형 통신. 대신 "메시지 경계"가 없다.
- 우리 코드: 서버 포트 9000(`UVHSettings::ServerPort`).
- 핵심: 보낸 패킷 두 개가 한 번에 붙어서 오거나, 하나가 반으로 잘려서 올 수 있다 → **스트림 재조립** 필요.

### 36. 스트림 재조립 (Stream Reassembly)
- 쉬운 설명: 조각나 도착한 바이트를 모아 "완성된 패킷" 단위로 다시 자르는 것.
- 우리 코드: `FVHPacketAssembler`(`Network/VHPacket.h/.cpp`) — `Append`로 받은 바이트를 버퍼에 쌓고, `Pop`이 앞 2바이트(size)를 읽어 그만큼 모였으면 `Packet`, 모자라면 `NeedMore`, size가 4 미만·8192 초과면 `Error`. 호출은 `UVHNetSubsystem::OnBytes`.
- 시험: `VaultHeist.Net.PacketAssembler`(1바이트씩 넣어도 같은 결과), Mock 설정 `bMockSplitPackets`(일부러 1~97바이트로 쪼개 보냄).
- [OS] 생산자-소비자 버퍼, 링 버퍼 개념과 연결.

### 37. 패킷 / 헤더 / 리틀 엔디언
- 쉬운 설명: 패킷 = 한 덩어리 메시지. 헤더 = 맨 앞의 "크기와 종류" 정보.
- 정의: `[size:uint16][type:uint16][body]`, 리틀 엔디언(작은 자리 바이트가 먼저), size는 헤더 포함 전체.
- 우리 코드: `Network/Protocol/protocol.h`(서버 팀원 원본 사본, v1.0), 래퍼 `Network/VHProtocol.h`(`namespace RobProto`), 조립·해석 `VHPacket::Make/ToBytes/ReadFixed/ReadVariable`.

### 38. `#pragma pack(1)` / memcpy 직렬화
- 쉬운 설명: 구조체 사이 빈칸(패딩)을 없애 서버·클라이언트가 같은 바이트 배치를 갖게 하는 것.
- 우리 코드: `protocol.h`의 구조체를 그대로 `memcpy`(`VHPacket::ReadFixed`)로 읽는다.
- 주의: 양쪽 컴파일러·엔디언이 같아야 한다(둘 다 x64 Windows).

### 39. 가변 길이 패킷
- 쉬운 설명: 배열이 마지막에 붙어 길이가 달라지는 패킷(예: 방 목록).
- 우리 코드: `SC_RoomList` → `VHPacket::ReadVariable` + `SC_RoomList_Size(count)`로 크기 검증.

### 40. 연결 단계 (Phase) — 상태 머신
- 쉬운 설명: 지금 "로그인 전인지, 로비인지, 방 안인지, 게임 중인지".
- 우리 코드: `EVHNetPhase`(`Network/VHNetTypes.h`): Disconnected → Connecting → Anonymous → Authenticating → Lobby → Room → Game. `UVHNetSubsystem::SetPhase`, 단계별 허용 패킷은 `UVHNetSubsystem::CanSend`(허용 안 되면 보내지 않고 경고 로그).
- 이유: 서버는 허용되지 않은 패킷을 받으면 연결을 끊는다(CLAUDE.md).
- [AI][OS] 유한 상태 기계(FSM) — 상태와 전이 조건이 명확한 예.

### 41. 하트비트 (Heartbeat) / 핑·퐁
- 쉬운 설명: "나 살아 있어" 신호를 주기적으로 보내는 것.
- 우리 코드: `UVHNetSubsystem::Tick` → `SendPing`(`PING_INTERVAL_MS` 마다 `CS_PING`), `HandlePong`에서 RTT·서버 시각. 15초(`ReceiveTimeoutSeconds`) 동안 아무것도 못 받으면 끊긴 것으로 처리.

### 42. 요청 속도 제한 (Rate Limit)
- 우리 코드: `UVHNetSubsystem::PassRateLimit` — 최근 1초 요청 수가 `RequestLimitPerSecond`(**8회**, 서버 제한 초당 10회보다 조금 낮게)에 닿으면 보내지 않고 "요청이 너무 잦습니다. 잠시 후 다시 시도해 주세요." 안내.
- [OS] 슬라이딩 윈도 방식 속도 제한(최근 1초 안의 요청 시각 목록을 유지).

### 43. 전송 계층 추상화 (Transport) / 인터페이스
- 쉬운 설명: "어떻게 보내는지"를 갈아 끼울 수 있게 겉모양만 정해 둔 것.
- 우리 코드: `IVHTransport`(`Network/VHTransport.h`: `Connect/Disconnect/Send/Tick/IsConnected`) ← `FVHTcpTransport`(진짜 서버), `FVHMockTransport`(가짜 서버). 어떤 걸 쓸지는 `UVHSettings::bUseMockServer`.
- 객체지향: 다형성(가상 함수), 의존성 역전.

### 44. Mock 서버 (가짜 서버)
- 쉬운 설명: 서버가 아직 없어서, 클라이언트 안에 넣은 "서버 흉내".
- 우리 코드: `FVHMockServer`(`Network/VHMockServer.h/.cpp`) — 같은 바이트 패킷을 받고 프로토콜대로 응답. 가짜 방 5개(생성자 `AddRoom`), 가짜 플레이어 준비, 게임 끝은 클라이언트 보고(`ClientReportsMatchEnd`)로 결과 생성.

### 45. 직렬화 문자열 (UTF-8, 고정 길이, 널 종료)
- 우리 코드: `VHPacket::WriteString/ReadString` — 이름 48바이트, 방 이름 60바이트 배열에 UTF-8로 넣고 끝에 `\0`.

### 46. 서버 권한 (Server Authority) / 판정
- 쉬운 설명: "누가 이겼는지, 금고가 열렸는지"는 서버가 정해야 한다(해킹·불일치 방지).
- 우리 코드: 지금은 `UVHLocalInteractionAuthority`가 클라이언트에서 판정하지만, 판정을 `UVHInteractionAuthority` 한곳에 모아 서버 판정 클래스로 바꾸기 쉽게 했다.

### 47. IOCP
- 쉬운 설명: 윈도우의 대량 비동기 소켓 처리 방식(서버 팀원 서버).
- 정의: I/O Completion Port — 완료된 입출력을 큐에 넣고 스레드 풀이 처리.
- 우리 코드: 클라이언트에는 없음. 서버 참고 사본 `Docs/ServerRef/Project_Rob-master/ServerCore`(참고 전용).
- [OS] 비동기 I/O, 스레드 풀, 완료 큐.

### 48. 프로토콜 버전
- 우리 코드: 클라이언트 `protocol.h`는 **v1.0** (`PROTOCOL_VERSION = (1u << 16) | 0u`). 서버 팀원 저장소는 2026-10-26 기준 **v2.0**으로 바뀜(`Shared/Protocol/protocol.h`) → 버전이 다르면 서버가 VersionMismatch로 거절. 옮기는 작업은 아직 안 함.

## C. C++ / 프로그래밍

### 49. 클래스 상속 / 가상 함수 / 오버라이드
- 우리 코드: `AVHSafe : AVHInteractableBase`, `virtual FBox GetInteractBounds()`, `virtual void SetOutline(...)` (`AVHDroppedTreasure`가 오버라이드).

### 50. 추상 클래스 (Abstract)
- 우리 코드: `UCLASS(Abstract)` — `AVHInteractableBase`, `UVHInteractionAuthority`는 직접 만들지 않고 자식만 쓴다.

### 51. enum class (열거형)
- 우리 코드: `EVHEntityKind`(Safe, ExitGate, HideSpot, DroppedTreasure, JailPoint, ReturnPoint …) — `protocol.h`의 `EntityKind`와 **같은 순서**로 맞춤(ReturnPoint만 클라이언트 전용).

### 52. 구조체 (struct) / USTRUCT
- 우리 코드: `FVHInteractOffer`(대상이 지금 제공하는 상호작용: 모드·시간·진행도 유지·문구·막힘 이유), `FVHItemData`(보물 이름·무게·가치), `FVHCharacterStats`.

### 53. 람다 (lambda)
- 우리 코드: `UVHNetSubsystem::HandlePacket`의 `auto Bad = [Id, Size]() {...}`, `FVHMockServer` 생성자의 `auto AddRoom = [...]`.
- 주의: 람다가 지역 변수를 **참조로** 잡고(`[&]`) 나중에 실행되면, 그 변수는 이미 사라졌을 수 있다(매달린 참조).

### 54. 스택 vs 힙 / 수명
- 쉬운 설명: 스택 = 함수가 끝나면 사라지는 지역 변수 자리, 힙 = 직접 지울 때까지(또는 GC가 지울 때까지) 남는 자리.
- [OS] 프로세스 메모리 구조(스택·힙·코드·데이터). 03_문제해결 문서의 "지역 변수 수명" 사례와 연결.

### 55. 스마트 포인터 `TUniquePtr`
- 우리 코드: `UVHNetSubsystem`이 전송 계층을 `TUniquePtr<IVHTransport>`로 소유(`Transport = MakeUnique<FVHMockTransport>(...)`), Mock 서버도 `MakeUnique<FVHMockServer>`. 소유자가 사라지면 자동 해제.
- 참고: `UVHNetSubsystem::DestroyTransport`가 전송 객체를 바로 지우지 않고 `TransportToDestroy`로 옮겨 두었다가 다음 `Tick`에서 `Reset()` — 헤더 주석 "콜백 도중 파괴하지 않도록 다음 Tick에 정리". 전송 객체의 함수가 실행되는 도중에 그 객체를 지우면 이미 해제된 메모리에서 코드가 계속 도는 문제(use-after-free)가 생기기 때문.

### 56. `static_cast` / `reinterpret_cast`
- 우리 코드: `HandlePacket`에서 `reinterpret_cast<const PacketHeader*>(Data)->type`로 바이트 앞부분을 헤더로 읽음.

### 57. 상수 표현식 `constexpr`
- 우리 코드: `ReceiveTimeoutSeconds = 15.0`(`VHNetSubsystem.cpp`), `MAX_PACKET_SIZE = 8192`(`protocol.h`).

### 58. 네임스페이스
- 우리 코드: `namespace RobProto { #include "protocol.h" }`(`VHProtocol.h`) — 서버 구조체 이름이 언리얼 이름과 충돌하지 않게. `namespace VHRules`(순수 규칙 함수).

### 59. 순수 함수 (Pure Function)
- 쉬운 설명: 같은 입력이면 항상 같은 출력, 바깥 상태를 안 바꾸는 함수 → 테스트하기 쉽다.
- 우리 코드: `VHRules::CheckPickup`, `NoiseRadius`, `SpeedMultiplier`, `IsInAttackFan`, `AimRelativeMove`, `AimYawToPoint`(`Gameplay/VHInteractionRules.h`).

### 60. Build.cs / 모듈
- 우리 코드: `Source/MCPTest/MCPTest.Build.cs` — `PublicDependencyModuleNames`: Core, CoreUObject, Engine, InputCore, EnhancedInput, AIModule, StateTreeModule, GameplayStateTreeModule, UMG, Slate, SlateCore, DeveloperSettings, Sockets, Networking. (AIModule·StateTree는 템플릿에서 온 것으로 아직 우리 기능에서는 안 씀 — 확인 필요)

## D. 게임 시스템 (우리 게임 고유)

### 61. 판정 담당 (Authority) / 반영 입구 (Apply*)
- 쉬운 설명: "할 수 있나·끝나면 뭐가 되나"를 정하는 곳 하나 + "화면·상태에 반영"하는 입구 하나.
- 우리 코드: `UVHInteractionAuthority`(인터페이스) → `UVHLocalInteractionAuthority::Evaluate / BuildOffer / RequestBegin / RequestCancel / ResolveComplete`. 반영은 `UVHInteractionSubsystem::ApplyInteract / ApplySafeOpened / ApplyTreasureReturned / ApplyStun ...`.
- 서버가 판정하면: `RequestBegin` → `CS_ACTION` 전송, 받은 `SC_` 패킷 → 같은 `Apply*` 호출.

### 62. 상호작용 상태 (Begin / Cancel / Complete)
- 우리 코드: `EVHInteractState`(`VHInteractionTypes.h`) — 로그 `[Interact] A → B : EVHInteractState::Begin (남은초 / 전체초)`.
- [AI] 작은 상태 머신.

### 63. 길게 누르기 (Hold) / 짧게 누르기 (Tap)
- 우리 코드: `EVHInteractMode`. Hold는 떼거나 이동·Space·좌클릭 입력이면 취소(`UVHInteractionComponent::InteractReleased`, `NotifyMoveInput`, `NotifyActionInput`).

### 64. 진행도 비율 저장 (`FVHHoldProgress`)
- 쉬운 설명: "10초 남음"이 아니라 "1/3 진행"으로 저장 → 시간 설정이 바뀌어도 자연스럽고, 서버의 "시작 시각+남은 시간"으로 복원 가능.
- 우리 코드: `FVHHoldProgress::Begin / BeginWithRemaining / Cancel(Now, bKeep) / GetProgress / IsComplete`, 시험 `VaultHeist.Interaction.HoldProgress`.

### 65. 의적 상태 (Free / Hidden / Captured / Jailed / Escaped)
- 우리 코드: `EVHThiefStatus`(`VHInteractionTypes.h`), `UVHThiefStateComponent::IsFree`. 프로토콜의 `ES_HIDDEN` 등과 대응.
- [AI] 상태 머신 — 상태마다 할 수 있는 행동이 다르다(숨음이면 이동 불가, 나오기만 가능).

### 66. 데드존 (Dead Zone)
- 쉬운 설명: 너무 작은 입력은 무시하는 구역.
- 우리 코드: 커서가 캐릭터 1m(`AimDeadZone` 100cm) 안이면 마지막 방향 유지 — `VHRules::AimYawToPoint`.

### 67. 소리 신호 (Noise Event)
- 우리 코드: `FVHNoiseEvent`, `UVHMovementNoiseComponent`가 걷기 0.5초·달리기 0.2초·구르기 매 프레임마다 `UVHInteractionSubsystem::ReportNoise` → `OnNoise` 델리게이트. 반경 = (동작 반경 + 2m × 보물 수) × 1.1 (`VHRules::NoiseRadius`).
- [AI] 감각 시스템(청각 자극) — AI 인지(Perception)의 입력.

### 68. 반납지점 / 방 지역
- 우리 코드: `AVHReturnPoint`, `AVHRoomVolume`(박스 `Area`, `RoomName`, `bAllowReturnPoint`, `FindRandomFloorPoint`), 관리 `UVHMatchSubsystem`(방마다 최대 1개, 항상 5곳, 50초 빨강·60초 교체).

### 69. 경직·면역·무적·탈진
- 우리 코드: `UVHStatusEffectComponent`(경직 3초 + 면역 10초, 구르는 중 무적), `UVHActionComponent::SetExhausted`(스테미나 0 → 탈진, 회복 50%, 100에서 해제).

- 쉬운 설명: AI가 에디터 기능(레벨 불러오기, 액터 놓기, PIE 시작, 로그 읽기, 화면 캡처)을 도구처럼 쓰게 하는 연결 통로.
- 우리 환경: 엔진 내장 Unreal MCP, `http://127.0.0.1:8000/mcp`(CLAUDE.md). 에디터가 켜져 있어야 한다.

### 72. FBX / 리임포트
- 우리 코드: 원본 `Art/Map/Mansion_1F_Blockout.fbx`(LFS) → `SM_Mansion_1F`. 맵이 바뀌면 스태틱 메시 에디터의 **[메시 리임포트]**(`Docs/맵_교체_가이드.md`).
