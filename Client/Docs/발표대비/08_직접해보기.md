# 08. 직접 해 보기 — 내가 진짜 이해했는지 확인하는 실습 12개

> 쉬운 것(값만 바꾸기)부터 어려운 것(새 오브젝트 만들기) 순서.
> 각 실습: **목적 → 방법 → 정답 확인 → 되돌리기 → 이걸로 답할 수 있게 되는 질문**.
> 에디터 메뉴는 한국어 UI 이름. 파일 경로는 프로젝트 폴더(`C:\UnrealProjects\MCPTest`) 기준.

## 시작 전에 꼭 알아 둘 것
- **실습 전에 Git 상태를 깨끗하게**: 터미널에서 `git status` → 바뀐 파일이 없을 때 시작하면 되돌리기가 쉽다.
- **에셋(.uasset)은 텍스트로 고치지 않는다.** 데이터 에셋 값은 에디터에서 더블클릭해 바꾼다.
- **되돌리기 공통**:
  - 코드·설정 파일: `git checkout -- 파일경로` (예: `git checkout -- Source/MCPTest/Network/VHMockServer.cpp`)
  - 데이터 에셋: 에디터에서 원래 값으로 다시 입력하고 저장. 또는 저장 전이면 저장하지 않고 닫기. 저장해 버렸다면 에디터를 끈 뒤 `git checkout -- Content/VaultHeist/Data/DA_VHInteractionConfig.uasset`
- **코드를 고친 뒤 반영**:
  - `.cpp`만 고쳤으면 에디터를 켠 채 **Live Coding**: 에디터에서 `Ctrl + Alt + F11`, 또는 콘솔(`~` 또는 에디터 아래 `Cmd` 칸)에 `LiveCoding.Compile`
  - `.h`(헤더)를 고쳤거나 새 파일을 만들었으면: **에디터를 닫고** 빌드한 뒤 다시 연다.
    ```
    "C:\Users\FORYOUCOM\Desktop\UE_5.8\Engine\Build\BatchFiles\Build.bat" MCPTestEditor Win64 Development -Project="C:\UnrealProjects\MCPTest\MCPTest.uproject" -WaitMutex
    ```
- **출력 로그 보기**: 에디터 **창 → 출력 로그**. 위쪽 검색칸에 `[Interact]`, `LogVHNet` 같은 글자를 넣어 거른다.
- **콘솔 명령**: 플레이 중 `~` 키(숫자 1 왼쪽) → 입력 → Enter. `VHHelp`로 개발용 명령 목록.

## 실습 1. 금고 여는 시간 바꾸기 (★ 쉬움, 5분)
**목적**: "숫자를 데이터 에셋으로 분리했다"를 몸으로 확인.

**방법**
1. 에디터 아래 **콘텐츠 드로어**(`Ctrl + Space`) → `콘텐츠 → VaultHeist → Data` → **DA_VHInteractionConfig** 더블클릭.
2. 디테일 패널에서 **Safe** 분류의 **Safe Open Seconds** 를 `30` → `5` 로 바꾸고 **저장**(`Ctrl + S`).
3. `콘텐츠 → VaultHeist → Maps → L_InteractionTest` 열기 → ▶ 플레이.
4. 콘솔 `VHGoto Safe_1` (그 판에 Safe_1이 등장하지 않았으면 출력 로그의 `[Treasure] Safe_x ←` 줄을 보고 등장한 번호로).
5. `R`로 손전등 켜기 → **마우스 커서를 금고 쪽에** 두기 → 우클릭(또는 G)을 누르고 있기.

**정답 확인**
- 화면 안내가 `[우클릭/G] 길게 눌러 금고 열기 (5초)`.
- 출력 로그: `[Interact] BP_VHTestThief_C_0 → BP_VHSafe_C_0 : EVHInteractState::Begin (5.00s / 전체 5.00s)` 그리고 5초 뒤 `... : EVHInteractState::Complete`.
- 화면 알림 `금고가 열렸습니다! 보물을 챙기세요`.

**되돌리기**: Safe Open Seconds를 `30`으로 되돌리고 저장.

**설명할 수 있게 되는 질문**
- "금고 시간을 바꾸려면 어디를 고치나요?" → `DA_VHInteractionConfig`의 Safe Open Seconds. 코드에서는 `UVHInteractionConfig::SafeOpenSeconds`를 `UVHLocalInteractionAuthority::BuildOffer`의 `case EVHEntityKind::Safe`가 읽는다.
- "왜 코드에 30을 직접 안 썼나요?" → 기획자가 빌드 없이 값을 바꾸게, 그리고 나중에 서버 값과 맞추기 쉽게.

**방법**

## 실습 5. Verbose 로그 켜서 `[Move]` 보기 (★★ 보통, 10분)
**목적**: 커서 각도·몸 각도·이동 방향이 실제로 어떻게 계산되는지 숫자로 보기.

**방법**
1. 플레이 → 콘솔에 `Log LogMCPTest Verbose`.
2. 커서를 화면 오른쪽에 두고 `W`, 그다음 `D`를 눌러 본다.
3. **출력 로그** 검색칸에 `[Move]`.

**정답 확인** (예시)
```
[Move] W/S 1 A/D 0 | 커서 88° 몸 88° | 이동 방향 (0.04, 1.00) | 위치 (-2864, -4759)
```
- 커서가 오른쪽이면 약 90°(언리얼은 화면 위 = +X = 0°, 오른쪽 = +Y = 90°).
- W → 이동 방향 (0, 1) = 오른쪽. D → (-1, 0) = 화면 아래(커서를 바라본 상태의 오른쪽).

**되돌리기**: `Log LogMCPTest Log` 또는 플레이 종료.

**설명할 수 있게 되는 질문**
- "D를 누르면 왜 화면 아래로 가나요?" → D는 화면 오른쪽이 아니라 **바라보는 방향의 오른쪽**이라서. 로그 출처: `AMCPTestCharacter::DoMove`(`MCPTestCharacter.cpp`).
- "그 계산이 맞는지 어떻게 확인했나요?" → 자동화 테스트 `VaultHeist.Interaction.AimMove` + PIE에서 커서 6방향 × WASD를 로그로 측정(작업보고 2026-10-26 10장).

## 실습 9. 로그를 추가해 TCP 조각과 패킷 재조립 보기 (★★★ 어려움, 30분)
**목적**: "TCP에서 패킷이 잘려 오면 어떻게 하나요?"를 내 눈으로 확인.

**배경**: Mock 서버 설정 `bMockSplitPackets`(기본 켬)는 서버 → 클라이언트 바이트를 1~97바이트 조각으로 일부러 쪼개 보낸다(`FVHMockTransport::Tick`). 받은 쪽 `UVHNetSubsystem::OnBytes`가 `FVHPacketAssembler`에 모아 완성 패킷만 꺼낸다.

**방법**
1. `Source/MCPTest/Network/VHNetSubsystem.cpp`의 `UVHNetSubsystem::OnBytes` 첫 줄 `LastReceiveTime = ...` 아래에 한 줄 추가:
   ```cpp
   UE_LOG(LogVHNet, Log, TEXT("[조각] %d바이트 받음 (버퍼에 모인 것 %d)"), Num, Assembler.BufferedBytes() + Num);
   ```
   (`BufferedBytes()`는 테스트에서도 쓰는 함수. 확인 필요: 추가 위치가 `Assembler.Append` 앞이면 `+ Num`을 붙여야 모인 양이 맞다)
2. 저장 → Live Coding.
3. `L_MainMenu` 플레이 → [시작하기] → [확인](로그인).
4. 출력 로그 검색 `LogVHNet`.

**정답 확인**: `[조각] 37바이트 받음 ...`, `[조각] 12바이트 받음 ...` 같은 줄이 여러 개 나온 뒤에 `← SC_LOGIN (… bytes)` 한 줄 → **조각 여러 개가 모여 패킷 하나가 됐다.**
- 추가로 편집 → 프로젝트 세팅 → 게임 → **털어라 금고** → Mock 분류 **Mock Split Packets** 를 끄고 다시 해 보면 조각 1개 = 패킷 1개로 바뀐다.
- 보내는 쪽 로그 `→ CS_LOGIN (… bytes)`, 받는 쪽 `← SC_LOGIN`은 원래 있는 로그(`SendBytes`, `HandlePacket`).
- Mock 서버 내부까지 보려면 콘솔 `Log LogVHMock Verbose` → `Mock ← CS_LOGIN`, `Mock → SC_LOGIN`.

**되돌리기**: `git checkout -- Source/MCPTest/Network/VHNetSubsystem.cpp` → Live Coding. 프로젝트 세팅을 바꿨다면 다시 켜기(또는 `git checkout -- Config/DefaultGame.ini`).

**설명할 수 있게 되는 질문**
- "패킷이 잘려 오면?" → `FVHPacketAssembler::Pop`: 4바이트(헤더)가 안 모이면 `NeedMore`, 헤더의 size만큼 안 모이면 `NeedMore`, 다 모이면 잘라서 `Packet`, size가 4 미만·8192 초과면 `Error` → 연결 끊기.
- "두 패킷이 붙어 오면?" → `OnBytes`가 `for (;;)`로 `Pop`을 반복해 하나씩 꺼낸다.

## 실습 12. 새 상호작용 오브젝트 직접 만들기 — "종(벨)" (★★★ 어려움, 1~2시간)
**목적**: 공통 상호작용 시스템의 구조(오브젝트는 상태·연출, 판정은 Authority, 반영은 Subsystem)를 직접 써 보기.
**결과**: 손전등으로 비춘 종에 커서를 두고 G를 짧게 누르면 0.5초 뒤 "딸랑! 종이 울렸습니다" 알림.

**무엇을 만들어야 하나 (코드 확인 결과)**
| 할 일 | 파일 | 이유 |
|---|---|---|
| 1. 종류 추가 | `Gameplay/VHInteractionTypes.h`의 `EVHEntityKind` **맨 끝**(ReturnPoint 뒤)에 `Bell` | 판정이 `Target->GetKind()`로 `switch`한다. 앞쪽 값은 `protocol.h`와 순서를 맞춘 것이라 **중간에 넣으면 안 됨** |
| 2. 액터 클래스 | 새 파일 `Gameplay/VHBell.h/.cpp` — `AVHInteractableBase` 상속 | 상태·외형 담당. 등록은 부모 `BeginPlay`가 `RegisterInteractable`로 자동 |
| 3. 무엇을 할 수 있나 | `VHInteractionAuthority.cpp`의 `UVHLocalInteractionAuthority::BuildOffer`에 `case EVHEntityKind::Bell` | 모드(짧게/길게)·시간·문구를 담은 `FVHInteractOffer` 반환 |
| 4. 끝나면 무슨 일 | 같은 파일 `ResolveComplete`에 `case EVHEntityKind::Bell` | 결과를 Subsystem에 반영(여기서는 알림) |

**방법**
1. **에디터를 닫는다**(헤더 변경 + 새 파일).
2. `VHInteractionTypes.h` — `ReturnPoint` 다음 줄에 `Bell` 추가:
   ```cpp
   	ReturnPoint,
   	/** 연습용 종 */
   	Bell
   ```
3. 새 파일 `Source/MCPTest/Gameplay/VHBell.h`:
   ```cpp
   #pragma once
   #include "CoreMinimal.h"
   #include "Gameplay/VHInteractableBase.h"
   #include "VHBell.generated.h"

   UCLASS(Blueprintable)
   class MCPTEST_API AVHBell : public AVHInteractableBase
   {
   	GENERATED_BODY()
   public:
   	AVHBell();
   };
   ```
   `VHBell.cpp`:
   ```cpp
   #include "Gameplay/VHBell.h"
   #include "Components/StaticMeshComponent.h"

   AVHBell::AVHBell()
   {
   	Kind = EVHEntityKind::Bell;                              // 판정이 이 값으로 규칙을 고른다
   	Body->SetStaticMesh(FindBasicShape(TEXT("Cylinder")));   // /Engine/BasicShapes/Cylinder
   	BodyColor = FLinearColor(0.9f, 0.7f, 0.1f);
   }
   ```
4. `VHInteractionAuthority.cpp` — `BuildOffer`의 `case EVHEntityKind::ExitGate:` 위에:
   ```cpp
   	case EVHEntityKind::Bell:
   		return FVHInteractOffer::Make(EVHInteractMode::Tap, 0.5f * Scale, false, LOCTEXT("RingBell", "종 울리기"));
   ```
   `ResolveComplete`의 `default:` 위에:
   ```cpp
   	case EVHEntityKind::Bell:
   		Sub->PostMessage(LOCTEXT("BellRang", "딸랑! 종이 울렸습니다"));
   		break;
   ```
   (이 파일은 이미 `#define LOCTEXT_NAMESPACE "VHInteract"`가 있다. `#include "Gameplay/VHBell.h"`는 `CastChecked<AVHBell>`을 쓸 때만 필요)
5. 빌드(맨 위 `Build.bat` 명령) → 성공 확인 → 에디터 열기. (Visual Studio에서 새 파일이 안 보이면 에디터 **툴 → Visual Studio 프로젝트 새로고침**)
6. `L_InteractionTest` 열기 → 콘텐츠 드로어 **C++ 클래스 → MCPTest → Gameplay → VHBell**을 레벨로 끌어다 놓기.
7. 플레이 → 종 앞으로 걸어가 `R`(손전등) → 커서를 종에 → `G` 짧게.

**정답 확인**
- 손전등이 비추면 종에 옅은 노랑 테두리, 커서를 두면 주황 테두리 + `[우클릭/G] 종 울리기`.
- 누르면 출력 로그 `[Interact] BP_VHTestThief_C_0 → VHBell_0 : EVHInteractState::Begin (0.50s / 전체 0.50s)`(액터 이름 끝 번호는 다를 수 있음) → `Complete` → 화면 알림 `딸랑! 종이 울렸습니다`.
- 손전등을 끄면 테두리·안내가 없다(빛 안에서만 상호작용 — `UVHInteractionComponent`가 `UVHFlashlightComponent::IsBoxLit`으로 보이는 물체만 고름).

**더 해 보기**
- 0.5초를 코드에 쓰지 말고 `UVHInteractionConfig`에 `BellSeconds`를 추가해 데이터로 빼기(데이터 에셋 분리 원칙).
- 종을 울리면 소리를 내게: `UVHInteractionSubsystem::ReportNoise`에 `FVHNoiseEvent`를 넘기기(`Gameplay/VHMovementNoiseComponent.h`의 `FVHNoiseEvent` 필드: `Source`(누가), `Location`(어디서), `Radius`(cm), `Kind`(`EVHNoiseKind`: Move / AttackMiss / AttackHit — 종 소리용 종류를 새로 추가하려면 이 enum에 값을 더한다). 예: `FVHNoiseEvent E; E.Source = this; E.Location = GetActorLocation(); E.Radius = 1500.f; E.Kind = EVHNoiseKind::AttackMiss; Sub->ReportNoise(E);`).

**되돌리기**: 레벨에 놓은 종 삭제(저장했다면 `git checkout -- Content/VaultHeist/Maps/L_InteractionTest.umap`), 코드 `git checkout -- Source/MCPTest/Gameplay/VHInteractionTypes.h Source/MCPTest/Gameplay/VHInteractionAuthority.cpp`, 새 파일 `VHBell.h/.cpp` 삭제(직접 만든 파일이므로) → 에디터 닫고 빌드.

**설명할 수 있게 되는 질문**
- "새 오브젝트를 추가하려면 무엇을 고치나요?" → 종류 enum 1줄 + 액터 클래스 + `BuildOffer`·`ResolveComplete`의 case 2개. 대상 찾기·테두리·길게/짧게 누르기·진행 바·1명 제한은 **공통 시스템이 이미 처리**한다.
- "왜 오브젝트가 직접 판정하지 않나요?" → 서버 판정으로 바꿀 때 `UVHInteractionAuthority`만 갈아 끼우기 위해.
