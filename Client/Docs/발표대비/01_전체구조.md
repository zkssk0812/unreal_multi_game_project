## 3. 주요 클래스와 서로의 관계

### 3-1. 메뉴·네트워크 쪽

```
UVHNetSubsystem (UGameInstanceSubsystem)            ← 레벨이 바뀌어도 하나
 ├ TUniquePtr<IVHTransport> Transport                 ← 설정 bUseMockServer에 따라 둘 중 하나
 │    ├ FVHTcpTransport   (FSocket 논블로킹, 게임 스레드 Tick에서 폴링, 별도 스레드 없음)
 │    └ FVHMockTransport  → FVHMockServer (클라 안의 가짜 서버, 같은 바이트 패킷)
 ├ FVHPacketAssembler Assembler                       ← TCP 스트림 재조립
 ├ 상태: Phase(EVHNetPhase), MyName, RoomList, RoomState, LastGameEnd …
 └ 델리게이트: OnPhaseChanged, OnLoginResult, OnRoomListUpdated, OnRoomStateChanged, OnRoomError, OnLeftRoom, OnGameEnd …
          ▲ 구독(Add/RemoveDynamic)
AVHMenuPlayerController ── 화면 하나를 골라 CreateWidget → AddToViewport
          │
UVHScreenWidget (UUserWidget, Abstract)  ← WBP_* 의 부모. BindWidget, 공통 스타일(UVHUIStyle)
 ├ UVHMainMenuWidget  (WBP_MainMenu)
 ├ UVHLoginWidget     (WBP_Login)
 ├ UVHLobbyWidget     (WBP_Lobby)
 ├ UVHRoomWidget      (WBP_Room)
 └ UVHResultWidget    (WBP_Result)
UVHCodeWidget (UUserWidget, Abstract)    ← 블루프린트 없이 C++에서 트리를 만드는 위젯
 ├ UVHToastWidget, UVHRoomRowWidget, UVHChoiceButtonWidget, UVHRoomSlotWidget, UVHPlayerResultCard
 └ UVHGameHUDWidget  (게임 중 HUD)
```

- 단계(`EVHNetPhase`): `Disconnected → Connecting → Anonymous(연결됨, 로그인 전) → Authenticating(CS_LOGIN 보냄) → Lobby → Room → Game` (`Network/VHNetTypes.h`).
- 화면(`EVHScreen`): `MainMenu, Login, Lobby, Room, Result` (`UI/VHScreenWidget.h`).

### 3-2. 게임 플레이 쪽

```
AVHGamePlayerController (AMCPTestPlayerController 자식)
 │  입력(Enhanced Input) → 캐릭터의 컴포넌트에 "전달만" 한다. HUD·토스트 생성, 매치 시작, 개발용 콘솔 명령(VH*)
 ▼
BP_VHTestThief (AMCPTestCharacter = ACharacter) — 캐릭터 클래스 자체는 템플릿 그대로, 기능은 컴포넌트 8개
 ├ UVHAimComponent            시선·커서 기준 이동·탑뷰 카메라·벽 투명 파라미터
 ├ UVHActionComponent         스테미나·탈진·달리기·구르기·공격
 ├ UVHStatusEffectComponent   경직·면역·무적·탈진 표시
 ├ UVHInteractionComponent    대상 찾기·테두리·상호작용 키 처리
 ├ UVHTreasureCarrierComponent 들고 있는 아이템·무게·가치
 ├ UVHMovementNoiseComponent  소리 반경·신호
 ├ UVHThiefStateComponent     의적 상태(자유·숨음·잡힘·갇힘·탈출)
 └ UVHFlashlightComponent     손전등 (USpotLightComponent 자식), 빛 안 판정 IsBoxLit

월드 서브시스템 (UTickableWorldSubsystem, 레벨마다 1개, Game/PIE 월드에서만)
 ├ UVHInteractionSubsystem   등록부(오브젝트·의적·전투원) + 판정 담당 Authority 보관 + 결과 반영 Apply*
 │    └ UVHInteractionAuthority (Abstract) ← UVHLocalInteractionAuthority (지금은 클라이언트가 판정)
 └ UVHMatchSubsystem         한 판의 규칙: 반납지점·반납 가치·탈출구 해금·제한 시간·게임 끝 → 결과 보고

레벨에 놓는 액터
 AVHInteractableBase (Abstract, AActor) ← 상호작용 오브젝트 공통 부모 (BeginPlay에서 서브시스템에 등록)
   ├ AVHSafe  ├ AVHDroppedTreasure  ├ AVHReturnPoint  ├ AVHHideSpot  ├ AVHJailDoor  └ AVHExitGate
 AVHRoomVolume (방·지역 상자)      AVHDummyGuard (ACharacter, 테스트용 경비원)

순수 규칙(언리얼 객체 아님): namespace VHRules (Gameplay/VHInteractionRules.*) + FVHHoldProgress
데이터 에셋 클래스: UVHGameplayConfig, UVHInteractionConfig (Gameplay/), UVHGameData (Game/), UVHUIStyle (UI/)
```

**한 문장 요약**: 컨트롤러는 입력을 전달하고, 컴포넌트는 입력·표시를 하고, 판정은 Authority 한곳, 결과 반영은 서브시스템의 Apply* 한 입구, 한 판 규칙은 MatchSubsystem.

## 4. 게임 시작부터 결과창까지 — 어떤 클래스가 어떤 순서로

> 아래는 Mock 서버(기본 설정) 기준. 파일은 모두 `Source/MCPTest/` 아래.

### ① 프로그램 시작 → 메뉴 레벨
1. 게임 인스턴스가 만들어지며 `UVHNetSubsystem::Initialize`가 실행된다 (`Network/VHNetSubsystem.cpp`).
   - 엔진 틱 `FTSTicker`에 `UVHNetSubsystem::Tick`을 등록, 맵 로드 완료 이벤트 `FCoreUObjectDelegates::PostLoadMapWithWorld`에 `OnPostLoadMap` 등록, 콘솔 명령 `vh.ShowSampleResult` 등록.
2. `GameDefaultMap`인 `L_MainMenu`가 열린다 → 게임 모드 `BP_VHMenuGameMode` → 폰 없이 `BP_VHMenuPlayerController` 생성.
3. `AVHMenuPlayerController::BeginPlay` → 마우스 커서 표시, 서브시스템의 `OnPhaseChanged`·`OnGameEnd`에 구독 → `ShowScreenForCurrentState()` → 연결 전이므로 `ShowScreen(EVHScreen::MainMenu)`.
4. `ShowScreen`은 **다음 틱에**(`SetTimerForNextTick`) 이전 위젯을 지우고 `CreateWidget`으로 `WBP_MainMenu`를 만들어 `AddToViewport`, 입력 모드를 `FInputModeUIOnly`로 바꾼다. (같은 틱에 바로 바꾸면 버튼 입력이 새 화면으로 이어지는 문제가 있어 다음 틱으로 미룸 — 코드 주석)

### ② 로그인
5. `[시작하기]` → `ShowScreen(Login)` → `WBP_Login`(`UVHLoginWidget`). 이름 입력칸에 `UVHNetSubsystem::LoadLastLoginName()`(세이브 게임 `UVHLocalSaveGame`)으로 지난 이름을 채운다.
6. `[확인]` → `UVHNetSubsystem::ConnectAndLogin(Name)`
   - `ValidateLoginName`(영문 2~12자) 검사 → 설정 `bUseMockServer`에 따라 `FVHMockTransport` 또는 `FVHTcpTransport` 생성 → 콜백(`OnConnected`, `OnBytesReceived` …)을 람다로 연결 → 단계 `Connecting` → `Transport->Connect(Host, Port)`.
   - 연결되면 `OnConnected` 람다: 단계 `Anonymous` → `CS_Login`(이름 + `PROTOCOL_VERSION`)을 보내고 단계 `Authenticating`.
7. 매 틱 `UVHNetSubsystem::Tick` → `Transport->Tick` → 받은 바이트가 있으면 `OnBytes` → `FVHPacketAssembler::Append/Pop`으로 완성된 패킷만 꺼내 → `HandlePacket`(switch) → `HandleLogin`.
8. 로그인 성공 → 단계 `Lobby` → `OnPhaseChanged` → `AVHMenuPlayerController::HandlePhaseChanged` → `ShowScreen(Lobby)`.
   - 같은 Tick에서 2초마다 `SendPing()`(CS_PING). 15초 동안 아무것도 못 받으면 끊긴 것으로 처리.

### ③ 로비 → 대기실
9. `WBP_Lobby`(`UVHLobbyWidget`) → `RequestRoomList()`(CS_ROOM_LIST) → `HandleRoomList` → `OnRoomListUpdated` → 목록 다시 그림.
10. `[빠른 찾기]` → `QuickFind()` → 목록 → 들어갈 수 있는 방에 `JoinRoom` 시도 → 없으면 `CreateRoom` (`QuickFindOnList`, `QuickFindTryNext`, `QuickFindCreate`).
11. 입장 성공(`HandleJoinRoom`/`HandleCreateRoom`) → 단계 `Room` → 화면 `Room`(`WBP_Room`, `UVHRoomWidget`).
12. 대기실: `SelectCharacter`, `SelectPerks`, `SetReady` → 서버는 개별 성공 응답 없이 **`SC_ROOM_STATE`를 방 전원에게** 보낸다 → `HandleRoomState` → `OnRoomStateChanged` → 화면을 항상 최신 상태로 다시 그림. Mock에서는 가짜 플레이어 2명이 몇 초 뒤 준비한다(`FVHMockServer::ScheduleFakeJoin`, `ScheduleFakePreparation`).
13. 전원 준비 → Mock이 `CheckAllReady` → `StartGameLoad` → `SC_GAME_LOAD`.

### ④ 게임 레벨 로드
14. `UVHNetSubsystem::HandleGameLoad` → 직전 방 상태 저장(`LastGameRoomState`, 결과창 이름 매칭용) → 단계 `Game` → `OpenGameLevel()` → `UGameplayStatics::OpenLevelBySoftObjectPtr`로 설정의 `GameLevel`(= `L_Mansion_1F`)을 연다.
15. 레벨이 바뀌면 메뉴 컨트롤러·위젯은 사라지고(`AVHMenuPlayerController::EndPlay`에서 구독 해제), **게임 인스턴스 서브시스템은 남는다**.
16. 새 월드가 만들어지며 월드 서브시스템 `UVHInteractionSubsystem::Initialize`(판정 담당 `UVHLocalInteractionAuthority` 생성), `UVHMatchSubsystem`이 생긴다.
17. 액터들의 `BeginPlay` (순서는 엔진이 정하며 보장되지 않음 — 그래서 아래처럼 "등록 → 첫 틱에 처리" 구조를 썼다):
    - 금고·숨는 곳 등 `AVHInteractableBase::BeginPlay` → `RegisterInteractable`
    - 캐릭터 컴포넌트: `UVHThiefStateComponent::BeginPlay` → `RegisterThief`, `UVHStatusEffectComponent` → 전투원 등록, `UVHActionComponent::BeginPlay` → 능력치 복사·`JumpMaxCount = 0`(점프 없음), `UVHAimComponent::BeginPlay` → `ApplyTopDownCamera()`(스프링암을 탑뷰 고정), 회전 방식 설정
    - `AVHGamePlayerController::BeginPlay` → `ApplyGameInputMode`(커서 표시, `FInputModeGameAndUI`) → HUD(`UVHGameHUDWidget`)·토스트 생성 → `ApplyOutlinePostProcess`(테두리 포스트 프로세스) → **`UVHMatchSubsystem::StartMatch()`**(반납지점 5곳 생성, 제한 시간 시작)
    - `AVHGamePlayerController::SetupInputComponent` → `IMC_VHGameplay` 등록, 입력 액션 바인딩
18. `UVHNetSubsystem::OnPostLoadMap` → 게임 레벨이면 `CS_LOAD_COMPLETE` 전송 → Mock이 `SC_GAME_START`.
19. `UVHInteractionSubsystem::Tick` 첫 틱 → `AssignSafeTreasures()`: 금고 후보 중 5곳만 남기고 보물 배정.

### ⑤ 한 판 진행 (매 프레임)
20. 입력 → `AVHGamePlayerController::On*` 함수 → 컴포넌트 (예: 우클릭/G → `UVHInteractionComponent::InteractPressed` → `Authority->RequestBegin`).
21. 이동은 템플릿 캐릭터의 바인딩(`AMCPTestCharacter::SetupPlayerInputComponent` → `Move` → `DoMove`)이 받고, `DoMove`가 `UVHAimComponent::ComputeMoveVector`로 커서 기준 이동 방향을 구한다.
22. `UVHInteractionComponent::TickComponent` → 손전등 빛 안의 오브젝트 찾기 → `UpdateFocus`(대상 1개), `UpdateOutlines`(테두리).
23. `UVHLocalInteractionAuthority::Tick` → 진행 중 상호작용의 완료·취소 판정 → `ResolveComplete` → `UVHInteractionSubsystem::Apply*` (예: `ApplySafeOpened`, `ApplyTreasureReturned`).

### ⑥ 게임 끝 → 결과 보고

## 5. 언리얼 개념 ↔ 우리 코드

### 5-1. 게임 모드 (AGameModeBase)
- **무엇**: 레벨의 규칙 담당. 어떤 플레이어 컨트롤러·폰을 만들지 정한다. 서버(호스트)에만 존재한다.
- **우리 코드**: `AVHMenuGameMode`(`Game/VHMenuGameMode.cpp`) 생성자에서 `DefaultPawnClass = nullptr`, `PlayerControllerClass = AVHMenuPlayerController::StaticClass()` → 메뉴 레벨은 캐릭터 없이 UI만.
  게임 레벨은 템플릿의 `AMCPTestGameMode`를 상속한 블루프린트 `BP_VHInteractionTestGameMode`가 `BP_VHTestThief`와 `BP_VHGamePlayerController`를 지정한다(블루프린트 값, 에디터에서 확인).
- **한계/메모**: 한 판의 규칙은 게임 모드가 아니라 `UVHMatchSubsystem`에 두었다(게임 모드는 블루프린트 값만 쓰고, 규칙은 어디서나 `GetWorld()->GetSubsystem<>()`으로 꺼낼 수 있게).

### 5-2. 플레이어 컨트롤러 (APlayerController)
- **무엇**: 플레이어의 "의지". 입력을 받아 폰을 조종하고, 화면(UI)·입력 모드를 관리한다. 레벨이 바뀌면 새로 만들어진다.
- **우리 코드**
  - `AVHMenuPlayerController`: 화면 전환 담당(`ShowScreen`, `ShowScreenForCurrentState`), 입력 모드 `FInputModeUIOnly`.
  - `AVHGamePlayerController`(`Game/VHGamePlayerController.cpp`): 입력을 컴포넌트로 전달(`OnInteractStarted` → `UVHInteractionComponent::InteractPressed` 등), HUD 생성, `StartMatch` 호출, 개발용 콘솔 명령(`UFUNCTION(Exec)` — `VHHelp`, `VHGoto`, `VHAddValue` …).
  - `UpdateRotation`을 덮어써 **컨트롤 회전 = 커서 방향**으로 맞춘다(마우스로 카메라를 돌리는 템플릿 동작 무시).

### 5-3. 캐릭터 (ACharacter)와 폰
- **무엇**: 걷기·충돌·중력이 있는 폰. `UCharacterMovementComponent`가 이동을 계산한다.
- **우리 코드**: 템플릿 `AMCPTestCharacter`(`MCPTestCharacter.cpp`)를 거의 그대로 쓰고, `DoMove`에만 "시선 컴포넌트가 있으면 커서 기준 이동" 분기를 추가했다. 블루프린트 `BP_VHTestThief`(부모 `BP_ThirdPersonCharacter`)에 우리 컴포넌트 8개를 붙였다.
- **왜**: 진짜 캐릭터(동물 모델)가 아직 정해지지 않아서, 캐릭터 클래스는 건드리지 않고 기능을 컴포넌트로 만들었다 → 새 캐릭터에 같은 컴포넌트만 붙이면 된다.
- 테스트용 경비원 `AVHDummyGuard`도 `ACharacter` 자식(기본 도형으로 만든 몸 + 보물 소지·상태이상 컴포넌트).

### 5-4. 액터 컴포넌트 (UActorComponent)
- **무엇**: 액터에 붙이는 기능 조각. 자기 `TickComponent`·`BeginPlay`가 있다. `USceneComponent` 계열은 위치를 가진다.
- **우리 코드**: 3-2의 8개. `UVHFlashlightComponent`는 `USpotLightComponent`(빛 = 씬 컴포넌트)를 상속해서 "빛 자체가 손전등 기능을 가진" 형태.
- 컴포넌트끼리는 `GetOwner()->FindComponentByClass<UVHActionComponent>()` 식으로 서로 찾는다(예: `UVHAimComponent::CanTurn`이 상태이상·의적 상태 컴포넌트를 찾아봄).
- 틱 순서 예: `UVHActionComponent::BeginPlay`에서 `Movement->PrimaryComponentTick.AddPrerequisite(this, …)` → 이 컴포넌트가 정한 속도로 이동 계산이 되도록 **이동 컴포넌트보다 먼저 틱**하게 했다.

### 5-5. 게임 인스턴스 서브시스템 (UGameInstanceSubsystem)
- **무엇**: 게임 인스턴스(프로그램이 켜져 있는 동안 하나)에 자동으로 붙는 싱글톤 같은 객체. **레벨이 바뀌어도 사라지지 않는다.**
- **우리 코드**: `UVHNetSubsystem`. 메뉴 레벨 ↔ 게임 레벨을 오가도 서버 연결·로그인 정보·방 상태·결과가 유지되어야 하므로 여기에 두었다. 어디서든 `UVHNetSubsystem::Get(this)`로 꺼낸다.
- 게임 스레드에서 매 프레임 돌리려고 `FTSTicker::GetCoreTicker().AddTicker`로 틱을 등록했다(서브시스템 자체에는 틱이 없어서).

### 5-6. 월드 서브시스템 (UWorldSubsystem / UTickableWorldSubsystem)
- **무엇**: 월드(레벨)마다 하나씩 자동으로 생기는 객체. 레벨이 바뀌면 새로 만들어진다.
- **우리 코드**: `UVHInteractionSubsystem`, `UVHMatchSubsystem` (둘 다 `UTickableWorldSubsystem`, `DoesSupportWorldType`에서 `Game`·`PIE` 월드만). 레벨에 하나만 있어야 하는 "관리자"(등록부, 한 판 규칙)를 액터로 레벨에 놓지 않아도 된다.
- 메뉴 레벨에도 생기지만 아무도 등록하지 않고 `StartMatch()`도 불리지 않아 아무 일도 하지 않는다.

### 5-7. 데이터 에셋 (UDataAsset / UPrimaryDataAsset)
- **무엇**: 코드 없이 값만 담는 에셋. 에디터에서 숫자를 고치고 저장하면 다음 플레이부터 적용.
- **우리 코드**(모두 `UPrimaryDataAsset` 상속)
  - `UVHGameplayConfig`(`DA_VHGameplayConfig`): 카메라, 시선·이동 배율, 캐릭터 능력치(`FVHCharacterStats`), 경직, 공격, 금고 보물 표·등장 수, 제한 시간·목표 가치, 반납지점, 테두리, 벽 투명 처리.
  - `UVHInteractionConfig`(`DA_VHInteractionConfig`): 상호작용 거리·각도·시간, 소리, 손전등, 문구.
  - `UVHGameData`(`DA_VHGameData`): 캐릭터·퍽·맵 목록(대기실용, 임시 데이터).
  - `UVHUIStyle`(`DA_VHUIStyle`): 색·글자 크기·여백.
- 수치를 바꾸려면 코드가 아니라 이 에셋을 고친다(02_기능별_구현.md "데이터 에셋으로 수치를 분리한 이유").

### 5-8. 개발자 설정 (UDeveloperSettings)
- **무엇**: 프로젝트 설정 창에 나오고 `Config/*.ini`에 저장되는 설정 클래스.
- **우리 코드**: `UVHSettings`(`Network/VHSettings.h`, `UCLASS(Config = Game, DefaultConfig)`) — `DefaultGame.ini`의 `[/Script/MCPTest.VHSettings]`를 읽는다.
  - 데이터 에셋 4개를 `TSoftObjectPtr`로 가리키고 `GetGameplayConfig()` 등에서 `LoadSynchronous()`로 불러온다. 에셋이 없으면 C++ 기본값(`GetDefault<UVHGameplayConfig>()`)을 쓴다.
  - Mock 사용 여부, 서버 주소, 메뉴 레벨·게임 레벨 경로도 여기. 맵을 바꾸면 `GameLevel=` 한 줄만 고치면 된다.
  - 어디서나 `UVHSettings::Get()`.

### 5-9. UMG 위젯과 BindWidget
- **무엇**: UMG = 언리얼의 UI 시스템. 위젯 블루프린트(WBP)에서 화면을 배치하고, C++ 부모 클래스의 `UPROPERTY(meta = (BindWidget))` 변수와 **이름이 같은 위젯**이 자동으로 연결된다(없으면 컴파일 오류, `BindWidgetOptional`은 없어도 됨).
- **우리 코드**
  - `UVHScreenWidget`(Abstract, `UI/VHScreenWidget.h`) — 메뉴 화면 공통 부모. `WBP_MainMenu`의 부모는 `UVHMainMenuWidget` 등(에디터에서 확인).
  - 예: `UVHLoginWidget`의 `UPROPERTY(meta = (BindWidget)) TObjectPtr<UEditableTextBox> NameTextBox;` → WBP_Login 디자이너에 `NameTextBox`라는 입력칸이 있어야 한다.
  - 로직은 C++(버튼 클릭 → 서브시스템 함수 호출, 델리게이트 받아 다시 그리기), 배치는 블루프린트.
  - 공통 스타일: 위젯 이름 규칙(`Title`, `Primary`, `Panel` …)을 보고 `UVHUIStyle` 값을 자동 적용(`ApplyCommonStyle`).
  - 반복되는 작은 위젯(방 목록 한 줄, 캐릭터 버튼, 결과 카드)과 게임 HUD·토스트는 **블루프린트 없이 C++에서 트리를 직접 만든다**(`UVHCodeWidget::RebuildWidget` → `BuildTree`). `BP_VHGamePlayerController`의 `HUDClass`는 비어 있어 C++ `UVHGameHUDWidget`을 그대로 쓴다(에디터에서 확인).

### 5-10. Enhanced Input (입력 액션 IA, 입력 매핑 컨텍스트 IMC)
- **무엇**: 입력 액션(IA) = "무슨 동작인가"(상호작용, 구르기…), 입력 매핑 컨텍스트(IMC) = "어떤 키가 어떤 IA인가". 코드는 키가 아니라 IA에 반응한다 → 키를 바꿔도 코드는 그대로.
- **우리 코드**
  - `IMC_VHGameplay`: 우클릭·G → `IA_VHInteract`, 왼쪽 Shift → `IA_VHSprint`, R → `IA_VHFlashlight`, Space → `IA_VHRoll`, 좌클릭 → `IA_VHAttack`.
  - 이동(WASD)은 템플릿의 `IA_Move`(`IMC_Default`)를 그대로 쓴다.
  - `AVHGamePlayerController::SetupInputComponent` → `UEnhancedInputLocalPlayerSubsystem::AddMappingContext(GameplayMappingContext, 1)` → `EIC->BindAction(InteractAction, ETriggerEvent::Started, …)` 처럼 **Started/Completed/Triggered**로 바인딩(길게 누르기는 Started=누름, Completed=뗌).
  - 어떤 IA를 쓸지는 `BP_VHGamePlayerController`의 변수(`InteractAction`, `RollAction` …)에 지정되어 있다(에디터에서 확인).
- 화면의 `[우클릭/G]` 안내 글자는 코드에 고정 → 키를 바꿔도 글자는 안 바뀐다(알려진 한계).

## 6. 알려진 한계 (구조 관점)

- **판정이 클라이언트에 있다**: 지금은 `UVHLocalInteractionAuthority`가 판정한다. 멀티플레이에서는 서버가 판정해야 하므로 서버 판정 클래스로 교체가 필요하다(구조는 준비됨, 패킷은 v2 반영 필요 → 04).
- **월드 서브시스템이 첫 플레이어 기준**: `UVHMatchSubsystem::EndMatch`/`SendResultReport`가 `GetFirstPlayerController()`를 쓴다 → 한 화면 1인 기준 코드다.
- **템플릿 이름이 남아 있음**: 모듈 `MCPTest`, 캐릭터 `AMCPTestCharacter`, 게임 모드 블루프린트 `BP_VHInteractionTestGameMode`(저택에서도 사용). 이름 변경은 큰 구조 변경이라 하지 않았다(CLAUDE.md).
- **템플릿 Variant 폴더**: 빌드에는 포함되지만 쓰지 않는다.
- **입력 안내 문구 고정**, **HUD는 코드로 만든 임시 디자인**(좁은 화면에서 겹침).
- BeginPlay 순서는 엔진이 보장하지 않는다. 그래서 ① 금고 보물 배정은 "모두 등록된 뒤 첫 틱"(`UVHInteractionSubsystem::Tick` → `AssignSafeTreasures`)에 하고, ② `StartMatch()`가 쓰는 방 목록은 등록이 아니라 그 순간 월드를 직접 훑어서(`UVHMatchSubsystem::GetRooms` → `TActorIterator<AVHRoomVolume>`, `bAllowReturnPoint`인 방만) 얻는다. 레벨에 미리 놓인 액터는 이 시점에 이미 월드에 있으므로 순서 문제가 없다.
