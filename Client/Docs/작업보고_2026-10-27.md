## 3. 남은 문제
1. **서버 `fbx_to_map.py`가 `floors`를 FBX 바닥으로 덮어써 `floor_exit`가 빠진다** → 서버에서 탈출 구역(문 밖)이 걸을 수 없는 칸. 서버 팀원에게 "FBX에 없는 바닥은 남겨 달라"고 답변서에 적었다(서버 코드는 우리가 고치지 않음).
2. 서버 기존 경비원 시작 2(`L2` = 클라 방 20)와 순찰 35·39·41이 **문 없는 방** 안 → 그 경비원은 나오지 못함(서버에도 원래 있던 경고). 모델러가 문을 내거나 서버가 위치를 옮겨야 함.
3. 순찰 연결 28→40이 금고 4(방 12) 위를 지난다(금고는 dynamic이라 격자에는 안 막힘).
4. 반납 상호작용 범위: 지금 클라는 사각형 가장자리에서 150cm(+여유 50). **서버 값(가운데 100cm 원)에 맞추기로 결정** → 반납 지점만 범위를 따로 두도록 클라 수정 필요(다음 작업).
5. 시작 위치 3개 중 어느 것을 쓸지는 지금 언리얼 기본 규칙(빈 PlayerStart 중 하나)을 따른다. 서버 연동 때는 서버가 정한 위치로 옮겨야 한다.
6. 게임 HUD의 위치 숫자가 바뀜(예: 시작 (−29.5, −49.0) → (49.0, −29.5)). 예전 문서·캡처의 좌표와 다르다.
7. (전부터) 문 없는 방 11·13·20, 방 14 L자, 숨겨진 금고가 정적 내비에 남는 문제 그대로.
8. `Config/DefaultEditor.ini` 의 에디터 자동 변경은 이번에도 커밋하지 않음.
9. `CLAUDE.md` 에 적힌 서버 프로토콜 경로 `Shared/protocol.h` → 서버 최신본은 `Shared/Protocol/protocol.h`. v2.1 반영 때 함께 고칠 것.

## 8. 발표 대비 메모
- **사용자·팀 결정**: 서버는 고칠 수 없으니 클라가 서버 좌표에 맞춘다 → 맵은 회전 없이 원점에, 화면 방향은 카메라만 90° 돌려 그대로. 서버 코드는 읽기만.
- **왜 좌표를 맞추나**: 서버는 같은 맵을 자기 좌표로 들고 있고(경비원 길찾기·충돌·탈출 판정), 클라가 보내는 위치를 그대로 쓴다. 두 좌표가 90° 다르면 금고 앞에 선 의적이 서버에서는 벽 속에 있게 된다. 좌표를 같게 하면 변환 실수가 생길 곳이 없다.
- **회전 변환**: 맵을 +90° 돌리면 모든 점은 (x, y) → (−y, x)로, 방향(Yaw)은 +90°. 오브젝트를 이 식으로 한꺼번에 옮겨 맵과의 상대 위치가 그대로다. 화면은 카메라 Yaw도 같은 90°를 돌려서 사용자가 보기에는 아무것도 안 바뀐다.
- **검증 방법**: 서버 맵 파일의 벽 상자 93개마다 레벨에서 직접 선을 쏴 벽 면까지 거리를 재서 비교(558번, 모두 0.1cm 안). "맞을 것"이 아니라 "맞았다"를 숫자로 확인.
- **커서 기준 이동이 카메라를 돌려도 그대로인 이유**: 이동 방향을 화면 축이 아니라 "커서가 가리키는 바닥 지점"(월드 좌표)으로 계산하기 때문. 카메라 각도와 무관하다.
- **배치 데이터 자동 생성**: 레벨에서 MCP로 액터 값을 뽑고 → 파이썬으로 서버 형식 JSON을 만든다. 배치가 바뀌면 다시 돌리면 된다(손으로 좌표를 옮겨 적지 않음).
- **미리 검사**: 서버의 맵 읽기·검사 코드(C++)를 파이썬으로 옮겨서 서버를 돌리지 않고도 "서버가 이 파일을 받아들이는지"를 확인했다. 그 과정에서 서버 변환 도구가 문 밖 바닥을 지워 탈출 구역이 막히는 문제를 통합 시험 전에 찾았다.

- **왜 서버를 우리 PC에서 직접 돌렸나**: 내일 처음 붙여 보면 문제가 생겨도 고칠 시간이 없다. 서버 코드는 건드리지 않고 사본을 빌드해 "진짜 서버"에 미리 붙여 봤다. 그 결과 탈출구 바닥(`floor_exit`)·보물 값·거리 기준 차이를 하루 먼저 찾았다.
- **프로토콜 헤더를 그대로 쓰는 이유**: 서버와 클라가 같은 구조체(`#pragma pack(1)`)를 memcpy 하므로 한 글자만 달라도 바이트 위치가 어긋난다. 파일을 바이트 그대로 복사하고, 언리얼 이름과 부딪히지 않게 `namespace RobProto { #include }` 로 감쌌다.
- **서버 권위(서버 판정)**: 이동은 클라가 정한 위치를 서버가 그대로 쓰지만, 금고·반납·탈출·포획은 서버가 판정한다. 클라는 "요청(CS_ACTION)"만 보내고, 결과는 "서버 이벤트(SC_…)"가 올 때만 화면에 반영한다. 기존 코드가 "판정 담당(Authority) 교체" 구조라 로컬 판정 클래스를 서버 판정 클래스로 바꾸기만 하면 됐다(가짜 서버 모드에서는 원래 로컬 판정).
- **스냅샷 보간**: 서버는 초당 20번(50ms) 위치를 보낸다. 그대로 그리면 뚝뚝 끊기므로 100ms 늦게, 두 스냅샷 사이를 선형 보간해서 부드럽게 그린다.
- **이동 전송량 줄이기**: 움직일 때만 최대 20Hz, 멈추면 1초에 한 번(서버 규칙). 상호작용 직전에는 위치를 한 번 더 보내 "서버가 아는 내 위치"를 최신으로 맞춘다(안 그러면 '너무 멉니다' 거절).
- **설정 파일을 안 고치고 서버 전환**: 콘솔 변수(`vh.Net.Mode`)와 실행 옵션으로 바꾼다 → 실수로 실서버 설정이 커밋되는 일이 없다. 기본값은 가짜 서버라 서버 없이도 개발 가능.
- **봇**: 사람이 한 명뿐이어도 두 번째 클라를 자동으로 돌려 "서로 보이는지"를 시험했다.

- **맵 데이터도 프로토콜의 일부**: 패킷이 같아도 서버 맵이 다르면 위치가 어긋난다. `map_version` 과 오브젝트 짝짓기 결과로 바로 알 수 있게 했다.
