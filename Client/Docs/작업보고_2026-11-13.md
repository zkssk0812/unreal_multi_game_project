## 요약
- 서버 v3.0(브랜치 `feature/pvpve-v3`, 커밋 `3badc96`)은 **PvP 규칙 전체를 서버가 판정**한다. 클라는 위치·시선·행동만 보내고, 서버가 보낸 결과를 화면에 그린다.
- 지금 클라(PvP 2단계)는 **규칙을 클라가 판정**하는 구조(Mock + 로컬 판정)라서, 2단계의 핵심은 "로컬 판정 → 서버 패킷 표시"로 바꾸는 일이다.

- 서버 사본을 `C:\UnrealProjects\VaultHeistServerV3\Project_Rob`에 복사해 빌드했고, 우리 맵(v2)으로 서버가 뜨는 것까지 확인했다.
- 코드는 아직 바꾸지 않았다. 아래 "사용자 결정" 답을 받은 뒤 2단계를 시작한다.

## 남은 문제
1. 상자·무기·소비 아이템·필드 아이템은 서버가 보내고 있지만 아직 화면에 그리지 않는다(2-4b). 커서를 올리면 뜨는 정보창도 없다.
2. 봇이 순간 이동으로 금고를 계속 털면 한 판에 보물 가치가 31,000$까지 오른다(×1.2 복리). 사람이 하면 이렇게까지는 안 가겠지만, 가치 상한이 없다는 점은 기획 확인 거리다.
3. 금고로 다가가기는 직선으로 걷는다(길찾기 없음). 3m 안에서만 시작하므로 대부분 문제없지만, 금고 옆 벽 쪽에서 누르면 3초 뒤 "가까이 갈 수 없습니다"가 뜰 수 있다.

## 확인 필요 (가정)
- 반납은 반납지점 위에서 **F를 눌러야** 한다(서버가 요청을 받아야 반납함). 기획 문구 "닿으면 반납"으로 바꾸려면 클라가 범위 안에 들어올 때 자동으로 요청을 보내면 된다 — 원하는 방식을 알려 주면 바꾼다.
- 줍기 후보 거리는 270cm(서버 300cm는 아이템 중심 기준이라 조금 안쪽으로).
- 대상 고르기는 "커서 방향에 가까운 것 우선 + 가까운 것 우선"이다. 기획의 "커서를 올린 것 우선"은 2-4b에서 커서 정보창과 함께 맞춘다.

## 발표 대비 메모 (2-4a)
- **F 한 번으로 다가가서 작업**: 서버는 "작업 지점에서 1.3m 안"인지 본다. 그래서 클라가 금고 앞 작업 지점까지 캐릭터를 걸어가게 한 다음 요청을 보낸다. 멀리서 요청하면 서버가 거리 초과로 거절하기 때문이다.
- **금고는 이어서, 상자는 처음부터**: 금고 진행도는 서버가 금고에 저장해 두어서 쓰러졌다 돌아와도 남은 시간부터 연다. 화면의 막대는 서버가 보낸 "지금까지 진행 / 전체 시간"으로 그린다.
- **시험용 봇이 순간 이동해도 되는 이유**: 이 서버는 이동을 검사하지 않는다(클라 위치를 믿음). 덕분에 길찾기 없이도 금고 → 반납 흐름을 자동으로 시험할 수 있었다. 거꾸로 말하면 실제 서비스라면 위치 검사가 필요하다는 뜻이고, 이것은 서버 설계의 한계로 설명할 수 있다.
