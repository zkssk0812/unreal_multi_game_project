## 변경 내용
### 1. 화염방사기 불꽃 (`NS_VH_Flame` 이미터 5겹, 재질 5개)
| 이미터 | 재질 | 하는 일 |
|---|---|---|
| Core | `M_VHFlameCore` (가산) | 흰·노랑 심지 → 주황 → 빨강 끝 |
| Flame | `M_VHFlameBody` (반투명) | 주황 → 빨강 → 검붉은 그을음 (밝은 바닥에서 윤곽) |
| Embers | `M_VHFlameEmber` (가산) | 작고 빠르게 흩어지는 불씨 |
| Smoke | `M_VHFlameSmoke` (반투명) | 나이 0.3부터 보이는 옅은 회색 연기 (불꽃 끝) |
| Haze | `M_VHHeatHaze` (굴절 2D Offset) | 열기 일렁임 |
- 색 변화는 **재질이 입자 나이로 계산**(나이아가라 MCP 로는 색 커브를 넣을 수 없음). 크기는 Set Parameters 로 `Particles.SpriteSize = lerp(처음, 끝, 나이)`.
- 범위: 속도·공기 저항·수명으로 이동 거리 ≈ 판정 길이 안, 원뿔 각도는 전체 각 26~28(좌우 13~14°) → 판정 원뿔(600cm·±15°) 안. 650cm 허수아비 앞에서 끝나는 것 화면 확인.
- 판정 부채꼴(도형)은 나이아가라가 있으면 옅은 테두리만 (꽉 찬 주황 부채꼴이 불꽃을 가려 솜뭉치처럼 보였다).
- 스크립트: `Tools/WeaponBuild/setup_flame.py`(재질), `setup_niagara.py flame`(5겹 표 `FLAME_LAYERS`).
- 함정: `Particle Color` 노드 기본 출력은 RGB 뿐(알파는 "A" 출력 따로), 굴절은 Unlit 에서 컴파일 실패 → Default Lit + 불투명도 0, 각도 무늬를 세게 하면 별 모양.

### 2. 수류탄
- 손에 든·날아가는 크기: 무기별 배율 1.4 → **0.8** (실제의 2.8배 → 1.6배, 9×6×13cm 모델 → 약 14×9×21cm).
- 던지기 키 프레임 다시(Lyra `MM_Rifle_GrenadeToss` 곡선 모양 참고): 0.07초 가슴 앞으로 모아 **핀 뽑기**(= 핀 "딸깍" 0초) → 0.20초 **뒤로 젖히기** → 0.29초 **던지기·손을 떠남**(= 던지는 바람 0.12초 늦게 시작한 소리의 휘두르는 구간) → 0.75초 끝. 서버 간격 1초 안.
- 손을 떠나는 순간을 코드 상수(0.2초) 대신 DA 동작의 Effect Time 에서 읽고, **날아가는 소리도 그 순간에** 낸다(소리 파일·음량은 그대로).
- 스크립트: `setup_character_data.py grenade`. 함정: 파이썬에서 DA 배열의 구조체는 복사본이라 `ws[i] = w` 로 다시 넣어야 저장됨.

## 발표 대비 메모
- **소켓**: 모델 안에 "여기가 총구" 같은 이름표 점을 박아 두면 이펙트가 그 점을 따라간다. 모델이 바뀌어도 코드·이펙트는 그대로 → 모델러와 프로그래머가 따로 일할 수 있다. 소켓이 없으면 모델 크기로 계산한 자리를 쓴다(게임이 멈추지 않음).
- **불꽃을 재질로 색칠**: 입자마다 "태어난 지 얼마나 됐나(0~1)"를 재질이 읽어 흰색 → 주황 → 빨강 → 연기로 칠한다. 가산 혼합(빛을 더함)은 밝은 바닥에서 묻히기 쉬워 어두운 반투명 몸통을 같이 깔았다.
- **판정과 연출 맞추기**: 서버 판정 원뿔(600cm·±15°) 안에서만 불꽃이 머물게 속도·공기 저항·수명을 계산했다 (이동 거리 = 속도/저항 × (1 − e^(−저항×수명))).
- **높낮이 미끄러짐**: 같은 소리 파일을 재생 속도만 바꿔 "위이잉↓"을 만든다(재생 중에 높낮이 값을 0.02초마다 바꿈).

## 확인한 것 (보고 요청 항목)
- **캐릭터3에 뼈대가 없는지**: `compare_rigs.py` 로 FBX 노드를 직접 읽음 → `Geometry/Mesh 1, Model/Mesh 1, Material 1, Texture 3`뿐, **LimbNode(뼈) 0 · Deformer(Skin/Cluster) 0 · BindPose 0**. 진짜 리깅이 없다. 리깅·우회는 하지 않았다.
- **캐릭터2 뼈대**: 뼈 65개, 이름은 캐릭터1과 같고 끝 뼈 13개만 다름(`Head_end`↔`HeadTop_End`, `*3_end`↔`*4`, `*ToeBase_end`↔`*Toe_End`). 관절 위치 방향은 거의 같지만(손가락 외 0~4°) **뼈 자기 축 방향이 다름**(평균 10°, 오른 아래팔 52°·오른손 36°). FBX 단위도 캐릭터1(m)과 달리 cm(UnitScaleFactor 1). 스킨 클러스터 52개(캐릭터1 65).
- **준비창·프로토콜**: 캐릭터 선택 창은 `UVHRoomWidget` 이 `DA_VHGameData.Characters` 목록으로 버튼을 만든다(C++ 기본값 도적1~5). 프로토콜 v3.0에 **이미 값이 있다**: `CS_SELECT_CHARACTER.character_id` → `SC_ROOM_STATE`의 `RoomMemberInfo.character_id` → 게임의 `EntitySpawn.type_id`(플레이어 = 캐릭터 ID). 다른 플레이어 표시(`AVHNetProxy`)도 이미 이 번호로 `DA_VHCharacterVisuals.Characters` 를 찾게 되어 있었다 → **고른 캐릭터 그대로 연결**(서버 번호 순서 방식은 쓰지 않음).

## 결정: 캐릭터1 스켈레톤을 함께 쓴다 (리타깃 대신)
- 이유: 캐릭터1 스켈레톤에 애니메이션이 약 100개(Mixamo 27·권총/라이플 36·리타깃 23·블렌드스페이스 3·몽타주) 있다. 캐릭터마다 리타깃하면 같은 에셋이 캐릭터 수만큼 늘고 DA 의 몽타주 칸도 캐릭터마다 다시 채워야 한다.
- 그대로 함께 쓰면 뼈 축 차이(52°) 때문에 팔이 비틀린다 → **캐릭터2의 바인드 자세를 "관절 위치는 캐릭터2, 축 방향은 캐릭터1"로 다시 잡고**(메시 모양은 그대로 = 다시 바인드, `SkeletonModifier`), 끝 뼈 이름을 캐릭터1 이름으로 바꾼 뒤 캐릭터1 스켈레톤으로 다시 임포트.
- 팔 길이가 다른 문제(위팔 1.05배 등): 스켈레톤 뼈 이동 리타게팅 모드를 `Hips = AnimationScaled`, 나머지 = `Skeleton` → 각 메시가 자기 뼈 길이를 쓴다. 엔진 코드(`AnimationRuntime.cpp`)에서 Skeleton 모드가 메시 자기 기준 자세를 쓰는 것을 확인했고, 캐릭터1 애니메이션의 뼈 이동값은 캐릭터1 기본 자세와 **0.000cm** 차이라 도적1은 바뀌지 않는다.

# ③ 레일건 충전 발사 + 총기 반동 (사용자 요청 2026-11-20 밤 ~ 11-21 새벽)

## 사용자 지시
- 레일건(6번): 좌클릭 → 충전음 + 총구에 모이는 빛 1초 → 발사(지금의 발사음·광선·방전음 그대로). 서버에 대기 시간이 있으면 맞추고, 없으면 클라가 1초 뒤에 신호. 충전 중 재클릭 무시, 조준은 마우스를 따라가고 발사 순간 방향으로. 무기 교체·사망·기절/감전이면 취소(소리·이펙트도). 이동은 그대로. 다른 플레이어 화면 확인, 값이 없으면 정호님께 부탁할 내용 정리. 충전음은 이미 받은 소리에서.
- 반동: 지금 상태를 연속 프레임으로 점검·표로 보고 → 현실적인 반동(권총 짧고 날카롭게, 레일건 크고 무겁게·상체 밀림·천천히 복귀, 테이저 가볍게, 화염 잔잔한 떨림). Lyra 곡선 기준, 무기별 세기·복귀 시간은 `DA_VHWeaponCatalog` 칸으로. 화면 흔들림 아주 약하게(레일건 가장 크게). 보이는 연출만(판정·조준·탄 방향 그대로, 섬광은 총구 소켓). 도적1·2 확인. 95fps 이상. 커밋은 client/menu-ui, `Config/DefaultEditor.ini` 제외, 패키징 안 함.

## 서버 코드 확인 (Docs/ServerRef, 읽기만)
- **충전·대기 시간 없음.** `AttackStart` → `attackHeld = true`, `nextFireMs = max(nextFireMs, now)` → 같은 틱 `UpdateFiring` → `FireWeapon` 에서 바로 발사 (`WorldCombat.cpp`). 입력은 틱(50ms)마다 모아 처리(`GameRoomPlay.cpp ProcessInputs`).

## 남은 문제
- 다른 플레이어에게 충전 예고가 안 보인다 → 서버에 상태 비트가 생기면 연결 (`Docs/ServerHandoff/서버_요청_2026-11-20_레일건충전.md`).
- 레일건 한 발 최소 간격이 1초 → 약 2초(충전 1초 + 발사 잠금 1초, 잠금 중 클릭 무시)로 늘었다. 탄이 2발뿐이라 영향은 작지만 기획 확인 필요.
- 신호를 보낸 뒤 서버 발사까지(로컬 42ms, 실제 망에서는 핑 + 최대 50ms) 충전 빛이 조금 더 남는다. 서버가 충전을 맡으면 없어진다.
- 레일건 든 자세에서 오른손이 총 아래 떠 있는 모양(예전부터, 이번 작업 범위 밖).
- `-VHBotHunt` 봇이 레일건을 들면 0.5초마다 "충전 중 클릭 → 무시" 로그가 찍힌다(동작은 정상).

## 발표 대비 메모
- **서버에 없는 충전을 클라가 만든 방법**: 서버는 "공격 시작"을 받으면 바로 쏜다. 그래서 클라가 클릭을 1초 들고 있다가(그동안 소리·빛) 그때의 마우스 방향으로 "공격 시작"을 보낸다. 판정은 여전히 서버가 하고, 클라는 보내는 시각만 늦춘다. 서버가 쏜 것을 확인(SC_FIRE)한 뒤에 "공격 끝"을 보내는 이유: 서버는 50ms마다 입력을 모아 처리해서 둘이 같은 묶음에 들어가면 쏘지 않기 때문.
- **취소 판단**: 무기 교체·쓰러짐·경직은 서버가 알려 주는 상태(HP·무기 칸·상태 비트)로 판단한다. 쓰러지면 서버가 HP 0 과 빈 무기 칸을 같이 보내서, 무기보다 HP 를 먼저 봐야 이유가 맞게 나온다.
- **반동이 안 보였던 이유**: 무기를 바꿀 때 팔이 순간이동하지 않게 자세를 부드럽게 따라가게 했는데, 이것이 0.05초짜리 반동도 같이 지워 버렸다. 반동은 그 부드럽게 따라가기 "뒤에" 더해서 해결했다.
- **보이는 것만 바꾸기**: 반동은 손·총·허리의 표시 위치만 바꾼다. 총알·빔은 서버가 판정한 방향(조준 yaw)으로, 섬광은 쏜 순간의 총구 자리에서 나오고, 반동은 그 뒤에 시작한다.
- **Lyra 곡선**: 실제 게임 애니메이션에서 "총구가 먼저 튀고 손이 2배 늦게 밀렸다가 0.3초에 돌아온다"는 모양을 숫자로 뽑아 기준으로 삼았다. 무기마다 세기와 시간만 다르게 → 표의 숫자만 고치면 조절된다.
- **사용자 결정**: 레일건은 1초 충전 후 발사, 충전 중 이동 가능, 반동은 무기별(권총 날카롭게·레일건 무겁게·테이저 가볍게·화염 떨림), 화면 흔들림은 아주 약하게.
