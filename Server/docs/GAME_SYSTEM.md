# 「털어라! 금고!」 서버 게임 시스템 정리

> 기준: 클라 게임 시스템 반영(프로토콜 v2.1) 이후. 지금 서버에 **구현되어 있는 것**을 기준으로 정리했습니다.
> 클라 규칙으로 바꾼 내용과 이유는 [RULES_CHANGE_PLAN.md](RULES_CHANGE_PLAN.md)를 봅니다. 경비원 AI는 서버 것을 그대로 쓰고 숫자만 맞췄습니다.
> 설계와 결정 이유는 [DESIGN.md](DESIGN.md), 단계별 진행은 [ROADMAP.md](../ROADMAP.md)를 봅니다.
> 숫자(시간·거리·점수)는 모두 `Content/GameData.h`에 모여 있고, ⚠ 표시는 기획·클라 팀 확인이 필요한 서버 임시값입니다.

---

## 1. 한눈에 보기

- 의적(플레이어) 1~3명이 한 방에서, 서버가 조종하는 경비원 3명을 피해 금고를 열고 보물을 반납 지점에 반납해 **팀 반납 가치 10,000$**를 채운 뒤 탈출하는 5분짜리 게임
- 서버: Windows IOCP C++, 20Hz 틱, 방마다 JobQueue(락 없는 액터)
- 이동은 클라가 정한 위치를 그대로 씀(검증 없음). **판정(상호작용·공격·포획·탈출)과 경비원 AI는 서버가 함**
- 맵: 클라 팀의 `Data/Maps/mansion_1f_server.json`(저택 1층)을 서버 시작 때 한 번 읽어 모든 방이 공유

```
접속 → 로그인 → 로비(방 목록) → 방 만들기/참여 → 캐릭터·퍽 선택 → 전원 준비
     → 로딩 → 게임(5분) → 결과(15초) → 로비로
```

## 2. 코드 구조

| 계층 | 위치 | 하는 일 |
|---|---|---|
| ServerCore | `ServerCore/` | IOCP, 세션, 송수신 버퍼, JobQueue/JobTimer, 메모리 풀, 로그, 지표 |
| 브리지 | `GameServer/` | 패킷 ↔ 콘텐츠 통역. 패킷 표와 연결 단계 검사(`Net/PacketHandler`), 디코더(`Protocol/CommandDecoder`), 인코더(`Protocol/MessageEncoder`), 하트비트 |
| 콘텐츠 | `Content/` | 게임 규칙. 소켓·패킷을 모름 |
| └ 로비 | `Content/Lobby/GameLobby` | 닉네임, 플레이어 ID, "누가 어느 방", 방 목록 |
| └ 방 | `Content/Room/GameRoom(.cpp, Play.cpp)` | 대기실(선택·준비), 로딩, 20Hz 틱, 결과, 복귀 |
| └ 세계 | `Content/Game/GameWorld.cpp` | 엔티티, 입력 반영, 규칙 판정, 이벤트 |
| └ AI | `Content/Game/GuardAI.cpp`, `PathFinder`, `Sight` | 경비원 상태 머신, A* 경로, 3D 시야 |
| └ 맵 | `Content/Game/MapData`, `MapLoader` | 맵 파일 읽기, 충돌체로 경로 격자 만들기, 검사 |
| 공용 | `Common/Protocol/protocol.h`(저장소 루트) | 패킷 구조체·ID (클라와 공유) |

데이터 모양의 변화:
```
바이트 → (PacketSession) 패킷 하나 → (CommandDecoder) Cmd/InputCmd → 로비·방·World
       → Msg → (MessageEncoder) SendBuffer → WSASend
```

## 3. 연결 단계 (ClientPhase)

연결마다 하나. 패킷이 올 때마다 브리지가 "이 단계에서 받아도 되는 패킷인가"를 검사합니다(`PacketHandler::Dispatch`).

| 단계 | 클라 화면 | 받는 패킷 | 다음 단계로 |
|---|---|---|---|
| Anonymous | 접속 직후 | `CS_LOGIN` | CS_LOGIN을 받으면 → Authenticating |
| Authenticating | 로그인 중 | 없음 (`CS_LOGIN` 재전송은 조용히 버림) | 성공 → Lobby / 실패 → Anonymous |
| Lobby | 메인·방 목록 | `CS_ROOM_LIST`, `CS_CREATE_ROOM`, `CS_JOIN_ROOM` | 방 입장 → Room |
| Room | 대기실 | `CS_LEAVE_ROOM`, `CS_SELECT_CHARACTER`, `CS_SELECT_PERKS`, `CS_READY` | 전원 준비 → Game / 나가기 → Lobby |
| Game | 로딩·게임·결과 | `CS_LOAD_COMPLETE`, `CS_MOVE`, `CS_ACTION`, `CS_RETURN` | 결과 뒤 → Lobby |

- `CS_PING`은 모든 단계에서 받습니다.
- 허용되지 않은 패킷은 `SC_KICK` 후 끊습니다. 예외: 단계가 바뀐 지 1초 안에 온 `CS_MOVE`/`CS_ACTION`은 늦게 도착한 것으로 보고 조용히 버립니다.
- 순서 규칙: 서버는 항상 **단계를 먼저 바꾸고 응답**합니다. 클라가 응답을 받자마자 보내는 다음 화면의 패킷이 막히지 않게 하기 위해서입니다.

## 4. 로비와 방

### 4.1 로그인
- 닉네임: 앞뒤 공백 제거, 최대 12자, 중복 불가(영문 대소문자는 같은 이름으로 봄) → 실패 시 `NameInvalid` / `NameInUse`
- 프로토콜 버전이 다르면 `SC_LOGIN(VersionMismatch)` 후 끊음
- 성공하면 플레이어 ID 발급, 단계 Lobby

### 4.2 로비가 맡는 것
- 플레이어 목록, 닉네임, **누가 어느 방에 있는지**(`player->roomId`), 방 목록(최대 20개, 대기 중인 방만)
- 방 만들기·참여 허가(이미 방에 있음 `AlreadyInRoom`, 정원 3명 `RoomFull`, 시작한 방 `RoomNotWaiting`)
- 연결이 끊기면 채널 ID(= 세션 ID)로 플레이어를 찾아 방에서 빼고 닉네임을 풀어 줌

### 4.3 방의 상태 (RoomState)
```
Waiting(대기실) ──전원 준비──▶ Loading ──전원 로딩 또는 30초──▶ Playing(5분) ──▶ Result(15초) ──▶ 모두 로비로, 방 삭제
```
| 상태 | 할 수 있는 것 | 방 목록 |
|---|---|---|
| Waiting | 입장, 캐릭터(1~4, 겹치면 `CharacterTaken`)·퍽(0~3개, 1~8, 중복 불가) 선택, 준비/해제, 나가기 | 보임 |
| Loading | `CS_LOAD_COMPLETE`. 나가기 불가 | 숨김 |
| Playing | 이동·행동 | 숨김 |
| Result | `CS_RETURN`(먼저 메인으로) | 숨김 |

- **전원 준비 = 자동 시작.** 방장 시작 버튼·카운트다운·최소 인원 없음(1명이어도 시작). 캐릭터를 골라야 준비 가능(`NotReadyable`).
- 방에 들어가면 방이 세션에 자기 입구를 등록(`BindRoom`)해서, 이후 방 패킷은 **로비를 거치지 않고 방으로 바로** 갑니다.
- 방 ↔ 로비는 서로의 JobQueue에 일을 넣는 방식으로만 대화합니다(방 → 로비: `MemberLeft`, `RoomStateChanged`).

### 4.4 끊김 처리
| 언제 | 처리 |
|---|---|
| 대기실 | 멤버에서 빼고 방 상태를 다시 알림. 방장이 나가면 다음 사람이 방장 |
| 로딩 | 의적을 이탈로 표시. 남은 사람이 모두 로딩 완료면 바로 시작 |
| 게임 | 의적을 이탈(LeftGame)로 표시, 차지하던 금고·숨는 곳·운반을 놓아 줌. 게임은 계속 |
| 모두 끊김 | 판 중단(Aborted), 방 삭제 |

## 5. 게임 진행

### 5.1 시작
1. 전원 준비 → `BeginLoading`: 판 번호 발급, 멤버 순서대로 스폰(0번 = 방장), **World 생성**(엔티티·금고 5곳 무작위·경비원 뇌), 단계 Game, `SC_GAME_LOAD`(맵 ID·버전, 금고 자리 5개, 스폰 배정, 로딩 제한 30초)
2. 클라마다 `CS_LOAD_COMPLETE` → 전원 완료면(또는 30초가 지나면) `StartGame`
3. `StartGame`: Playing, 시작 시각 기록, 로딩 중 쌓인 입력 버림, 사람마다 `SC_GAME_START`(엔티티 전부 + 자기 의적 번호), 첫 틱 예약

### 5.2 틱 (20Hz, `GameRoom::Tick`)
```
① ProcessInputs   수신함을 통째로 가져와 ApplyMove / ApplyAction (거절이면 그 사람에게만 SC_ACTION_REJECT)
② World.Update    경비원 AI → 스테미나·탈진·상호작용 진행·공격 판정·구르기·운반·경직·소리·반납 지점 수명·탈출 → 떨어진 보물 생성
③ 이벤트 전송     이번 틱에 생긴 일 (SC_ATTACK, SC_HIT, SC_GUARD_ALERT …) — 스냅샷보다 먼저
④ 스냅샷 전송     모든 엔티티의 위치·방향·상태 비트·보물 수·행동 (한 번 인코딩해서 방 전원이 공유)
⑤ 끝 확인         모두 탈출·감금·이탈이면 바로, 아니면 5분이 지났을 때
   다음 틱 예약    "시작 시각 + (틱 + 1) × 50ms" (처리 시간만큼 밀리지 않게)
```
- 이동(`CS_MOVE`)은 Job을 만들지 않고 방의 **수신함**에 쌓였다가 다음 틱에 한꺼번에 반영됩니다. 내 이동은 최대 50ms 뒤 다른 사람의 스냅샷에 보입니다.
- 모든 예약(로딩 제한, 틱, 결과 화면)에는 판 번호가 붙어 있어, 판이 바뀐 뒤 늦게 실행된 예약은 아무것도 하지 않습니다.

### 5.3 종료와 결과
| 이유 | 조건 |
|---|---|
| AllEscaped | 스스로 움직일 수 있는 의적이 없고, 남은 사람(이탈 제외)이 모두 탈출 |
| AllDone | 스스로 움직일 수 있는 의적이 없음 (감금·포획·이탈 등) |
| TimeUp | 5분 경과 |
| Aborted | 방에 아무도 없음 |

`SC_GAME_END`(의적별 탈출·감금·이탈, 반납 보물 개수·가치, 연 금고, 기절시킨 횟수, 점수) → 15초 뒤 또는 `CS_RETURN` → `SC_LEAVE_ROOM(GameEnded)`, 단계 Lobby.

**점수 ⚠** = 탈출 1000 + 반납 가치 ÷ 10 + 연 금고 × 100 + 경비원 기절 × 50 (클라 기획에 없는 서버 임시 공식)

## 7. 의적의 조작과 규칙

### 7.1 조작 → 패킷
| 조작 | 패킷 | 서버 처리 |
|---|---|---|
| 이동·달리기·방향 | `CS_MOVE` (위치·yaw·flags) | 위치·방향을 그대로 반영. 달리기는 스테미나가 있고, 탈진이 아니고, 공격 중이 아닐 때만 |
| 좌클릭 | `CS_ACTION(Attack, yaw)` | 공격 시작 |
| Space | `CS_ACTION(Dodge)` | 구르기 시작 (구르는 이동은 클라) |
| 우클릭 | `CS_ACTION(InteractBegin, 대상)` / `InteractCancel` | 상호작용 시작·취소 (숨어 있을 때는 나오기) |
| R | `CS_ACTION(FlashlightOn/Off)` | 상태 비트만 |
| Q | `CS_ACTION(UseSkill)` | 기획 미정 → 거절 |

거절 이유(`SC_ACTION_REJECT`): `InvalidState`(지금 할 수 없음), `Cooldown`(앞 행동의 후딜 중), `NoStamina`, `OutOfRange`, `TargetBusy`(다른 사람이 사용 중), `TreasureFull`(10개), `NotAvailable`, `TooHeavy`(20kg 초과).

### 7.2 스테미나와 탈진
- 최대 100. 뛰는 동안 초당 10 소모, 안 뛰면 초당 10 회복. 공격 30, 구르기 20.
- **무게 비례**: 달리기·공격·구르기 소모 × (1 + 무게/20kg) → 0kg 1배, 20kg 2배.
- **탈진**: 0에 닿으면(달리기·공격·구르기 어느 것으로든) `Exhausted` → 달리기·공격·구르기 불가(`NoStamina`), 회복 50%(초당 5). **100까지 차면 풀림.**

- `SC_TREASURE`: 의적마다 개수·무게(g)·가치, 팀 반납 개수·가치, 탈출 가능 여부.

### 7.4 상호작용
- 대상의 상호작용 위치(`interact_pos`)에서 **150cm 안**이어야 함(바닥 위 거리). 반납 지점은 가운데에서 100cm.
- 시간 걸리는 상호작용은 **대상마다 한 명**. 범위를 벗어나거나, 공격·구르기하거나, 잡히면 중단(`SC_INTERACT Cancel`).
- 공격·구르기가 끝나기 전에는 시작할 수 없음.

| 대상 | 시간 | 결과 |
|---|---|---|
| 닫힌 금고 | 30초, **중단해도 진행도 유지** | 열림 → `SC_SAFE_OPENED` |
| 열린 금고 | 즉시 | 보물 1개 줍기 (10개·20kg 한도) → `SC_TREASURE` |
| 떨어진 보물 | 즉시 | 줍기(같은 한도), 엔티티 사라짐 |
| 반납 지점 | 즉시 | 들고 있는 보물 전부 반납(빈손이면 `InvalidState`) → `SC_TREASURE`, 그 지점은 사라지고 다른 방에 새로 |
| 탈출구 | — | 상호작용 없음(`NotAvailable`). 가치 10,000$에 저절로 열림 |
| 창고 문 | 5초 ⚠, 처음부터 | 창고 구역 **밖**에서만. 갇힌 의적 모두 구출 → `SC_RELEASED(Rescued)` |
| 숨는 곳 | 1초, 처음부터 | 숨음 → `SC_HIDE(Hidden)`. 한 곳에 한 명 |

### 7.5 반납 지점과 탈출
- 반납 지점은 **항상 5곳, 방마다 최대 1개**. 방(`rooms`, 33개) 안에서 걸을 수 있고 의적이 닿는 칸 중 무작위. 문 없는 방(L2·U2·U4)과 창고(W3)에는 생기지 않음.
- 생긴 지 **50초 → 빨강**(`Warning`), **60초 → 사라지고 다른 방에 새로**. 반납하면 시간과 상관없이 바로 다른 방으로(사라진 방·이미 있는 방 제외).
- 팀 반납 가치가 **10,000$**가 되는 순간 탈출구가 저절로 열리고 전원에게 `SC_EXIT_OPENED`(전체 메시지). 이후 **탈출 구역(`exit.escape_zone`)에 들어선 의적은 탈출**(`SC_ESCAPED`). 들고 있던 보물도 반납으로 칩니다.

### 7.6 공격과 구르기
| | 의적 | 경비원 |
|---|---|---|
| 선딜 / 판정 / 후딜 | 0.2 / 0.5 / 0.3초 (20/50/30%) | 0.2 / 0.35 / 0.45초 (20/35/45%) |
| 범위 ⚠ | 시작할 때 방향 기준 좌우 60°(120° 부채꼴), 거리 120cm, 높이 차 150cm 이하 | 같음 |
| 비용 | 스테미나 30 (무게 비례) | 없음 |

- 판정 구간 동안 매 틱 검사하고, 한 공격은 한 명만 맞힙니다.
- **구르기**: 누르는 순간부터 0.5초 동안 무적(Dodging), 선딜·후딜 없음. 구르는 이동은 클라가 처리.
- **의적이 경비원을 맞히면**: 경비원 3초 경직 → 이어서 10초 면역. 들고 가던 의적은 풀려나고(`SC_RELEASED(GuardStunned)`), 빼앗았던 보물은 종류 그대로 주변 80cm에 흩어짐(`SC_ENTITY_SPAWN`).
- **경비원이 의적을 맞히면**: 포획(`SC_HIT`, `SC_CAPTURED`). 의적의 보물은 종류 그대로 경비원에게로, 의적은 경비원을 따라 이동하며 입력이 무시됨.
- 숨은 의적, 구르기 무적 중인 의적은 맞지 않습니다.

### 7.7 포획 → 감금 → 구출
경비원이 잡은 의적을 창고 문 앞까지 운반 → 감금 자리에 가둠(`SC_JAILED`) → 동료가 창고 문을 5초 상호작용하면 갇힌 사람 모두 풀려남. 운반 중인 경비원이 기절해도 풀려납니다.

## 8. 경비원 AI (`Content/Game/GuardAI.cpp`)

### 8.1 상태 머신
| 상태 | 하는 일 | 넘어가는 조건 |
|---|---|---|
| Patrol 순찰 | 순찰 지점(47개, 연결 68개)을 따라 걷기(3m/s). 도착하면 1초 둘러보고 이어진 지점 중 걸어서 갈 수 있는 곳으로 무작위 | 보임 → Chase / 소리 → Suspicious |
| Suspicious 의심 | 소리 난 곳으로 걷기 | 보임 → Chase / 도착 → Search |
| Chase 추격 | 달려서 쫓기(6m/s), 경로는 0.5초마다 다시 계산. 더 가까운 의적이 보이면 대상 교체 | 100cm 안 → Attack / 숨는 걸 봄 → PullOut / 3초 못 봄 → Search |
| Attack 공격 | 선딜·판정·후딜 동안 멈춤 | 잡음 → Carry / 빗나감 → 0.5초 멈춘 뒤 Chase |
| PullOut 끄집어내기 | 숨기 직전 1초 안에 본 의적이 숨은 곳 앞까지 달려가 꺼내서 포획(`SC_HIDE(PulledOut)`) | → Carry |
| Carry 운반 | 창고 문 앞까지 걷기(한 명당 15% 느려짐) → 가둠 | 가둠 → Patrol / 다른 의적이 보임 → (든 채로) Chase |
| Stunned 경직 | 아무것도 못 함 | 풀림 → Search |
| Search 탐색 | 그 자리(마지막으로 본·들은 곳)까지 가서 2초 둘러보기 | 보임 → Chase / 없음 → Patrol |

경계 수준이 바뀔 때만 `SC_GUARD_ALERT(Patrol / Suspicious / Chase + 대상 / Search / Stunned)`를 보냅니다. 공격·끄집어내기는 Chase로, 운반은 Patrol(+ Carrying 비트)로 보입니다.

### 8.2 감지
- **시야 ⚠**: 거리 15m(3D), 시선(이동 방향) 좌우 45°, 눈 높이 160cm → 의적 가슴(100cm) 사이에 시야를 막는 충돌체가 없어야 함. 낮은 조리대·분수대는 시야를 막지 않고, 창고 문·탈출구는 창살로 보고 건너뜀. 숨은 의적은 안 보임. 보이는 의적 중 **가장 가까운** 의적을 쫓음.
- **소리** (클라 소리 표): 걷기 0m(소리 없음), 달리기 0.2초마다 12m, 구르기 구르는 동안 매 틱 15m, 공격 빗나감 5m·적중 20m(한 번). 보물을 들면 (기본 + 개당 2m) × 1.1, 기본이 0이면 보물이 있어도 소리 없음. 벽은 소리를 막지 않음. 순찰·의심·탐색 중인 경비원만 반응.

### 8.3 경로
- 경로 격자(50cm × 196행 × 138열, 서버가 충돌체로 만듦, `.` 이동 가능, `#` 벽, `~` 낮은 장애물) 위의 **A\***. 8방향, 벽 모서리를 비스듬히 뚫지 않음. 걸어서 못 가는 곳(구역이 다름)은 탐색 없이 실패.
- 직선으로 갈 수 있는 중간 점은 생략(경로 다듬기).
- A* 작업 배열은 스레드마다 하나를 재사용(방 수와 무관한 메모리).

## 9. 맵 데이터 (`Data/Maps/mansion_1f_server.json`)

- 서버 시작 때 실행 파일 옆 `Data/Maps/mansion_1f_server.json`을 읽고 규칙을 검사(`ValidateMap`). 게임이 깨지는 문제(지점이 벽 안, 의적이 금고·탈출구에 못 감, 반납 지점을 놓을 방이 6곳보다 적음)가 있으면 **서버를 시작하지 않음**, 덜 심각한 문제(경비원 스폰·순찰 지점이 안 이어짐, 반납 지점을 놓을 칸이 없는 방)는 경고 로그.
- 맵 파일은 `tools/fbx_to_map.py`가 만듦: 벽·바닥은 `Data/Maps/Mansion_1F_Blockout.fbx`(충돌 박스 98개), 게임 지점·소품은 클라 팀 데이터.
- **경로 격자는 서버가 바닥과 충돌체로 만듦**: 바닥판 위의 칸만 열고(건물 밖은 막힘), 파일의 격자는 얇은 벽이 빠져 있어서 쓰지 않음. 정적 충돌체를 25cm 넓혀 겹치는 칸을 막고, 이어진 칸끼리 구역 번호를 붙여 서로 못 가는 곳은 A*가 바로 실패.
- 맵을 바꾸려면 파일 교체 후 서버 재시작(다시 빌드할 필요 없음). `SC_GAME_LOAD`의 `map_version`으로 클라가 같은 파일인지 확인.
- 좌표: Unreal 월드 좌표, cm, X = 북, Y = 동, Z = 위, 맵 중심 = 원점. yaw는 도, 0 = +X.
- 들어 있는 것: 스폰(의적 3, 경비원 3), 금고 후보 10, 숨는 곳 8, 방 33(반납 지점 후보), 탈출구·탈출 구역, 창고 문·감금 자리 3·창고 구역, 순찰 지점 47·연결 68, 충돌체 114개(정적 102 + 금고·문 12), 격자 틀 50cm × 196 × 138.
- 파일의 `vents`는 옛 규칙(환풍구 반납)이라 읽지 않습니다.
- 방마다 반납 지점을 놓을 칸(`returnCells`)을 서버 시작 때 모아 둠: 방 사각형 안, 걸을 수 있고 첫 의적 스폰과 이어지며, 창고·탈출 구역 밖인 칸. JSON에 `return_point: false`가 있는 방은 뺌.
- ⚠ 지금 맵의 문제(클라 팀 전달): 문 없는 방 3개(L2, U2, U4) → 경비원 스폰 1이 갇히고 순찰 지점 3개를 못 감, 반납 지점도 안 생김(클라도 제외). 배치(탈출구 위치 등)는 클라 레벨 데이터를 받으면 교체.

## 12. 성능 지표

서버 화면에 5초마다 한 줄:
```
[Stats] 접속 N | 게임 방 N, 틱 N회 평균 Nµs 최대 Nµs | AI 평균 Nµs, 경로 N회 평균 Nµs 최대 Nµs 칸 N, 시야 검사 N
        | 수신 KB/s | 송신 KB/s (WSASend 횟수) | 패킷/s ...
```
| 지표 | 뜻 |
|---|---|
| 틱 평균·최대 | 방의 틱 하나(입력·규칙·AI·인코딩·송신 요청)에 걸린 시간 |
| AI 평균 | 틱 하나에서 경비원 AI에 쓴 시간 |
| 경로 | A* 횟수, 한 번의 평균·최대 시간, 꺼내 본 칸 수 |
| 시야 검사 | 선분 ↔ 충돌체 계산을 실제로 한 수 |

성능을 위한 구조: 방마다 JobQueue(같은 방은 순서대로, 다른 방은 병렬), 이동 입력은 Job 없이 수신함, 스냅샷은 한 번 인코딩해서 공유, 송신 버퍼는 스레드별 64KB 덩어리, 객체 메모리 풀, A* 버퍼 스레드별 재사용, 경로는 가끔만 계산.
