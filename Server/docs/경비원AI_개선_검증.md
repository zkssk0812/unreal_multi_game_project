# 경비원 AI 개선 검증

> 대상: [경비원AI_공격탐색_개선안.md](경비원AI_공격탐색_개선안.md)의 A-2, S-1·S-3~S-6, P-1~P-7 (P-8은 선택 항목이라 넣지 않음)
> 브랜치: `guard-ai-improvement` (단계마다 커밋 하나: 0 측정 도구 → 1 공격 → 2 탐색 → 3 순찰 → 4 검증. `main`에는 아직 합치지 않음)
> 기본 수치는 그대로입니다: 회전 90°/s, 이동 2.1·4.2m/s, 시야 15m·90°, 공격 범위 60°·난사 ±30°.

|---|---|---|---|---|

| ① 등 뒤 돌며 때리기 (반응 0.25초 봇) | 〃 | 2 | **85** | 나아짐 |
| ② 쫓기다 숨기 | 탐색 끝에 다시 찾은 비율 | 62% | **100%** | 나아짐 |

## 1. 측정 방법

### 1.1 돌리는 법

```
Server\Binaries\x64\Debug\ContentTests.exe Bench
```

- 결과는 `[측정]` 줄로 나옵니다. 측정은 오래 걸려서(약 15초) 이름으로 고를 때만 돕니다. 그냥 `ContentTests.exe`를 돌리면 빠집니다.
- 코드: `Tests/ContentTests/GuardBenchTests.cpp`
- 씨앗이 고정이라 매번 같은 숫자가 나옵니다.
- 측정마다 "개선 후가 개선 전보다 나아야 한다"는 검사가 들어 있습니다(⑤ 제외). 나중에 코드를 바꿔서 효과가 사라지면 이 시험이 실패합니다.

### 1.2 개선 전과 개선 후를 어떻게 나누나

`GuardFeatures`로 개선 항목을 하나씩 켜고 끕니다(`Content/Game/GameWorld.h`).

- `GuardFeatures::None()`: 모두 끔. 코드를 고치기 전과 똑같이 움직입니다.
- `GuardFeatures::All()`: 모두 켬. 게임 서버의 기본값입니다.
- 항목 하나만 끄는 것도 됩니다. 게임에서 문제가 생기면 그 항목만 꺼서 확인할 수 있습니다.

### 1.3 측정 상황

모두 실제 맵(`mansion_1f_server.json`)과 실제 게임 규칙(`GameWorld`)으로 돌립니다. 플레이어는 정해진 규칙으로 움직이는 봇입니다.

| 상황 | 내용 | 횟수 |
|---|---|---|
| ① 등 뒤 돌며 때리기 | 삼단봉을 든 봇이 경비원 등 뒤 1.5m에 붙어 따라 돌며 15초 동안 때림. 스테미나 규칙대로 10초 달리기(6m/s) 뒤 걷기(3m/s). **완벽한 봇**은 경비원 방향을 바로 알고, **반응 0.25초 봇**은 0.25초 늦게 앎 | 시작 각도 8가지 |
| ② 쫓기다 숨기 | 경비원이 5~8m 앞에서 봇을 발견 → 봇이 달려서 14m 안쪽의, 경비원 자리와 처음 자리 모두에서 안 보이는 곳(모퉁이 너머·옆 방)으로 숨음. 경비원이 놓쳐서 탐색을 시작한 시도 중 25초 안에 다시 찾은 비율 | 맵 곳곳 40곳 |
| ③ 경직시키고 숨기 | 2m 앞에서 테이저(경직 2초)를 맞히고 ②처럼 숨음. 경직이 풀린 뒤 20초 안에 다시 찾은 비율 | 40곳 |
| ④ 5분 순찰 | 경비원 3명이 5분 동안 순찰만 함(플레이어 없음). 들른 순찰 지점(156개)과 방(순찰 지점이 있는 방) 비율, 멈춰 있던 시간 비율 | 씨앗 6개 |
| ⑤ 뒤따라가기 | 봇이 순찰하는 경비원이 지나간 길을 5m 뒤에서 그대로 따라감. 60초 안에 들킨 비율과 걸린 시간 | 12회 |
| ⑥ 동료 호출 | 경비원 하나가 봇을 발견. 그 경비원에게서 10~19m 떨어져 있고 봇을 직접 볼 수 없는 다른 경비원이 20초 안에 와서 봇을 본 비율 | 20곳 |

## 2. 결과 상세

### ① 등 뒤 돌며 때리기: A-2 물러나며 돌아서기

| 봇 | | 경비원이 준 대미지 | 봇의 타격 | 봇이 공격 범위(정면 60°) 안에 있던 시간 |
|---|---|---|---|---|
| 완벽한 봇 | 개선 전 | 2 | 21.0회 | 0.2% |
| | 개선 후 | **69** | 19.9회 | **8.5%** |
| 반응 0.25초 봇 | 개선 전 | 2 | 21.0회 | 12.5% |
| | 개선 후 | **85** | 20.0회 | 13.1% |

- **나아진 점.** 개선 전에는 등 뒤에서 때리는 플레이어에게 경비원이 사실상 반격하지 못했습니다(15초에 2). 개선 후에는 69~85를 줍니다. 플레이어 HP가 100이니 계속 돌며 때리면 거의 쓰러질 만큼입니다.
- **그대로인 점.** 봇이 경비원을 때린 횟수는 거의 같습니다. 경비원이 물러나도 달리기 속도(4.2m/s)가 플레이어(6m/s)보다 느려서, 바짝 붙어 따라오는 플레이어를 떼어 놓지는 못합니다. 개선안 2.1의 계산대로 1.5m 거리에서는 90°/s로 계속 정면에 두기 어렵습니다. 그래서 "공짜로 때리기"가 "맞으면서 때리기"로 바뀐 것이고, 때리는 것 자체를 막지는 않습니다.
- **반응 0.25초 봇 개선 전에 12.5%인데 대미지가 2인 이유.** 개선 전에는 지금 타겟이 때려도 반응하지 않아서, 타겟을 놓친 상태로 다른 곳을 보고 있었습니다. 그래서 봇이 우연히 정면 60°에 들어와도 쏘지 않았습니다.

### ② 쫓기다 숨기, ③ 경직시키고 숨기: S-1·S-3·S-4·S-6

| 상황 | | 다시 찾음 | 찾기까지 평균 |
|---|---|---|---|
| ② 쫓기다 숨기 | 개선 전 | 20/32 (62%) | 5.0초 |
| | 개선 후 | **31/31 (100%)** | 5.2초 |
| ③ 경직시키고 숨기 | 개선 전 | 18/40 (45%) | 8.8초 |
| | 개선 후 | **33/40 (82%)** | 8.7초 |

- 개선 전에는 놓친 자리에서 반 바퀴(180°)만 보고 돌아가서, 모퉁이 너머로 숨으면 40% 가까이 그대로 빠져나갔습니다.
- 개선 후에는 도망 방향 앞(S-1), 한 바퀴(S-3), 안 보이는 주변 지점(S-4)을 차례로 확인해서 ②는 모두 찾았습니다.
- ③은 경직 동안 봇이 움직인 것을 경비원이 보지 못했습니다. 그래서 도망 방향을 몰라서 ②보다 낮지만, 마지막으로 맞은 곳부터 찾기(S-6)와 주변 지점 확인(S-4) 덕에 45% → 82%가 되었습니다.
- 찾는 데 걸린 시간은 비슷합니다. 개선 전에는 금방 찾을 수 있는 경우만 찾았기 때문입니다. 개선 후에는 더 어려운 경우까지 찾았는데도 평균 시간이 늘지 않았습니다.

### ④ 5분 순찰: P-1~P-5

| | 들른 순찰 지점 | 들른 방 | 가장 적게 들른 경우 (방) | 멈춰 있던 시간 |
|---|---|---|---|---|
| 개선 전 | 58% | 48% | 35% | 23% |
| 개선 후 | **73%** | **61%** | **52%** | 30% |

- 오래 안 간 곳 우선(P-1), 동료와 겹치지 않기(P-2), 지나가는 지점 통과(P-3)로 더 넓게, 덜 치우치게 돕니다.
- 개선안의 단순 시뮬레이션(방 52% → 73%)보다 효과는 작습니다. 실제 경로 찾기와 둘러보기 시간이 들어갔기 때문입니다.
- **멈춰 있던 시간은 늘었습니다(23% → 30%).** 지나가는 지점은 통과하지만 멈추는 지점마다 좌우 훑기(2초)와 가끔 뒤돌아보기(2초)를 하기 때문입니다. 멈춘 시간 대부분이 둘러보는 시간이라 나쁜 것은 아니지만, 5장의 변형을 쓰면 24%로 줄어듭니다.

## 5. 발견한 문제: 뒤따라가는 플레이어를 늦게 알아챔 (결정 필요)

### 원인

개선 후 상태에서 항목을 **하나씩만 꺼서** ⑤를 다시 쟀습니다(`Bench_TrailAblation_P`).

| 하나만 끔 | 60초 안에 들킴 | 들키기까지 평균 |
|---|---|---|
| (모두 켬) | 12/12 | 23.9초 |
| P-1 끔 | 12/12 | 23.9초 |
| P-2 끔 | 12/12 | 23.9초 |
| P-3 끔 | 12/12 | 17.8초 |
| **P-4 끔** | 12/12 | **14.2초** (개선 전과 같음) |
| P-5 끔 | 12/12 | 23.9초 |
| P-6 끔 | **8/12** | 24.4초 |

- **P-4(좌우 45° 훑기)가 원인입니다.** 개선 전에는 한쪽으로 90° 돈 채로 다음 지점 쪽으로 다시 돌아섰습니다. 이때 몸이 등 뒤를 스치며 지나가서 뒤따라오는 플레이어가 보였습니다. P-4는 "왼쪽 → 오른쪽 → **가운데**"로 끝나서 늘 진행 방향을 보고 끝나므로 등 뒤를 스치지 않습니다.
- **P-6(뒤돌아보기)는 제 역할을 합니다.** 끄면 4번을 아예 놓칩니다. 다만 20% 확률로는 P-4의 손실을 메우지 못합니다.

### 고칠 방법과 측정값

| 방법 | ⑤ 들키기까지 | ④ 지점 / 방 (최소) | ④ 멈춘 시간 | 바뀌는 것 |
|---|---|---|---|---|
| 지금 (개선안대로) | 23.9초 | 73% / 61% (52%) | 30% | - |
| **가) 훑기를 가운데로 돌아오지 않고 한쪽에서 끝냄** | **15.6초** | 73% / 62% (55%) | **24%** | P-4: "왼쪽 45° → 오른쪽 45°"로 끝남 (0.5초 짧아짐) |
| 나) 뒤돌아보기 확률 20% → 50% | 20.3초 | 69% / 62% (52%) | 34% | P-6 수치만 |
| 다) P-4 끄기 | 14.2초 | (측정 안 함) | - | 문에서 방 안쪽 보기도 사라짐 |

**가)를 추천합니다.** 모든 측정이 개선안대로보다 낫거나 같고, 뒤따라가기도 개선 전과 거의 같아집니다. 개선안의 P-4 설명에서 "→ 가운데"만 빠집니다. 정하시면 반영하겠습니다.

## 6. 그 밖에 알아 둘 점

1. **P-8(걸으며 두리번)은 넣지 않았습니다.** 개선안에서 "선택"으로 표시된 항목이고 체크리스트에서 고르지 않았습니다.
2. **걸을 수 없는 칸에 잠깐 서는 문제는 개선 전부터 있었습니다.** 순찰 2분(7,200번 확인) 동안 개선 전 2번, 개선 후 4번입니다. 경로 끝이 벽 여유(25cm) 안쪽 칸에 걸리는 맵 가장자리 문제로 보이며, 이번 작업과는 별개입니다.
3. **봇 측정의 한계.** 봇은 사람보다 단순합니다. 예를 들어 ②의 봇은 숨은 뒤 움직이지 않습니다. 숫자는 개선 전과 후의 **방향과 크기를 비교하는 용도**로 보세요.
4. **클라이언트 연출.** A-2에서는 경비원이 보는 방향과 움직이는 방향이 다릅니다(뒷걸음·옆걸음). 서버는 위치와 방향만 보내므로 Unreal 쪽에 해당 애니메이션이 필요합니다.
5. **성능.** 탐색을 시작할 때 경로 찾기를 최대 8번, 시야 검사를 최대 36번 더 합니다. 탐색 시작 때만 하므로 매 틱 비용은 거의 그대로입니다.
