## 1. 맵 배치 [필수]

### 확인한 것
- **형상은 이미 같음**: 클라가 쓰는 `Mansion_1F_Blockout.fbx` = 서버의 FBX. 서버는 `tools/fbx_to_map.py`로 이 FBX에서 벽 93개·바닥판 5개를 뽑아 씁니다.
- **좌표·원점도 같음**: 서버 맵의 벽 좌표가 FBX의 충돌 박스와 1cm 안에서 일치합니다(블록아웃을 언리얼 원점에 회전·크기 변경 없이 놓은 기준). FBX는 X축을 뒤집어 저장하므로(`CoordAxisSign = −1`) 언리얼 좌표 = (−x, y, z) — 언리얼 임포트 결과와 같습니다. 클라 문서의 "원점 위치 변환 검증 필요"는 **배치 좌표를 언리얼 월드 좌표 그대로** 주면 해결됩니다.
- **배치는 FBX에 없음**: 스폰·금고 후보·숨는 곳·창고·탈출구는 클라 레벨(`L_Mansion_1F`)에 있습니다. 서버는 지금 클라 팀이 예전에 준 배치(`mansion_1f_server.json`)를 쓰고 있어서 **탈출구가 정문(현관)**입니다.
- **"서쪽 옆문" 위치가 FBX 벽과 맞지 않음**: FBX의 바깥 벽에서 뚫린 곳은 ① 정문(현관, 화면 오른쪽) ② 화면 위쪽 끝의 틈(x ≈ 9778, y −4630~−4360, 옛 배치에서 `blocker_113`으로 막음) 두 곳뿐이고, **화면 왼쪽(서쪽 방 W1~W6 쪽) 바깥 벽에는 틈이 없습니다.** 클라가 레벨에서 벽을 뚫었는지, ②를 서쪽 옆문으로 부르는지 확인이 필요합니다.
- 문 없는 방 3곳: 클라 번호 11·13·20 = 서버 로그의 L2·U2·U4 (경고 4개의 원인). 클라는 이 방을 **반납 지점 후보에서 제외**합니다.

### 서버가 받아야 할 배치 데이터
클라 문서 14장 4번("서버용 맵 파일을 클라 배치에서 자동으로 만드는 도구")이 이것입니다. 아래 항목을 **언리얼 월드 좌표(cm)** 로, 지금 `mansion_1f_server.json`과 같은 이름으로 주면 서버 쪽은 `fbx_to_map.py --layout <받은 파일>` 한 번으로 끝납니다.

| 항목 | 내용 |
|---|---|
| `spawns.thief` (3), `spawns.guard` (3) | 위치·yaw |
| `vault_slots` (10) | 금고 위치·yaw·**상호작용 위치** |
| `hiding_spots` | 옷장 위치·yaw·상호작용 위치 (+옷장 크기 → 서버가 충돌체로) |
| `exit` | 탈출구 위치·yaw·**탈출 구역 사각형** (상호작용 위치는 이제 필요 없음) |
| `jail` | 창고 문 위치·상호작용 위치, 감금 자리, 창고 구역 |

## 2. 반납 지점 [필수]

### 클라 기준
- 방 안 랜덤 바닥에 **1m × 1m 초록 사각형**, **50초에 빨강, 60초에 사라짐**
- **방마다 최대 1개, 항상 5곳**. 반납하면 시간과 상관없이 **즉시 사라짐** → 즉시 새 지점 (**사라진 방·이미 있는 방 제외**)
- **짧게 눌러 들고 있는 보물 전부 반납** (우클릭/G)
- 조명과 관계없이 항상 보임 (클라 표시 규칙)

### 서버 지금
`EntityKind::Vent` 3곳 고정 ([GameWorld.cpp](../Content/Game/GameWorld.cpp) `Setup`), `BeginInteract` case Vent → `Deliver`.

### 바꿀 곳
| 파일 | 내용 |
|---|---|
| `Types.h` / `protocol.h` | `EntityKind::Vent` → **`ReturnPoint`** (값 유지, 이름만). 엔티티의 `typeId` = **방 번호** |
| `GameData.h` | `ReturnPointCount = 5`, `ReturnPointHalfCm = 50`, `ReturnPointWarnMs = 50000`, `ReturnPointLifeMs = 60000` |
| `MapData` | `rooms`(사각형, 번호, 반납 가능 여부) |
| `GameWorld.cpp` `Setup` | 반납 가능한 방 중 서로 다른 5곳 → 각 방에서 **경로 격자의 걸을 수 있는 칸** 중 무작위 위치 |
| `GameWorld.cpp` `Update` | 생긴 지 50초 → 상태 비트 `Warning`(빨강) / 60초 → 사라짐 + `RespawnReturnPoint` |
| `GameWorld.cpp` `BeginInteract` case ReturnPoint | 상호작용 범위 = 사각형 안(중심에서 ±50cm, 판정 여유 +50cm). 보물이 있으면 `Deliver` → 그 지점 사라짐 + 재등장. 빈손이면 `InvalidState` |
| 새 함수 `RespawnReturnPoint(빠진 방)` | 후보 = 반납 가능 방 − 빠진 방 − 지점 있는 방 → 무작위 |
| 이벤트 | 등장 `SC_ENTITY_SPAWN`(위치, typeId = 방 번호) / 빨강 = 스냅샷 상태 비트 `Warning` / 사라짐 `SC_ENTITY_DESPAWN` — **새 패킷 없이** 클라 요청(등장·빨강·사라짐, 위치·방 번호)을 충족 |
| 시험 | 항상 5곳 유지, 같은 방 중복 없음, 50초 Warning·60초 교체, 반납 시 즉시 교체, 제외 방에 안 생김 |

## 4. 보물 가치·무게와 소지 한도 [필수]

### 클라 기준
- 보물은 **금고에서만**, 금고마다 **1개**, 금고마다 가치가 다름. **10종**, 어떤 5개가 나와도 합계 **11,000$ 이상** [임시]
- 1인 **10개 / 20kg**, **주워서 20kg를 넘게 되면 줍기 불가**
- 의자·그림·책·꽃병은 **나중에** (클라 14장 6번) → 이번에는 보물만

### 서버 지금
`Entity::treasure`(uint8) = 종류 없는 개수, `MaxCarryTreasure = 3`.

### 바꿀 곳
| 파일 | 내용 |

스테미나 **0pt** → 탈진: **회복 50%**(10 → 5pt/s), **특수 동작(달리기·구르기·공격) 불가**, **최대치까지 회복되면 해제**. HUD에 표시.

## 9. 프로토콜 변경 모음 (v2.0 → v2.1)

클라 문서 "새로 필요하거나 바뀌어야 할 패킷"과 서버 계획의 대응:

| 클라 요청 | 서버 방법 | 새 패킷? |
|---|---|---|
| 반납 지점 등장 / 빨강 / 사라짐 (위치, 방 번호) | `SC_ENTITY_SPAWN`(`kind = ReturnPoint`, `type_id` = 방 번호) / 상태 비트 `Warning` / `SC_ENTITY_DESPAWN` | 아니오 (비트 1개 추가) |
| 반납 결과와 팀 반납 가치 합계 | `SC_TREASURE`에 `delivered_value` 추가 | 필드 추가 |
| 탈출구 열림 + 전체 메시지 | **`SC_EXIT_OPENED`** | **예** |
| 보물 정보에 가치·무게 | `ThiefTreasure`에 `weight_g`·`value`, 보물 종류는 엔티티 `type_id` | 필드 추가 |
| 탈진 시작·해제 | 상태 비트 `Exhausted` (스냅샷) | 아니오 (비트 1개) |
| 구르기 방향 | `CS_ACTION(Dodge)`의 기존 `yaw` 필드 | 아니오 |
| 무게·소지 한도 초과 줍기 거절 | `SC_ACTION_REJECT`의 `TreasureFull`(개수) / 새 `TooHeavy`(무게) | enum 값 추가 |
| (가능하면) 대기실 복귀 | `CS_RETURN`에 `target` | 필드 추가 |

이름만 바뀌는 enum: `EntityKind::Vent` → `ReturnPoint`(값 유지). `PROTOCOL_VERSION` 2.0 → **2.1**. 클라는 v1에서 바로 **v2.1**로 옮기면 됩니다(클라 14장 1번과 한 번에).
